## DataEditorWindow.cs 增强

5. **重构**：将各 Tab 的过滤 lambda 抽取为 `FilterXxxItems` 方法，供 `DrawXxxLeftPanel` 与 `MoveSelection` 共用。

### 设计要点
- 键盘导航仅在 `!EditorGUIUtility.editingTextField` 时生效，避免影响搜索框/属性输入框的字符与光标行为。

## DataEditorWindow 架构重构（接口 + 泛型基类）

将 `Assets/Editor/DataEditorWindow.cs` 从 1498 行的 God Class 重构为 300 行的调度器，消除 8 个 Tab 间的重复代码。

### 新增文件结构（`Assets/Editor/DataTabs/`）
- `IDataTab.cs` - 统一契约接口 + `TabType` 枚举（提升为顶层 public）
- `DataTabModule.cs` - 泛型抽象基类 `DataTabModule<TItem> where TItem : struct`，封装：列表绘制模板、点击选中、高亮、右侧 inspector、移动选择、过滤调度、焦点重置
- `MissionTabModule.cs` / `CampTabModule.cs` / `AirdropTabModule.cs` / `MapTabModule.cs` / `UpdateTabModule.cs` / `WeaponModuleTabModule.cs` / `WeaponUpgradeTabModule.cs` / `AboStateTabModule.cs` - 8 个具体 Tab，各只含差异点（~60-120 行）

### 架构要点
- **主窗口职责**：仅持有 `_tabs` 字典 + `_currentTab` + `_cachedEditor`，通过 `Current` 属性委托所有操作。所有 8 分支 switch（OnGUI/DrawSearchField/RefreshCurrentTab/MoveSelection/GetSelectedAssetPath）塌缩为单行 `Current.xxx`。
- **主窗口暴露的 public API**（供模块调用）：`SetCachedEditor` / `DestroyCachedEditor` / `HasCachedEditor` / `DrawCachedInspector` / `DrawSelectionHighlight` / `ResetFocus`(static) / `ColoredLabel`(static) / `GetEnumLabel`(static) / `GetInspectorName<T>`(static) / `Repaint` / `position`。
- **基类模板方法**：`DrawItem` 统一处理"绘制内容→取 rowRect→点击→OnSelect→高亮"，子类只实现 `DrawListItemContent(item, isSelected)`。
- **子类差异点**（abstract）：`GetItemData` / `FilterItems` / `DrawListItemContent` / `RefreshData` / `GetEmptyMessage` / `GetSelectedTitle`；可选 override：`GetSelectedTitleStyle` / `DrawRightPanelExtra`。
- **死代码清理**：删除原 `HandleClick<T>` / `SelectItem<T>` / `RefreshFromFolder<...>` / `RefreshFromFolderWithSubDirs<...>` 4 个从未调用的残留方法。
- **性能优化**：原 `OrderBy(...).ToList()` 改为 `Items.Sort(...)`，减少 GC 分配。
- **Item structs**：~~每个 struct 定义在对应 TabModule 文件中~~ **已移除**，见下方"二次优化"。
- **新增 Tab 成本**：只需新建一个 `XxxTabModule.cs` + 在 `RegisterTabs()` 加一行，主窗口零改动。

## 二次优化：移除 Item 包装 struct（方案 A3）

发现 7 个简单 Tab 的 struct 只含单个 `data` 字段，纯属透传包装。Mission 的 `MissionItem` 有额外 `label`/`isMain` 字段。

### 改动
- 基类签名从 `DataTabModule<TItem> where TItem : struct` 改为 `DataTabModule<TData> where TData : ScriptableObject`
- 基类直接持有 `List<TData> Items` 和 `TData Selected`，移除 `GetItemData` 抽象方法（item 即 data 本身）
- `IsSelected` 改用引用相等（`==`），比 struct 值相等更便宜
- 基类新增 `Dictionary<TData, string> LabelCache`，供 Mission 缓存反射计算的 label；`Refresh()` 时自动清空
- 7 个简单 Tab 直接 `DataTabModule<XxxData_SO>`，struct 全部删除
- Mission 仍 `DataTabModule<MissionData_SO>`，label 用 `LabelCache` 查询，`isMain` 用 `is` 即时判断（`is` 判断很便宜）
- 接口 `IDataTab` 和主窗口零改动

### 收益
- 删除 7 个 struct 定义（约 30 行模板代码）
- 8 个子类的 `GetItemData` 方法全部删除
- 基类更直观：`List<CampData_SO>` 比 `List<CampItem>` 自然
- label 反射结果缓存，过滤/绘制时 O(1) 查询，避免重复反射

## 三次优化：RefreshData 模板方法化

发现 8 个子类的 RefreshData 结构完全一致（路径校验→搜索→加载→排序），只有 4 个差异点。

### 改动
- 基类 `RefreshData` 从 `abstract` 改为 `virtual` 模板方法，封装完整流程
- 基类新增 5 个扩展点：
  - `RootPath`（abstract）- 资产根路径
  - `TypeName`（abstract）- 如 "t:CampData_SO"
  - `IncludeSubDirs`（virtual，默认 false）- 是否搜索子目录
  - `OnItemLoaded(TData)`（virtual，默认空）- 加载后钩子（Mission 用来填 LabelCache）
  - `SortComparison`（abstract）- 排序比较器
- 基类新增 `GetSearchPaths()` 私有方法，根据 `IncludeSubDirs` 构造搜索路径数组
- 8 个子类的 `RefreshData` override 全部删除，改用扩展点声明
- Mission 的 `IncludeSubDirs=true`（原逻辑只遍历子目录，但 root 下无直接资产，等价于 root+子目录）
- WeaponModule/WeaponUpgrade 的 `IncludeSubDirs=true`
- 其余 5 个 `IncludeSubDirs=false`（用默认值，无需声明）

### 收益
- 8 个子类各删除约 20 行 RefreshData 模板代码
- 新增 Tab 时不再需要写加载流程，只填 5 个数据点
- 加载流程统一，便于后续维护（如添加加载耗时日志）

## 异常状态伤害逻辑重构

`AboStateData_SO` 新增字段：`fullDamage`(满槽固定伤害)、`fullPerDamage`(满槽百分比伤害，/100f)、`damageTriggeredResponse`(是否触发 TakeDamage 的 response)。原 `damage` 改为未满时造成的伤害。

### 改动
- `Health.cs` 新增 `_isAboTickDamage` 标志字段；`HandleDamage` 加 `isAboTick` 参数，为 true 时跳过 `AddAboGauge`（不更新 Current/LastGainTime）且 Hacker/Terror/Vertigo/Toxicity 也直接返回伤害值（Destruction 仍返回 0）；`TakeDamage` 透传该标志给 `HandleDamage`。
- `Health_AboState.cs` 的 `DealAboTickDamage(entry, stateData, isFull)`：满槽造成 `fullDamage + fullPerDamage/100f*MaxHealth`，未满造成 `damage`，伤害类型用 `stateData.typeEnum`（不再用 Real）；调用前置 `_isAboTickDamage=true`，调用后复位。`AboTick` 未满分支也调用 `DealAboTickDamage(...,false)` 造成伤害。

### 设计要点
- 字段标志法避免改 `TakeDamage` 的 6 参签名（已超 5 参规范）。TakeDamage 同步执行，标志安全。
- tick 伤害走完整 TakeDamage 流程（护盾、扣血、OnDamaged、HandleDeath），仅 response 由 `damageTriggeredResponse` 控制、积蓄槽不被更新。
