## Scripts 目录 asmdef 分层分析（仅分析，用户手动改）
- 现状：除 `00_Core`/`00_Attribute`/`01_GameContract`/`05_EffectComp`/`08_Map`/`DayNightSystem`/`04UI/Assembly`/`00Tools/Test`/第三方外，业务代码（01Manager、02Data、02Game、04UI-Wnd、Effect顶层、Rendering、Feature/Fog、00Tools根）全部无 asmdef，编译进 `Assembly-CSharp` 单体。
- 根因：业务层依赖成环（Data ↔ Game ↔ Manager ↔ UI；Data 引 `FpsGame.Mission`/`FpsGame.MapUtils`，Manager 引 Mission/Furn/MapUtils）。asmdef 只能表达 DAG，成环必须同装配。
- 关键卡死点：`02Data` 的 SO 文件引用 `FpsGame.Mission`（在 02Game 单体），导致 Data 无法独立成 asmdef。
- 建议路线（务实）：只拆干净叶子层（Map/EffectComp/DayNight/Rendering/Fog/Tools/Editor），业务层保持一个单体 asmdef（`02_Game` 或留在 Assembly-CSharp）；严格分层需先解环（抽接口/事件进 Contract、SO 改引枚举/ID），属架构重构。
- 另：仅 `00_Core` 设了 rootNamespace，其余 asmdef rootNamespace 为空，需补齐。
