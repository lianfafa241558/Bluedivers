## 玩家新增语音调用（SpeechTypeEnum：CollOOPartsFail/ReLoad/Install/Uninstall/FinalMaga）
- 触发方式统一用 `GlobalEventSub.PlayMeetSpeech(GameObject user, SpeechTypeEnum)`（PlayerSpeechManager 已订阅 OnPlayMeetSpeech，`user==gameObject` 才播，内部有 CanSpeech 节流）。非玩家 owner 触发会被自动忽略。
- `CollOOPartsFail`：**已存在**（`OOPart.cs` 采集背包满时 line 23），无需改动。
- `ReLoad`（换弹）：`WeaponReloadController.ReloadStart()` 加 `if (Owner != null) GlobalEventSub.PlayMeetSpeech(Owner, ReLoad)`。Owner 为 WeaponBaseController 的 GameObject，玩家武器时即玩家。
- `FinalMaga`（最后一组弹药）：`WeaponReloadController.ReloadEnd()` 换弹完成后 `if (Owner != null && !InfiniteAmmo && Ammo.CurrValue < Magazine.FinalValue)` 触发（后备弹不足以再填满一整组弹匣）。
- `Install`/`Uninstall`（装备/卸载物品）：`EquipController.InstallEquip()`（TryAdd 成功后）与 `UninstallEquip()`（Remove 成功后），`if (m_actor != null) GlobalEventSub.PlayMeetSpeech(m_actor.gameObject, X)`。EquipController 需 `using Unity.FPS.Game;`。
- 注：主/副武器的"装备切换"由 PlayerWeaponsManager 管理（非 IEquippable），Install/Uninstall 针对的是背包物品（WeaponBag）流程。
- **后续修正（ReLoad/FinalMaga 逻辑）**：
  - `ReLoad` 语音放回 `WeaponReloadController.ReloadStart()`。**手动换弹**与**弹匣打空的自动换弹**（`UseMagazine` 打空 → `TryManualReload` → `ReloadStart`）都会播；带 **`WeaponFlag.AutomaticReload`** 的武器走 `WeaponController.UpdateAmmo()` 随时间恢复弹药（不调 `ReloadStart`，speed>99 时直接 `ReloadEnd`），因此不播。已撤销上一轮的 `TryManualReload(bool isManual)` 参数方案，所有调用方恢复无参。
  - `FinalMaga` 触发条件为 **`Ammo.CurrValue == 0`（后备弹清零，无限子弹除外）**：`ReloadEnd()` 中 `if (Owner != null && !InfiniteAmmo && Ammo.CurrValue == 0)`。

## ArmamentWnd 团队强化改为展开面板布局
- 原实现：点击第5槽位 `GetChild(i,5,4)` → `CycleTeamEnhance()` 按 ID 排序循环切换单选。
- 改为战备式展开：点击 `GetChild(i,5,4)` → `ToggleBooster()` 展开 `GetChild(i,8)`（Booster 面板，`SetBool("Booster",true)`），填充强化按钮，选中后收起并广播。
- 新增方法：`ToggleBooster()`（展开/收起切换，展开时加 Cancel 监听 + `InitBoosterButtons()`）、`InitBoosterButtons()`（清空后填充 `buttonPrefab` 到网格容器 `GetChild(i,8,0,0,0,1)`=RedList，按钮 icon 取 `te.icon`，绑定 `SetButton`+`SetCilck`）、`SelectBooster(id)`（`SendPlayerSelectTeamEnhance` + 收起面板）。
- 新增字段 `boosterExpanded` 标记强化面板展开态；`Cancel()` 优先处理强化面板收起；`ShowWnd()` 每次开窗重置 `SetBool("Booster",false)`+`boosterExpanded`。
- 场景结构确认（ArmamentItem.prefab）：`GetChild(i,8)`=Booster(根)、`GetChild(i,8,0)`=AirdropView(ScrollRect)、`GetChild(i,8,0,0,0)`=Content(VerticalLayout，含预置 RedText/RedList)、`GetChild(i,8,0,0,0,1)`=RedList(GridLayout, CellSize 72x72)。
- 注意：`ArmamentItem.controller` 原只有 `Airdrop` 参数，用户已在 Unity 里自行补好 `Booster` 参数（controller 文件未含 Booster 参数，为 Unity 侧手动配置）。
- **资源字典名修正**：全队强化字典实际字段名是 `ResSvc.boostDic`（非 teamEnhanceDic），`ArmamentWnd` 中三处引用（ShowTip/InitBoosterButtons/ReceivePlayerSelectTeamEnhance）均已统一为 `ResSvc.boostDic`。
- **优化为界面打开时预创建**：`InitBoosterButtons()` 调用从 `ToggleBooster()`（点击展开时）移到 `ShowWnd()` 末尾，与战备 `InitPlayerAirdrop()` 一起在界面打开时创建好；`ToggleBooster()` 只做动画展开/收起（`SetBool("Booster")`），不再重新填充。`InitBoosterButtons` 保留先清空 RedList 再填充的逻辑，避免重复开窗叠加（战备 `UnInitPlayerAirdrop` 在 HideWnd 中被注释，存在重复填充隐患，强化未复制该问题）。
