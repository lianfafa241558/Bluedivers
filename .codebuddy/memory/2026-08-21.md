## WeaponTemporaryController 改为输入驱动以支持射击分类
- 问题：`WeaponTemporaryController.cs`（继承 `WeaponReloadController`，被 `WeaponMineLauncherController` 继承）原为**自驱动全自动**——override `LogicTick` 每帧 `TryShoot()`，绕过 `HandleShootInputs`，导致无 Manual/Automatic/Charge/Laser/Lock 分类（激光等全部靠 `WeaponController.HandleShootInputs` 输入状态机触发）。
- 方案A（用户选择）：父类由 `WeaponReloadController` 改为 **`WeaponController`**（abstract partial 但无强制抽象成员，可编译）；`LogicInit` 仅 `base.LogicInit()`（移除原 `StartCool==0` 时 `WantsToShoot=true`，该逻辑已由 `WeaponReloadController.LogicInit` 的 `ShootInterval -= StartCool` 覆盖）；`LogicTick` 在 `base.LogicTick()` 后改为 **`HandleShootInputs(true, true, false)`** 每帧模拟按住扳机，由 Inspector 的 `ShootType` 决定行为（全自动/激光/蓄力/锁定）。保留 `IVfxEffect.SetOwner` 实现。
- 依赖链：`WeaponBaseController→WeaponReloadController→WeaponController→WeaponTemporaryController→WeaponMineLauncherController`。编译通过无 lint 错误。`WeaponMineLauncherController` 无需改动。

## 无敌状态统一：ActorFlag.Invincible 为唯一真相源
- 背景：复活后 4 秒无敌只设了 `Actor.AddTag(ActorFlag.Invincible)`，但伤害结算拦截走 `Health.Invincible` 属性，两套状态不同步 → 已锁敌的敌人/已发射的投射物/范围伤害仍能打中"无敌"玩家。
- 决策：**删除 `Health.Invincible` 属性，统一使用 Actor 的 `ActorFlag.Invincible`**。理由：无敌是单位级状态，Actor 是唯一身份（Health 可多部位多实例）；`ActorFlag.Invincible` 已被 AI 索敌（`FpsHelper.VaildTarget`）/仇恨（`EnemyController._OnDamaged`）/BOSS 装甲（`PartController`）消费，是主流语义通路；`Health.Invincible` 全项目仅 1 处写入。
- 改动：①`Health.cs` 删除 `public bool Invincible { get; set; }`，新增 `protected Actor m_Actor`（Awake 中 `GetComponentInParent<Actor>()` 缓存，不依赖 MainPart），`TakeDamage` 拦截改为 `if (m_IsDead || (m_Actor != null && m_Actor.HasFlag(ActorFlag.Invincible))) return;` ②`PlayerController.Start` Bridge 场景 `Health.Invincible = true` → `Actor.AddTag(ActorFlag.Invincible)`。
- 复活 OnRevive 的 AddTag/RemoveTag（4 秒）无需改动，现在自动覆盖伤害拦截。编译通过，`Health.Invincible` 无残留引用。
