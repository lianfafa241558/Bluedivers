# 2026-08-22

## HpItemBoss 优化：同步 invincibleArmor + 单位无敌 FillR 变白
- 背景：`HpItemBoss.Set` 只在初始化时把 `PartController.invincibleArmor` `.ToArray()` 快照一次，BOSS 运行时通过 `AddInvincibleArmor`/`OnInvinciblePartDestroy` 增删装甲（如 UnitSkill_OrbitArmor），UI 感知不到；且单位自身 `ActorFlag.Invincible`（复活/Bridge/无敌装甲期间）无视觉反馈。
- 改动1 `PartController.cs`：新增 `public event UnityAction OnInvincibleArmorListChanged;`，在 `AddInvincibleArmor` 末尾与 `OnInvinciblePartDestroy` 末尾（if 外）各 `OnInvincibleArmorListChanged?.Invoke();`。清空降级也会触发，UI 据此重建（含降级显示 deathArmor）。
- 改动2 `HpItemBoss.cs`：提取 `RebuildArmor()`（先 -= 旧 `OnDamage` 防泄漏，再按当前 `invincibleArmor` 重建栏位并显示/隐藏多余子物体，订阅 `OnInvincibleArmorListChanged`）；`Tick` 中检测 `actor.HasFlag(ActorFlag.Invincible)` 翻转：进入无敌 `SetColor(FillR, Color.white)`，退出恢复 `_originalRColor`（Set 时 `GetColor(FillR)` 缓存），用 `_isInvincibleShown` 标志避免每帧重复 SetColor；`End` 中取消 `OnInvincibleArmorListChanged` 订阅并遍历 `damageables` 取消 `OnDamage`。
- 编译零 lint 错误。复用既有 `SetColor/GetColor/SetFill`（`using static WndTools.WndRootTool`）。

## Damageable 爆炸免疫字段化 + 批量迁移工具
- 背景：爆炸免疫原先靠 `armors[DamageTypeEnum.Explosion] <= 0`（即 showArmorLists 爆炸值-AllArmor>=1）判定，判定条件依赖护甲运算，不够直观。
- 改动1 `02Game/Game/Shared/Damageable.cs`：新增 `[SerializeField][InspectorName("爆炸免疫")] private bool isExplosionImmunity;`。`IsExplosionImmunity()` 改为直接返回该字段；`ExplosionBlocking()` 中"爆炸免疫直接跳过"分支改为 `if (isExplosionImmunity) return false;`（不再读 armors[Explosion]）。注意：爆炸抗性条目仍保留在 showArmorLists 用于伤害倍率运算，不再参与免疫判定。
- 改动2 新增 `Assets/Editor/ExplosionImmunitySetter.cs`（菜单 `Tools/爆炸免疫迁移（扫描全项目 Prefab）`）：`AssetDatabase.FindAssets("t:Prefab")` 全项目扫 prefab，用 `PrefabUtility.LoadPrefabContents` 打开，遍历 `GetComponentsInChildren<Damageable>(true)`，用 `SerializedObject` 读私有 `showArmorLists`，若某条目 `Key`(enumValueIndex==(int)Explosion) 的 `Value >= 0.95f`，则 `DeleteArrayElementAtIndex` 移除该条目并设 `isExplosionImmunity=true`，最后 `SaveAsPrefabAsset` 保存。遍历从后往前删避免下标错乱。已加 `using Core;`（DamageTypeEnum 在 Core 命名空间）。编译零 lint 错误。
- 迁移工具只处理 Prefab 资产，不处理场景内已摆放的实例；如需场景迁移可后续扩展。
