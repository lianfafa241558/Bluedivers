## AI 状态机两套架构对比结论

`02Game/AI/StateMachine/` 下并存两套 AI 状态机方案：

- **架构 A：`StateMachineFrame<T>`（GuardDog/SimpleTurret 用）**：数据驱动委托表 `Dictionary<Enum, StateInfo>`（onEnter/onUpdate/onLateUpdate/onExit），子类重写 `InitState()` 注册，基类统一 Update/LateUpdate 查表调用。自带 CharacterController + 手写 MoveToTarget，直接操作 DetectionModule（紧耦合），与下层 AIController/属性系统脱节。应用范围窄。
- **架构 B：`AIInputBaseController`→`AIInputUnitController`→具体类（EnemyMobile/EnemyTurret/SpecUnitKei 用）**：模板方法 + switch 分支，基类提供 `UpdateAiStateTransitions()`/`UpdateCurrentAiState()` 两个抽象钩子，经 `I_AIController` 接口反向订阅解耦，复用 EnemyController 的 NavMeshAgent + GameAttribute.Speed 属性 modifier + DetectionModule，异常状态（眩晕/中毒/恐惧）天然接入。7 个状态，扩展性强。缺点是逻辑堆在两大方法里接近 God Method，无显式 onEnter/onExit（散落在 SwitchState 的 if/else）。

**结论**：B 是项目主流（EnemyMobile/EnemyTurret/SpecUnitKei），深度耦合核心体系；A 仅适合作 GuardDog 这类不依赖 NavMesh/属性加成/逻辑简单的独立单位的轻量特例。理想融合点：把 B 的 SwitchState 散落 if/else 改成 A 的委托表 onEnter/onExit，大 switch 拆成每状态一个方法。

## 伤害抗性系统重构（DRG式 → 绝地潜兵2式穿甲结算）

已按用户确认的方案完成"伤害抗性从肢体迁移到 Health 整体 + 穿甲等级 AP 结算"重构，全部 7 个 todo 完成，lint 0 错误。

**新模型**：
- 肢体 `Damageable`：保留护甲值破坏机制（armorValue/remainArmor/BreakArmor/RestoreArmor/BleedValue）+ 弱点 + 爆炸遮挡；新增 `armorLevel(int)` 与 `explosionResistance(float)`，移除按类型减伤（GetArmor/armors/AllArmor 结算逻辑）
- 结算公式（`Damageable.InflictDamage`）：`armorFactor = AP >= armorLevel ? 1 : max(0.1f, 1-(armorLevel-AP)*0.33f)`，爆炸成分额外乘 `(1-explosionResistance)`
- Health：新增 `showArmorLists`（无 AllArmor）+ `GetResistance(type)`，`TakeDamage` 每成分乘整体减伤
- 攻击方：`DamageData`/`SustainedDamageData` 新增 `DirectAP`/`ExplosionAP`(int) + 蓄力缩放 `DirectAPChargeScale`/`ExplosionAPChargeScale`，`IDamageData` 扩展 `GetDirectAP`/`GetExplosionAP`
- 接口 `I_Damagable`：移除 `GetArmor`/`IsExplosionImmunity`，新增 `int ArmorLevel`/`float ExplosionResistance`，`InflictDamage` 加 `int AP` 参数
- `FpsHelper`：直击传 `GetDirectAP`，爆炸传 `GetExplosionAP`，移除 `.Where(!IsExplosionImmunity)` 过滤

**改动文件**：Interface_Game.cs、Damageable.cs、Health.cs、TransferDamageable.cs、DamageData.cs、SustainedDamageData.cs、FpsHelper.cs、DamageDataDrawer.cs、新增 ArmorLevelMigrationTool.cs。

**迁移工具**（`Assets/Editor/ArmorLevelMigrationTool.cs`，菜单 `Tools/护甲等级迁移`）仿 ExplosionImmunitySetter 范式：
- 读旧 showArmorLists 的 Gun/Explosion 值，每 0.2 抗性=1 级向下取整，取较大写入 armorLevel
- bool isExplosionImmunity → float explosionResistance（true→1.0）
- 复制主肢体(MainPart) 非 Gun/Explosion 抗性到 Health.showArmorLists
- **关键**：`Damageable` 上旧字段 `showArmorLists/AllArmor/isExplosionImmunity` 以 `[HideInInspector][SerializeField]` 保留，供迁移工具读取 prefab 旧数据（若删字段则 SerializedObject.FindProperty 找不到）。迁移工具跑完后可删除这些残留字段。

**待用户操作**：在 Unity 编辑器运行 `Tools/护甲等级迁移` 迁移全项目 prefab；验证后删除 Damageable 的旧残留字段。
