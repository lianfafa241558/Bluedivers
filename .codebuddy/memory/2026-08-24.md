## TransferDamageable 增加独立护甲等级（伤害系统重构后续）

在 8-23 伤害抗性系统重构基础上，按用户要求让附属肢体 `TransferDamageable` 拥有**独立的护甲等级**（不再跟随主肢体）。

改动：
- `TransferDamageable.cs`：新增 `armorLevel(int)` 与 `explosionResistance(float)` 独立字段；`ArmorLevel => armorLevel`、`ExplosionResistance => explosionResistance`（原转发 source）
- `Damageable.cs` `InflictDamage`：结算改用 `source.ArmorLevel` / `source.ExplosionResistance`（被击肢体自身值），而非 `this.armorLevel`（主肢体值）

结算链路验证：
- 直击主肢体：`source`=主肢体 → 用主肢体护甲等级
- 直击附属肢体：命中附属 Collider，`comp`=`TransferDamageable`，转发给主肢体 `Source.InflictDamage(source=附属肢体)` → 主肢体结算用 `source.ArmorLevel`=附属肢体值（独立生效）
- 爆炸路径 `item.Damageables` 只含 `Damageable`（`Actor` 用 `GetComponentsInChildren<Damageable>()`），不含 TransferDamageable，故爆炸不命中附属肢体，不受影响
- 护甲破坏（Destruction→ArmorDestruction）仍作用于主肢体 `remainArmor`（结算在主肢体执行），护甲值破坏机制保留在主肢体合理

lint 0 错误。附属肢体命中 Destruction 时护甲破坏扣主肢体护甲值，属既定行为。

## ArmorLevelMigrationTool 自动读取 Explosion 值到爆炸抗性

按用户要求，迁移工具现在会从抗性列表的 Explosion 项自动读取 `explosionResistance`（float）：
- `MigrateDamageable`：遍历旧 `showArmorLists` 时捕获 Explosion 的 Value，clamp01 写入 `explosionResistance`；若旧 `isExplosionImmunity`(bool) 为 true 则优先级最高强制 =1
- `MigrateTransferDamageable`：遍历旧 `extraLists.arr` 时捕获 Explosion 的 Value，clamp01 写入 `explosionResistance`（无 bool 免疫标记，纯读取）

- armorLevel 换算仍取 Gun/Explosion 较大者

lint 0 错误。

## 肢体编辑器窗口 LimbEditorWindow（含修复与增强）

新增 `Assets/Editor/LimbEditorWindow.cs`（菜单 `Tools/肢体编辑器`，命名空间 `Unity.FPS.Game`——注意不能放 `.Editor` 段，否则 `Editor`/`EditorStyles` 被解析为命名空间导致 `CreateEditor`/`selectionColor` 编译错误），三栏布局：
- 左上：预制体内全部 `Damageable`，左下：全部 `TransferDamageable`，各带独立滚动条，点击切换选中；选中项按钮**蓝色背景白字**（`_cardSelectedStyle` 设 normal.background 纯色贴图）
- 中间：**模型预览用 PreviewRenderUtility 手动渲染**（不能用 `Editor.CreateEditor(stage实例).OnPreviewGUI()`，stage 实例的 Editor 无预览 GUI；须对**预制体资产** `AssetDatabase.LoadAssetAtPath<GameObject>(stage.prefabAssetPath)` 建 Editor，或用 PreviewRenderUtility）。当前实现：`BeginPreview`→ 遍历 Renderer 用 `DrawMesh`（Skinned 用带 bones 的重载）→ `EndPreview`→`GUI.DrawTexture`；左键拖拽旋转、中键缩放（`_previewYaw/Pitch/Dist`）
- **选中肢体 Collider 线框**：`GetSelectedLimb()` 取选中组件，`GetComponentsInChildren<Collider>(true)`，把 Box/Sphere/Capsule/Mesh 的边线转换成**世界坐标线段**收集到 List，构建 `MeshTopology.Lines` 的 Mesh（顶点色蓝色）+ `Hidden/Internal-Colored` 材质，用 `_preview.DrawMesh` 排队渲染
- 右侧：选中组件字段，用缓存 `Editor.OnInspectorGUI()`；选中 Damageable 时下方依次序列化显示其关联 TransferDamageable

关键技术点：
- 自动读取当前预制体：`PrefabStageUtility.GetCurrentPrefabStage().prefabContentsRoot`，用 root 引用 + stage.GetHashCode() 做指纹检测切换并 `RefreshAll()`
- `LineArmor` 是私有 `[SerializeField]` 字段，须通过 `_selectedEditor.serializedObject.FindProperty("LineArmor")` 枚举 `objectReferenceValue` 读取关联 TransferDamageable，不能直接访问
- **重要坑（多次返工，最终确认真实 API）**：Unity 2022.3 的 `PreviewRenderUtility.DrawMesh` 实际重载（反编译确认）：
  - `DrawMesh(Mesh mesh, Matrix4x4 matrix, Material mat, int subMeshIndex)` ← 4 参数，最常用
  - `DrawMesh(Mesh, Matrix4x4, Material, int, MaterialPropertyBlock, Transform probeAnchor, bool useLightProbe)`
  - `DrawMesh(Mesh, Vector3 pos, Vector3 scale, Quaternion rot, Material, int subMeshIndex, MaterialPropertyBlock, Transform, bool)`
  - **没有** `(Mesh, Matrix4x4, Material[], int)`、**没有**带 `Transform[] bones/rootBone` 的重载、**没有** 10 参数版（那是 `Graphics.DrawMesh`）。只接受**单个 Material**，支持 `Matrix4x4` 含 scale。
  - 所以：① 模型网格把顶点**烘焙到世界坐标**（Skinned 用 `smr.BakeMesh` 再乘 `localToWorldMatrix`，Mesh 用复制顶点乘矩阵）后，用 `DrawMesh(mesh, Matrix4x4.identity, mat, subMeshIndex)` 渲染；蒙皮无需 bones 参数（BakeMesh 已处理），多材质逐 subMesh 循环调用；② Collider 线框不能建 Lines 拓扑 Mesh（DrawMesh 只支持三角形），须把每条线段**扩展成细长 Box**（`AddThickSegment`，0.02 宽，6 面 12 三角）
- **渲染时机坑（导致"一片灰"）**：`PreviewRenderUtility.DrawMesh` 内部是 `Graphics.DrawMesh(..., camera, ...)`，只把 mesh **注册到相机**，`EndPreview()` **不调用** `camera.Render()`（反编译确认）。必须自己**显式调 `_preview.Render(true, false)` 或 `camera.Render()`** 才会真正绘制到 RT。且传 `true` 开启 `Unsupported.useScriptableRenderPipeline`，否则 URP 材质在非 SRP 路径下不显示（一片灰）。顺序：`BeginPreview` → 各 `DrawMesh` 注册 → `_preview.Render(true,false)` → `EndPreview` → `GUI.DrawTexture`。`updatefov=false` 因 fov 已手动设
- **临时对象销毁坑**：所有临时 Mesh/Material 必须在 `EndPreview()` 之后才能 `DestroyImmediate`，否则渲染时对象已销毁报错。用 `List<Mesh> _tempMeshes` + `List<Material> _tempMaterials` 收集，EndPreview 后 `DestroyTempPreviewAssets()` 统一销毁
- 所有缓存的 `Editor` 对象在 `OnDisable`/刷新时 `DestroyImmediate` 释放；`PreviewRenderUtility` 用 `_preview.Cleanup()` 释放
- `PrefabStage.prefabAssetPath` 已过时 → 用 `stage.assetPath`
- **选中按钮蓝色**：用自定义 GUIStyle 切换背景不可靠，改用 `GUI.backgroundColor`（选中项设蓝 `(0.16,0.45,0.85)`）染亮**默认按钮**，绘制后恢复 `Color.white`。已清理不再用的 `_cardStyle`/`_cardSelectedStyle`/`MakeSolidTexture`
- **Collider 高亮范围**：`CollectTargetColliders()`：选中 Damageable → **主肢体自身 Collider**（`GetComponentsInChildren`）+ `new SerializedObject(dmg).FindProperty("LineArmor")` 枚举引用的 TransferDamageable 取其 Collider（两者都要显示）；选中 TransferDamageable → 取它自身及子物体 Collider。已移除无引用的 `GetSelectedLimb`
- **NRE 加固**：`DestroyImmediate(editor)` 在 editor 的 serializedObject 已被 Unity 释放时会触发其 OnDisable 访问已释放 SerializedProperty 抛 NRE（曾发生在对 prefabAsset 建的 GameObjectInspector 上）。当前代码只对组件建 Editor，不再对 GameObject 建（预览用 PreviewRenderUtility）。销毁统一走 `SafeDestroyEditor`（try/catch 包裹）。若用户仍看到旧 `DestroyRootPreviewEditor`/`GameObjectInspector.OnDisable` NRE 栈，是旧编译残留，重新编译即可消失
- lint 0 错误

## 拆毁值机制（DamageData 拆毁 > Health 拆毁则秒杀）

按用户要求给 Health 和 DamageData 加拆毁值字段，实现"伤害拆毁值 > 血量拆毁值 → 直接秒杀"。

改动：
- `Health.cs`：新增 `[SerializeField] private int demolishValue = -1`（默认 -1 视为无法被拆毁）；`TakeDamage` 增加 `int demolishValue=-1` 参数，开头判定：`demolishValue > 0 && this.demolishValue != -1 && demolishValue > this.demolishValue` 则 `CurrentHealth=0` + `HandleDeath`（直接击杀，无视护盾，但受 Invincible 无敌标记保护）
- `DamageData.cs`/`SustainedDamageData.cs`：新增 `demolishValue` 字段（默认 0）+ `GetDemolishValue()`；`IDamageData` 接口扩展
- `Damageable.InflictDamage`/`TransferDamageable.InflictDamage`：加 `int demolishValue=-1` 参数传给 `Health.TakeDamage`
- `FpsHelper.Hit`：直击/爆炸调用 `InflictDamage` 时传 `damageData.GetDemolishValue()`
- `DamageDataDrawer`：直接伤害区 + SustainedDamageData 爆炸区绘制 `demolishValue`

关键逻辑：`this.demolishValue == -1` 时单位"无法被拆毁"（必须显式排除，否则默认 -1 会被任意拆毁值触发秒杀）。其他 TakeDamage 调用点（Tick 流血/AboTick/落地）用默认参数 -1。
lint 0 错误。拆毁值不随蓄力缩放（GetDemolishValue 直返字段值）。
【修复】首版漏改 `I_Damagable.InflictDamage` 接口声明（未加 demolishValue 参数），导致 Damageable/TransferDamageable 实现不匹配报 CS0535/CS1501。已补 `Interface_Game.cs` 接口声明加 `int demolishValue=-1`，与实现一致，lint 0 错误。

## InflictDamage 参数封装为 DamagePacket 结构体

按用户要求（参数太长），将 `I_Damagable.InflictDamage` 的长参数列表（10 个参数）封装为 `DamagePacket` 结构体（纯逻辑 DTO），接口签名简化为 `void InflictDamage(DamagePacket packet)`。

`DamagePacket`（`Assets/Scripts/00GameContract/Interface_Game.cs`，命名空间 `GameContract`，struct）公开字段：
- `Source`(I_Damagable 被击肢体)、`Damage`(PEInt 基础伤害)、`DamageGroups`(List<SKVP<DamageTypeEnum,float>>)、`WeaknessBonus`(PEInt)、`AP`(int 穿甲)、`NoSource`(bool)、`DamageSource`(GameObject)、`Pos`(Vector3)、`DemolishValue`(int 拆毁)

改动：
- `Interface_Game.cs`：新增 `DamagePacket` struct，`I_Damagable.InflictDamage` 改 `void InflictDamage(DamagePacket packet)`
- `Damageable.cs`：方法体内解包 `packet.Damage`/`packet.DamageGroups`/`packet.Source` 等；`damage` 和 `damageSource` 因体内被修改用局部变量
- `TransferDamageable.cs`：`Source.InflictDamage(packet)` 直接转发
- `FpsHelper.cs`：直击/爆炸分支构造 `DamagePacket`（对象初始化器）后 `comp/item.InflictDamage(packet)`

注意：`DamagePacket` 含 Unity 类型（GameObject/Vector3）与 `I_Damagable`，尚未完全解耦为纯逻辑 DTO（与 memory 中 DamagePacket 规划的方向一致但未彻底解耦）。命名空间 `GameContract`。lint 0 错误。
