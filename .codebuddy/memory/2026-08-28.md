- **修复 HaloController 固定不动 bug（2026-08-28）**：原代码用 `Distance(target, parent.position) < 6` 判定瞬移，但该距离含 lastPos 滞后量，speed 调小后稳态滞后激增（如 speed=1 时 L≈4.9m）顶过 6，每帧触发 else 硬贴 → 视觉完全固定。改为按**父物体帧间位移突变**判定瞬移（新增 `snapDistance` + `_prevParentPos`），正常滞后不再误触发。参数建议：想明显拖尾 speed=1~3。该脚本挂在 `Prefabs/StudentModle/*` 与 `NpcModle/*`、`BattleBase/Kei.prefab` 的模型根物体子节点（dv=(0,0,0)）。
- **HaloController 仍"固定不动+轻微抖动"的根因（2026-08-28）**：瞬移判定非根因（else 分支未变）。"基本不动+抖动"= transform 每帧被其他系统覆盖（典型：Animator 竞争写）。角色 prefab 的 Animator 为 `m_UpdateMode: 2`（AnimatePhysics），动画在物理阶段更新，穿插在 LateUpdate 之后、渲染之前，会把我们写入的位置覆盖回动画值。修复：写入挪到 `Camera.onPreCull`（渲染前最后时机，多相机用 `Time.frameCount` 防重），并加 `debug` 日志验证：若 `parentMove≈0` 说明 parent 引用未指向真正移动的物体（应指向挂 CharacterController 的物体）；若仍被覆盖则建议 Animator.UpdateMode 改 Normal（0）。
- **HaloController 最终根因判断（2026-08-28，用户确认动画只驱动光环节点子物体）**：排除 Animator 覆盖后，"基本不动"只剩一种代码可能——`parent`（transform.parent=模型根）本身位移≈0，它只是被外层带动（CharacterController 挂在更外层），lastPos 追的是不动点 → 光环钉死；动画微动引起抖动。修复：Start 里 `parent` 优先取 `GetComponentInParent<CharacterController>()` 的 transform（真正位移物体），替换时用 `parent.InverseTransformPoint(transform.position)` 重算 dv 保持不跳变。保留 `onPreCull` 兜底与 `debug` 日志。
- **HaloController 移除 onPreCull（2026-08-28）**：URP 下 `Camera.onPreCull` 不触发（SRP 不支持内置管线相机事件），且 `OnPreCull` 方法名与 Unity 消息机制冲突（需无参签名）→ 报 `Script error: OnPreCull`。用户确认 Animator 只驱动光环节点子物体、不碰节点本身，兜底本就多余。已删掉 OnEnable/OnDisable/OnPreCull/_lastFrame，恢复纯 LateUpdate 写入。若需渲染前兜底应改用 `RenderPipelineManager.beginCameraRendering`。
- **HaloController 最终修复：运行时脱离层级（2026-08-28）**：日志确认 parentMove=0.048（parent 在动）、halo-parent 偏移 0.4m 与 speed=10 理论滞后吻合（逻辑在工作），但调参仍"固定相对位置"→ 根因是**光环节点作为角色层级子物体，父物体移动时渲染系统强制自动带动，与手动滞后互相抵消**。修复：Start 里 `dv = parent.InverseTransformPoint(transform.position)` 记录偏移后 `transform.SetParent(null, true)` 脱离角色层级，位置完全由脚本控制。UpdateHalo 检测 `parent==null || !parent.gameObject.activeInHierarchy` 时自隐藏。注意：对象池复用角色重新激活时，脱离的光环不会自动激活，需在角色激活处补激活。参数：speed=10 约 0.5m 轻微拖尾，speed=1 约 3~4m 强烈拖尾。
- **HaloController 最终定稿：私有 _current 状态插值（2026-08-28）**：用户要求回滚 SetParent(null)，保持节点在父级层级下。**真正根因**：`transform.position = Lerp(transform.position, target, ...)` 中读 `transform.position` 会被父级自动带动污染（父级每帧移动 d，子物体被层级强制带走 d，读值超前 d），插值起点错误导致滞后被逐帧抵消 → "固定相对位置"，且 returnSpeed 失效。修复：维护私有 `_current` 做插值（`_current = Lerp(_current, target, b)`），最后 `transform.position = _current` 写回；`speed`/`returnSpeed` 双参数均生效。关键教训：**子物体跟随类脚本不要用 `transform.position` 作为插值起点，父级带动会污染它，应维护私有位置状态**。
