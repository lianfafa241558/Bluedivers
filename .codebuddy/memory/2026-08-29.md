## 单位半高度(HalfHeight) + 地雷竖直判定

需求：地雷(DeployableMine)原来只做平面距离判定，能对空中单位生效；需要加竖直维度。

实现：
- `00Core/Interfaces/CoreInterfaces.cs` 的 `I_Entity` 新增 `float HalfHeight { get; }`。
  语义：单位竖直占位区间 = `[CenterPos.y - HalfHeight, CenterPos.y + HalfHeight]`；**0 = 未配置，调用方退化不做高度过滤**（保证存量行为不变）。

- `DeployableMine.cs` 新增 `VerticalRange`(0=复用 TriggerRange) 与 `InVerticalRange(I_Actor)`：算地雷 Y 到单位竖直区间的距离 <= 竖直触发范围才触发；`HalfHeight<=0` 直接放行。空间网格仍只做水平过滤。
- 新增编辑器工具 `Assets/Editor/ActorHalfHeightTool.cs`（菜单 `Tools/单位半高度批量设置`）：扫描 Assets 下所有含 Actor 的预制体，把半高度写为 `actor.transform.InverseTransformPoint(AimPoint.position).y`；支持「覆盖已配置值」「跳过嵌套预制体内 Actor」，写入用 `PrefabUtility.LoadPrefabContents` + SerializedObject + `SaveAsPrefabAsset`（try/finally Unload）。

## DamageData 是否模块化（结论：暂不动序列化结构）

用户问能否把 `DamageData.cs` 的 52-68（运动组）和 112-132（碰撞/特效组）抽成 struct。**结论：不做**，理由：

- **序列化静默丢数据**：平铺字段挪进嵌套 `[Serializable] struct`，Unity 不迁移（`[FormerlySerializedAs]` 只管同级改名，管不了"平铺→嵌套"）。**107 个预制体**序列化了 DamageData（Weapons/ 全部、Enemy/Zerg、Enemy/Robot、BattleBase 载具机甲、Projectiles/、Airdrop/），Speed/Gravity/MaxLifeTime/MaxRange/MinRange 会全部归零且不报错。要做必须配一次性 SerializedObject 迁移脚本 + 全量备份。
- **Inspector 分组已存在**：`Assets/Editor/Drawer/DamageDataDrawer.cs` 已有 运动/直接伤害/爆炸伤害/碰撞 四分区，还带蓄力联动双列（`DrawPropertyOrPaired`）、`UseHole` 条件展开 `Hole`、`DamageExplosion>0` 才展开半径组。套 struct 只会变成两层折叠，更差。
- **运动组无去重收益**：只有 DamageData 有运动参数，SustainedDamageData 没有；抽出来只是加 `.Motion.` 前缀，却要改 ~26 个文件访问点。
- **碰撞/特效组有去重价值**（与 SustainedDamageData 重复 7 字段 + 在 IDamageData 契约上），但要配迁移脚本，属独立任务。

## 空投机器人落地目标点被 StopNav 清掉（已修）

现象：日志顺序「发送目标点(203.38,11.26,165.86)」→「取消了目标点」，空投机器人落地后不会移动到指定落点。

根因时序竞争：`RobotWave.DropGroupUnits` 把单位从鹰上放下时 `Behaviour.enabled=true`（含 `EnemyMobile` 状态机），**同帧**就调用 `EnemyController.SetNavDestination` 发送目标；但 `EnemyMobile.Start()` 落地才首次运行，因无巡逻点进 `AIState.Idle` → `EnterIdle()` → `StopNav()` 把刚设的目标点清空。普通出生单位没这问题是因为 `EnemyController.Start()` 里有 `Invoke(BirthEnd, BirthDuration+0.1)` 会延迟补发目标；而空投单位出生在鹰上，该 Invoke 早已触发且 `m_lastDestination` 当时是 default，落地后不会补发。且空投单位 `BirthComplete` 恒 true，`SetNavDestination` 会直接入队 `RequestPath`。

修复：`EnemyController.cs` 新增 `SetNavDestinationDelayed(Vector3)` + 协程 `DelaySetNavDestination`（两个 `yield return null`，确保 `EnemyMobile.Start()→EnterIdle→StopNav` 先执行完再设置目标），补 `using System.Collections;`；`RobotWave.DropGroupUnits` 改调 `SetNavDestinationDelayed`。

**后续升级（本轮）**：用户要求"长期有效目标点、到达后不移除、中断回 Idle 不丢失"。改用更本质方案并移除临时的 Delayed 协程：
- `EnemyController` 新增 `public Vector3 HomePoint { get; set; }`（长期落点，default=未设置，区分 `PatrolPos` 的"到达即自毁"哨兵语义）。
- `EnemyMobile.EnterIdle()`：`HomePoint != default` 时 `SetNavDestination(HomePoint)`（回 Idle 继续走向落点），否则 `StopNav()`。
- `RobotWave.DropGroupUnits`：空投时 `ec.HomePoint = 落点` + `ec.SetNavDestination(ec.HomePoint)`。
- 移除 `SetNavDestinationDelayed`/`DelaySetNavDestination` 及 `using System.Collections;`（不再需要）。
- 时序已验证：`birthTime` 在 `AIController.Start()` 才赋值，空投落地时 `BirthComplete=false` 只记录 `m_lastDestination`，`BirthEnd()` 在 `BirthDuration+0.1` 后补发；`BirthEnd` 只清临时 `m_lastDestination` 不清长期 `HomePoint`，因此落点目标最终必然送达且长期有效。

实现（`PatrolContriller.cs`）：
- `Start()` 订阅 `BattleEventSub.OnEvacuate += OnEvacuateStart`，`OnDestroy()` 退订
- 新增 `OnEvacuateStart(PEVector3 evacuatePos)`：遍历 `ActorsManager.Enemys`，过滤出有 `PatrolPos != default` 的 `EnemyController`（即巡逻队单位），方向 = `evacuate - 当前Pos`，用 `Tool.GetCircleIntersection(mapCenter, mapRadius+30, from.ToVector2(), dir).ToVector3()` 计算地图边界交点赋给 `PatrolPos`；已在撤离点（方向近似0）跳过
- 注意：`PEVector3` 转 `Vector3` 用 `.RawVector3`（不是 `.ToVector3()`，那是 `Vector2` 的扩展方法）
