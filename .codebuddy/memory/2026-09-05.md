## ToonLit 阴影锯齿排查最终结论（2026-09-05 晚，多次实测）
- **现象**：ToonLit 模型（穹顶类多三角面）在地面投影出现"线条状无阴影"，自身表面也出锯齿状阴影；加粗描边无效、改 ShadowResolution(4096) 只缓解不变细根因。
- **排除项**：①描边与阴影无关（Outline pass 由 OutlineRendererFeature 在 AfterRenderingOpaques 用 DrawRenderers(LightMode="Outline") 绘制，不进 shadow camera；ToonLit 各变体 ShadowCaster/DepthOnly pass 均未 define ToonShaderIsOutline，顶点不外拓）；②caster 端手动 `positionWS += normalWS` 会把阴影轮廓撑大，不可取（已删干净，Shared.hlsl 恢复 ApplyShadowBias 原样）。
- **根因（ToonLit 自身）**：ToonLit.shader ForwardLit **注释掉了 `#pragma multi_compile_fragment _ _SHADOWS_SOFT`（line 235）**→ ToonLit 永不编译 PCF 软阴影变体，`shadowAttenuation` 为单点采样、mesh 表面像素级 0/1 硬跳；叠加 `_CelShadeSoftness=0.05`（smoothstep 过渡带仅 0.1，几乎 step）+ `lerp(1, shadowAttenuation, _ReceiveShadowMappingAmount)`（默认 0.65）→ 硬跳阴影与硬卡通过渡相乘 = 像素级锯齿条纹。ShadowResolution 提升只是让 texel 变小（缓解），根因未消。
- **可选修法**：A. ToonLit 取消注释 `_SHADOWS_SOFT`（启用 PCF，但阴影会变柔，违背硬卡通意图）；B. `_CelShadeSoftness` 0.05→0.2~0.3（过渡带摊平 hard shadow 跳变，保留硬朗感）；C. 缩小 ShadowDistance(100→50) 提高近处 cascade 精度。用户暂未选定；地面 TerrainLit 侧已先改（见下）。
- **地面 Terrain 接收端**：Test.shader 走 `_EnableToon`，TerrainLitPasses.hlsl `ShadeSingleLight` 原 `step(0.5, shadowAttenuation)` 硬切会放大锯齿；用户选"先只改地形 shader"，已改为 `smoothstep(0.40,0.60,shadowAttenuation)` + `lerp(0.5,1,...)`。注意：URP 软阴影关闭时 shadowAttenuation 无中间值，此改效果有限，需开 PCF 或 shader 内 PCF。
- **激活 URP Asset**：`Assets/Setting/New Universal Render Pipeline Asset.asset`（GraphicsSettings m_CustomRenderPipeline guid=fb51c7dc）。m_SoftShadowsSupported=0（软阴影关）、MainLightShadowmapResolution=2048、ShadowDistance=100、Cascade=3、DepthBias=1、NormalBias=1。
- **摄像机穿入模型内部看到"随描边宽度变化的缝"（2026-09-05 末）**：外扩反向壳描边固有特性，非 bug。本体 Cull Back 在内部全剔（模型消失），描边壳 Cull Front 在内部反而全保留成为"内壁"，壳在硬边/折角外扩时面被拉开成缝（缝宽 ∝ _OutlineWidth）。用户确认正常不会进入内部（仅调试偶发穿模），结论**不需要修**；如调试碍眼可临时 _OutlineWidth=0 或优化碰撞。
- EmittController/MpbController 微优化（审阅后用户确认直接落地）：① 离屏短路——MpbController 新增 `IsAnyVisible()`（任一 Renderer.isVisible 即 true）；EmittController.LateUpdate 改 `if (mpb.IsAnyVisible()) Refresh();`，并新增 `OnBecameVisible` 补一次 Refresh 消除"离屏→可见当帧用旧值画 1 帧"的 pop（isVisible 反映的是上一帧剔除结果，LateUpdate 早于 Cull，故需该回调）。② PropertyID 缓存——BaseModify 加 `[NonSerialized] int fieldId + bool idResolved` 惰性解析（勿用 0 当哨兵，SerializeReference 反序列化不保证字段初始值），ScaleModify/OffsetModify 改用 int；MpbController 新增 int 重载 `Set(int,float)/SetOffsetX/Y(int,float)` + `GetVectorOrDefault(int)`，字符串版全部保留，不影响 ShowVehicle/BattleApplyVehicleData/SpecUnitKei 等其他调用方。
- RendererSet.cs（02Game/AI/FxCont）套用第 5 条（PropertyID 缓存）：加 `[System.NonSerialized] int colorId + bool colorIdResolved` 与 `GetColorId()`（空 colorName 时兜底：Switch→`_EmissionColor`、Trigger→`_HitColor`），Update 内两处 `mpb.SetColor(...)` 改为 `mpb.SetColor(GetColorId(), ...)`。结论：**第 3 条（isVisible 短路）不套用**——RendererSet 是事件+时间窗瞬态驱动（空闲只有 IsValid+时间比较，不迭代 renderers），非 EmittController 那种常驻逐帧动画；且其非 MonoBehaviour 无 OnBecameVisible，"离屏跳过闪窗"会留下可见当帧补色缺口。
