## 积雪后处理接入 Unity 全局雾（SnowOverlay.shader）

- 问题：远处积雪只是"盖一层雪色"，没有随距离过渡到雾色，与周围已雾化的不透明表面脱节。
- 根因：`Assets/Shader/Feature/SnowOverlay.shader` 从未参与 URP 雾计算（无 `multi_compile_fog`、无 `MixFog`）。
- 修复（按项目既有约定，同 `Texture2.shader`/`SimpleFogAdditive.shader`）：
  - `#pragma multi_compile_fog`
  - `Varyings` 加 `float fogFactor : TEXCOORD2;`
  - vert 内 `OUT.fogFactor = ComputeFogFactor(OUT.positionHCS.z);`
  - frag 内光照后 `snowCol = MixFog(snowCol, IN.fogFactor);`
- 数学上正确：雪层是 Alpha 叠加在下层不透明表面上，对雪色做 MixFog 等价于
  `lerp(mask*snowC+(1-mask)*surfC, fogC, f)`，即"先合成再整体雾化"，远处雪自然融进雾色消失。
- 相关信息：场景 `TestScene.unity`（FogMode=3 Exp2, end 由密度控制）/`PV.unity`（FogMode=2 Exp）均 `m_Fog: 1`；
  `Setting/New Universal Render Pipeline Asset_Renderer.asset` 中 SnowRendererFeature `renderPassEvent: 300`(AfterRenderingOpaques)，
  Meryuhi `FullScreenFogRendererFeature` `_injectionPoint: 550`(BeforeRenderingPostProcessing) —— 550 是**合法**枚举值（此前记忆记为非法，特此更正），故体积雾本身也会作用于积雪层。

## 天空盒换成 Skybox/Procedural 后的体积云适配

- 背景：原天空盒是昼夜全景（`_DayTex`/`_NightTex`/`_Lerp`/`_TintColor`/`_Exposure`），换成内置 `Skybox/Procedural` 后这些属性全部不存在，`DrawVolumetricCloud` 的 `autoSampleSkyColor` 分支整体失效（`GetTexture("_DayTex")` 返回 null），云永远停在该分支不写入的默认 `_CloudLerp=0`（夜色）。
- 改 `Assets/Scripts/Rendering/DrawVolumetricCloud.cs`：
  - 昼夜插值改由**太阳**方向的 Y 分量 + `AnimationCurve _dayNightBySunHeight`（默认 -0.1→0、0.02→0.35、0.35→1）推算；注意必须用 `_sunLight` 而不是当前主光源（月亮升起时若用主光源会把夜晚算成白天）。
  - 天空盒匹配：`_SkyTint`（无则退回 `_TintColor`）经 `NormalizeColor`（按最大通道归一化保色相）+ `Lerp(white, tint, _skyTintInfluence=0.6)` 后写入 `_CloudTintColor`；`_Exposure` 读 `_Exposure`。
  - **修掉旧 Bug**：`_CloudExposure = GetFloat("_CloudExposure") * CloudBrightnessMultiplier` 是逐帧累积相乘（指数衰减），改为每帧整体重算 `exposure * brightness`。
  - 主光源选择改为"取强度更高的一盏"（`PickMainLight`），与程序化天空盒太阳盘跟随主光源的规则一致；新增 `GetSunTint`（主光源色归一化后染受光面）。
- 改 `Assets/Shader/Environment/VolumetricCloud.shader`：新增动态属性 `_CloudSunColor`，frag 里明暗改为 `lerp(shadowCol, litCol, shade)`，受光面乘 `_CloudSunColor`；删除已无来源的 `_CloudDayTex`/`_CloudNightTex`。
- 附带修复：`EnvironmentLightingModule.Tick` 用户新加的 `SetColor("SkyTint", ...)` 属性名少了 `_`（静默失败），已改为 `_SkyTint` 并加 `HasProperty` 守卫。
- 遗留待定：程序化天空盒没有 `_Lerp`，`skyboxDayNightLerp`/`SkyLerpMultiplier` 对天空不再生效（云的昼夜仅由本脚本曲线承担）；恶劣天气要压暗天空需改驱动 `_Exposure`。

## 决策：天空盒昼夜/天气压暗统一走 _Exposure（2026-09-11 追加）

- 用户拍板「lerp 就按 _Exposure 走」：`EnvironmentLightingModule.Tick` 里 `skyboxDayNightLerp × SkyLerpMultiplier` 不再只写 `_Lerp`，改为按天空盒能力分派：
  - 有 `_Lerp`（昼夜全景天空盒）→ 照旧写 `_Lerp`；
  - 无 `_Lerp` 有 `_Exposure`（`Skybox/Procedural`）→ `_Exposure = 基础曝光 × Lerp(nightSkyExposureScale=0.15, 1, 插值)`。
- 基础曝光（材质上手调值）**缓存一次**，用 `_exposureSkybox`（材质引用）+ `_skyExposureApplied`（上帧写入值）双条件判断：材质被换或外部手改过才重读，杜绝逐帧相乘的指数衰减（同类坑已在 DrawVolumetricCloud 修过一次）。
- `_SkyTint`/`_GroundColor` 写入改走缓存的 `Shader.PropertyToID`（`SkyLerpId/SkyExposureId/SkyTintId/SkyGroundColorId`），且色调乘上天气 `ambient`。
- 连带调整 `DrawVolumetricCloud`：不再对 `_CloudLerp` 叠 `SkyLerpMultiplier`（天空压暗已通过 `_Exposure` 流入 `_CloudExposure`），避免昼夜/暴雨时云被压两层。

## 体积云改成"远景云雾"质感（第二次改造）

- 现场实测（重要）：`TestScene.unity` 的 `PlaneColud` 是**一块水平平板**——position(400.6, 550, 474)、scale(1000,100,1000)、mesh=内置 Plane(10×10) → **10km×10km**，
  `horizontalStackSize: 2`、`cloudHeight: 5`（平板厚 5m 的 20 层堆叠其实只有 ±2.5m，`hFade` 在 ±2.5m 处正好为 0）。
  **陷阱：层数=2 时两层都在 hFade 零点 → 完全不渲染**；层数需 ≥ 8（间距=cloudHeight/(N-1)）。
  材质 `Colud1.mat`（TestScene 用的就是它）：`_CloudScale=0.02`、`_CoverageBase=0.5`、`_Density=1`、`_EdgeSoftness=0.5`、`_WindSpeed=0.25`、`_ShadowStrength=0.3`、`_DayCloudColor` 白。
  组件上 `_sunLight/_moonLight` 场景里未序列化 → 伪光照方向恒为 (0,1,0)。
- 质感差的四个根因：①噪声频率过高（0.02 → 50m 基频，5 个八度叠到 ~3m，550m 外即"颗粒/爆米花"）；②覆盖率顶满没云隙；③没有远景雾融合，云像一块浮在空中的板；④明暗分离弱 + 颜色被 `_CloudLerp/_CloudTintColor` 拖到中间灰蓝。
- Shader 改造（`Assets/Shader/Environment/VolumetricCloud.shader`）：
  - `_CloudScale` Range 下限 0.02 → **0.002**（能做出数百米大云团）；新增 `_ShadowTint/_LitBoost/_ClusterStrength/_CloudWarp/_DetailAmount/_DetailFrequency/_DetailFadeDistance/_GrazingBoost`（都进 CBUFFER）。
  - `Fbm(float2 p, float detailFade)`：第 3~5 个倍频按 `detailFade` 加权并**按实际权重归一化**（保证阈值语义不漂移）→ 距离自适应细节，消除远处颗粒。
  - 域扭曲（两层低频 ValueNoise 偏移采样坐标）+ 云团聚强度参数化 + 受光/背光分离（受光乘 `_CloudSunColor`、背光乘 `_ShadowTint`）+ 掠射加厚（`1-|viewDir.y|` 平方 → `_GrazingBoost`）。
  - **风改为世界空间米/秒**：`p = (posWS.xz + _WindSpeed*t*float2(1,0.6)) * _CloudScale`。**旧材质 `_WindSpeed=0.25` 会变得几乎不动，必须重设成 8~10。**
  - 远景雾融合：`_CloudHazeColor/_CloudHazeStart/_CloudHazeEnd/_CloudHazeStrength`（脚本写入），`col = lerp(col, hazeColor, haze)` → 远处云溶进地平线雾色。
- 雾色来源：`WeatherAtmosphereController` 新增静态 `FogColor`，由 `EnvironmentLightingModule`（全屏雾 `color.value` / 梯度模式 `RenderSettings.fogColor`）写入，`DrawVolumetricCloud` 读取后推给材质（组件上可选"用地面雾色/自定义色"）。

## 云"到不了地平线"（第三次改造，2026-09-11）

- 现象：天上只有一块云板，下方与地平线之间露出天空，边界是硬边。
- 根因：平板只有 ±5km（scale 1000 × 内置 Plane 10），边缘仰角 = atan(高度/半宽)；550m 高 → 6.3°，玩家不在平板中心时更高。水平平板**永远**到不了地平线，除非边缘仰角压到 1~2°（半宽 ≈ 20~30km）。
- 关键排查结论：
  - `Assets/Resources/Prefabs/BattleBase/Player.prefab` 主相机 **far clip = 300**，云（550m 高、>300m 远）还能显示是因为 shader 里 `ZClip Off` 关掉了深度裁剪（推断 D3D11 DepthClipEnable=false）。**不要移除 ZClip Off**，否则云整片消失。
  - 旧脚本的"视锥锥形裁剪"按**层中心**判断是否可见 —— 对铺满视野的大平板是错的（中心在侧后方时该层依旧铺满屏幕），跟随相机后会把云整片裁掉。已删除该逻辑，空像素剔除交给 Shader 的提前 discard。
  - `Hash21` 用 `frac(sin(dot(p,float2(127.1,311.7)))*43758)`：平板拉到 20km 后噪声坐标到 ~126，sin 参数达 1e8 量级，fp32 精度崩坏 → 远处出现重复条纹。已换成 Hoskins 风格 frac 哈希。
- 脚本新增（`DrawVolumetricCloud`）：`_followCamera`（云层中心跟随相机 XZ，边缘永远固定仰角）、`_horizonElevationDegrees`（=1.5°，所需半宽 = 高度/tan(角度)，自动放大**绘制**尺寸而不改 Transform）、`_autoExtendPlate`、远景雾起止改为按平板半宽取比例（`_hazeStartRatio=0.35`/`_hazeEndRatio=0.95`，保证雾在平板边缘前吃掉云）；层落在厚度边界（hFade=0）时直接跳过 + `OnValidate` 警告层数 <3。
- Shader 追加：frag 里先算大形状，`shape*(1-_DetailAmount)+_DetailAmount < threshold` 时提前 `discard`（省掉细节/光照采样的 ALU）。

## 用户要求"完全重构云层系统"（当天第四次，已落地）

- 用户给的平板方案（无论怎么打补丁）**架构上不可能**达到目标效果，根因两条：
  1. 所有层都用**世界 XZ** 采样 → 每层看到的是同一张 2D 云图，叠 N 层只是把同一张图变深，**没有体积/视差**；
  2. 水平平板的边缘仰角 = atan(高度/半宽)，永远 > 0 → **数学上到不了地平线**，除非半宽 20~30km。
- 已重写 **`DrawVolumetricCloud.cs`（全新架构）+ `VolumetricCloud.shader`（全新）**，类名/文件名/shader 名保持不变（场景与材质 guid 引用不断）。新架构见 MEMORY.md「体积云系统」条目。
- 关键实现点（复盘用）：
  - 天穹 mesh 运行时生成（`CreateDomeMesh`，半球 y≥0，默认 48×24 段），`HideFlags.DontSave`，段数变化才重建，`OnDestroy`/`OnValidate` 释放；
  - **深度压到远平面**（`#if UNITY_REVERSED_Z → o.pos.z = w*1e-5; #else → w*(1-1e-5)`）：云在天空之上、仍被近处不透明物遮挡，且**不再需要 ZClip Off**（旧方案依赖它才能画出 550m/300m far 外的云，是隐患）；
  - 投影距离 `rayLength = (层高度 - 相机Y) / max(dir.y, _MinRayY)`，用 `rayLength` 驱动 detailFade（>2.5km 无细节）与雾融合（3~12km）→ 地平线附近自动成雾带；
  - 不透明度 `alpha = cloud * (1 - exp(-密度 * clamp(1/dir.y, 1, 8)))`；
  - 每层**独立 MaterialPropertyBlock**（同一帧复用同一 MPB 会串数据），属性全部声明在 CBUFFER 之外（否则 MPB 覆盖不生效）。
- 目标是《绝地潜兵2》风格雪原云海；材质侧建议值：`_ShadowStrength 0.55`、`_EdgeSoftness 0.3`、`_HorizonCloudTint` 暖粉、`_ZenithCloudTint` 冷白。

## 重构后第一轮反馈修复：云盖住山 + 云很脏很小

- 现象①「云盖住远山、给人很近的感觉」→ 根因：云的**距离**是投影距离（几百米~几十公里），而天穹几何只有 200m，**硬件深度测试表达不了云的真实远近**（旧的 z 压远平面方案在 DrawMesh 的绘制时机/深度缓冲状态下不可靠）。
  → 改为 **`ZTest Always` + shader 内手动比场景深度**：`SampleSceneDepth(GetNormalizedScreenSpaceUV(pos))` → `LinearEyeDepth` 与 `rayLength` 比较，山比云近就 `discard`（天空像素 rawDepth=far 特判跳过；用 `_OcclusionBias=3m` 容差防抖）。入口开关 `_OcclusionEnabled`（默认 1，设 0 可退回无遮挡）。
  → 注意：这依赖 `_CameraDepthTexture`（项目里 FullScreenFog/SnowRendererFeature 都要 Depth，正常存在）；若云整片消失说明深度纹理没生成，把 `_OcclusionEnabled` 设 0 验证。
- 现象②「很脏很小」→ 高频噪声占比过高：把层「细节占比」0.30→0.12、`_DetailFadeDistance` 2500→900、`_ClusterStrength` 0.45→0.30（云连片）、`_CloudWarp` 0.35→0.50（有机边缘）、`_EdgeSoftness`→0.45、层「云团尺度」0.010→0.006（云团 ~170m）、主层云量 0.42→0.50、高层云量降到 0.22（两层图案穿插也会显得脏）。
- 相机 far clip 备忘：`Assets/Resources/Prefabs/BattleBase/Player.prefab` 主相机 **far = 300 / near = 0.01**（脚本里无运行时修改）；demo 地图本身也小（PlaneColud 在 (400,474)），所以远景雾/山都在 300m 内。若以后要更完整的远景，需把这个 far 提到 2000+（并考虑 near 提到 0.05~0.1 保深度精度）。

## 地平线条纹 → 改为"圆罩（有界）采样映射"（用户提议，2026-09-11）

- 现象：云在近地平线出现一圈横向细碎条纹/虚线。
- 根因：**采样映射是无限大的云层平面**（`rayLen = h/dir.y`，dir.y→0 时距离→∞）。掠射角下每个像素横跨数公里世界范围，径向被极度压缩 → 任何噪声倍频都被拉成横线。此前靠 footprint LOD + 强行"推向实心"打补丁，属治标。
- 用户提议「改成一个巨大的圆罩子」→ 采纳（但**做在采样映射层，不是几何层**，理由见下）：
  - `float2 domePos = dir.xz / (dir.y + _DomeFlatten) * altitude;`，新增材质属性 `_DomeFlatten`（Range 0.02~1.5，默认 **0.35**）。
  - `k→0` = 原无限平面（退化、条纹）；`k` 越大越接近纯天穹（等角、零压缩）。k=0.35 时地平线方向的最大角放大被限制在 `k/(1+k)`≈2.9 倍（原来 ∞），云团在任何方向都保持足够角尺寸 → 条纹从结构上消失。
  - 近地平线的云团角尺寸因此大 3~5 倍，正好是"大块云带"而不是"碎线"。
  - 物理正确的部分全部保留：**远景雾、地形遮挡、Beer-Lambert 掠射加厚仍用真实视线距离 `rayLength = altitude/max(dir.y,_MinRayY)`**，只有噪声采样坐标改用 domePos。
- 为什么不做成"几何上的巨大球壳"：①几何在相机 far clip(300m) 之外会被裁掉（除非再压深度/ZClip Off）；②云的真实距离是几十公里，只能由 shader 算，几何半径只决定"像素从哪来"。所以天穹几何保持 200m 跟随相机即可，别改大。
- 顺带：噪声采样网格旋转 25°（`_NoiseRotation`）破坏与等距离线对齐的规则感；倍频 LOD 改为按 `domePos` 的屏幕足迹计算（现在有界，只作抗锯齿保险）。

## 地平线硬边 → 改为"按仰角的平滑淡出"（2026-09-11）

- 现象：云在地平线附近有一条锐利的边界线。
- 根因：远景雾用的是**被 `_MinRayY` 钳住的 `rayLength`** 做 `saturate((rayLength-start)/(end-start))`。`rayLength = altitude/max(dir.y,_MinRayY)` 在 `dir.y = _MinRayY` 处被钳住 → 雾量曲线出现**斜率拐点**；再加上雾化后颜色=雾色、而天空在那一侧颜色不同，就显出一条硬边。
- 改法（`VolumetricCloud.shader`）：
  - 雾改由**仰角**驱动：`yStart = altitude/_CloudHazeStart`、`yEnd = altitude/_CloudHazeEnd`（把组件上的"米"换算成正弦仰角），`horizonFade = 1 - smoothstep(yEnd, yStart, dir.y)` → smoothstep 两端导数为 0，没有任何拐点；同时不再受 rayLength 钳制影响。
  - 新增材质属性 `_HazeAlphaFade`（默认 0.9）：`alpha *= 1 - horizonFade * _HazeAlphaFade` → 云在地平线附近**既并入雾色又整体淡出**（"化掉"），不再留下实心色带。设 1 表示完全淡出。
- 组件上「远景雾起始/完成距离(米)」语义不变（会换算成仰角；550m 高时 3km≈10°、8km≈4°、12km≈2.5°），tooltip 已更新。

## FullScreenFog（Meryuhi）与天空 / 注入点（2026-09-11）

- 用户已删除自研的 `Assets/Scripts/Feature/Fog/`（FogFeature + FogVolme + DepthCamera）→ 对应 `Assets/Shader/Feature/FogEffect.shader` + `Setting/Feature/Fog.mat` 成为孤儿资产（我上一轮给 shader 加的 `_SkipSky` 保留备用）。
- **关键结论：`FullScreenFog` 各模式对天空的行为完全不同**
  - `Depth` / `Distance`：fog 因子只由深度决定，天空深度恒为远平面 → 因子恒定最大 → **整片天空被刷成雾色**（天空渐变/云/太阳全被抹平）。当年"UI 相机 Clear Depth → 贴花被吞"就是这个机制。
  - `Height` / `HeightAndDistance`（项目 `EnvironmentLightingModule.Initialize` 强制用的就是后者）：fog factor = 距离因子 × **高度因子**，高度由深度重建的世界坐标算；天空处重建点在视线方向上"在无穷远" → 仰角朝上 → 世界高度在雾层之上 → 高度因子 0 → **地平线以上的天空天然不吃雾**，只有贴地平线几像素的窄带吃到（正好遮住天地接缝）。所以正常使用下**不需要为天空做特殊处理**。
- **真正要改的是注入点**：原本 `_injectionPoint: 550`（BeforeRenderingPostProcessing）在透明物之后 → 云/雪花/粒子/贴花会被按"背后不透明物的深度"雾化（云在几十公里外却按背后地形 ~200m 吃满雾 → 云被洗掉）。已改为 **450（BeforeRenderingTransparents）**：天空盒(350)已画、透明物未画 → 地形与天空吃雾、透明物不吃 ✓；云的地平线雾交给它自己的 `horizonFade`，颜色与雾色同源（`WeatherAtmosphereController.FogColor`）。
- 顺手修 `Packages/Fog/Runtime/FullScreenFogRendererFeature.cs`：`Execute` 里加 `if (cameraData.renderType != CameraRenderType.Base) return;` → 相机堆叠时 Overlay 相机不再重复叠一次全屏雾（比"UI 相机别 Clear Depth"更彻底的根因修复）。

## 沙尘暴（天空响应雾）接线完成（2026-09-11）

- 需求：沙尘暴时天空要变浑。原状：天空"完全不响应雾"，根因 = `HeightAndDistance` 模式下 fog 因子 = 距离因子 × **高度因子**，天空像素深度恒为远平面、重建出的世界高度高于雾层 → 高度因子 = 0。
- 采用**连续方案（不动 FullScreenFog 的 mode）**，共 4 处：
  1. `WeatherAtmosphereController`：新增 `TargetSkyDust/SkyDust`（0~1）与 `TargetSkyDustColor/SkyDustColor`，在 `Smooth()` 里一起平滑。
  2. `WeatherEffect`：新增 `_calmSkyDust/_stormSkyDust/_skyDustColor`（沙尘色默认 (0.76,0.62,0.45)），`ApplyAtmosphere` 写入桥。
  3. `EnvironmentLightingModule`：天空盒 `_SkyTint`/`_GroundColor` 按 SkyDust 向沙尘色 `Color.Lerp`（**不乘 ambient**，沙尘是散射体要保持亮）；`_AtmosphereThickness` 按 `dustAtmosphereScale`(默认 2.5) 放大（基础值缓存 + 外部改动检测，同 `_Exposure` 那套）；`UpdateFullscreenFog` 里高度雾起止额外抬升 `dustFogHeightRise`(默认 600m) → 天空落入雾层。
     ⚠️ 抬升量与相机 far clip 耦合：必须 > farClip + 相机高度（现 far=300 → +600 够；far 提到 2000 就要跟着加到 ~2500）。
  4. `DrawVolumetricCloud`：远景雾色随 SkyDust 转向沙尘色，雾带起止从 `3000/12000` 收缩到 `_dustHazeStartDistance/_dustHazeEndDistance`(10/400) → 起止很近时 `horizonFade` 在整个天空都≈1 → 云整体化进沙尘（**无需改 Shader**）。
- 另一条思路（用户提出）：让天气切换 `FullScreenFog.mode`（平时 HeightAndDistance、风暴 Distance）→ 天空会被整片雾色覆盖。**结论：可行且对 far clip 不敏感，但模式是 shader keyword，切换那一帧必然突跳**，且风暴期会失去全部高度雾（startHeight/endHeight/fogHeightRise 失效）。建议保持 HeightAndDistance + 高度抬升；若要加这个枚举，切换要放在 `SkyDust` 已归零之后。
- 注：因为雾的注入点已改到 450（透明物之前），**天空会被雾盖住、但云不会** → 沙尘暴里"云也消失"必须靠上面第 4 条，两者互补。

### 雾层高度改由天气预制体配置（2026-09-11，用户指出架构问题）

## Warping.shader 不响应 FullScreenFog 的根因与方案（分析，2026-09-11）

- 现象：`Assets/Shader/Warping.shader`（Transparent+1 的抓屏热扰动面片，用于 `Resources/VFX/Enemy/Birth/Warping_*.prefab`、`InWarpingMat`、`MineWarping`）区域完全没有雾，与周围被雾化的画面割裂。
- 根因（两条叠加）：
  1. 雾 pass 注入点 = `450 BeforeRenderingTransparents`（不透明后、**透明前**），而 Warping 队列 `Transparent+1` = 3001，**在雾之后**绘制 → 雾早就写完了，它没吃到。
  2. Warping 采样的 `_CameraOpaqueTexture` 由 URP 的 CopyColorPass 在 `AfterRenderingOpaques(300)` 拷贝，**同样早于 450** → 抓到的背景本身也没雾；而 frag 里 `col.a = 1` 全额覆盖 → 把下面已雾化的画面彻底盖掉。
- 可选方案（未实施，等用户拍板）：
  - A 改注入点 450→500(AfterRenderingTransparents)：一行生效，但所有透明物（云/雪/粒子/贴花）一起吃雾，即之前被否掉的副作用。
  - B 让 Warping 在雾之前绘制：新增 RendererFeature 在 ~445 用自定义 `ShaderTagId` + `DrawRenderers` 手绘 Warping（把 shader 的 `LightMode` 从 `UniversalForward` 改掉），雾即覆盖它；无额外全屏开销，但 Warping 的可见性依赖该 RF。
  - C 让 Warping 采样"雾后颜色"：FullScreenFog pass 末尾把结果 blit 到全局纹理（`cmd.SetGlobalTexture`），Warping 改采样它（需 fallback 到 `_CameraOpaqueTexture`）；视觉最自然（扭曲的是带雾画面），代价是雾开启时多一次全屏 blit。

### Warping 远距离"扭得特别厉害"（2026-09-11 修复）

- 根因：`Warping.shader` 的位移是**屏幕空间固定偏移**（`screenUV += float2(distortX, distortY) * i.color.a`，量级由 `_HeatForce` 决定，与距离无关），而噪声采样坐标是**模型 UV**（`TRANSFORM_TEX`）。远处的面片在屏幕上只占几十像素，同样的偏移占比被放大几十倍 → 看起来剧烈扭动/错位；近处反而正常。
- 改法（`Warping.shader`）：新增属性 `_DistortFullDistance`（Range 0.1~200，默认 **15** 米）；vert 里 `o.distortScale = saturate(_DistortFullDistance / max(vertexInput.positionCS.w, 0.001))`（`positionCS.w` ≈ 相机空间深度），frag 里并入 `distortAmount = _HeatForce * strengthTex.r * i.distortScale`。语义：≤15m 满强度（近处观感不变），更远按距离反比线性衰减。
- 已存在的 4 个材质无需改动 —— 未序列化该属性时用 shader 默认值。
- 若远处仍嫌"噪声过密/抖得碎"：那是模型 UV 噪声随面片缩小的固有表现，需再把噪声 UV 按距离归一（等价于把噪声挪到屏幕空间），是下一步可选项。
