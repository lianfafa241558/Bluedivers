## 咨询：敌人单位死亡时"检视器配置事件（禁用/显示物体）"该怎么做
用户问题：`EnemyControllerFX_AboState.cs` 相关需求——想在单位死亡时用检视器配置某些事件（如禁用某些物体），是否必须用 UnityEvent？但用 UnityEvent 又像回滚到"内联直连"的旧写法（现在已经升级成 SO 了）。

### 诊断结论
- 触发逻辑**已存在**：`EnemyControllerFX.TriggerFX()` 里已经对 `FxSetConfig.go`（`List<ArmorBreakEffect>{go,state,scale}`）执行 `SetActive` + `scale`。所以**不需要新增 UnityEvent**。
- 真正卡点是**引用作用域**：`FxSetConfig.go` 里的 `GameObject go` 是**直接引用**，而它挂在共享 SO `EnemyFxEventData_SO.fxDic` 上。**SO 资产无法持有 prefab 内部子物体的引用**（prefab 子物体不是资产，Project 里展开不了、拖不进去；只有 prefab 根/独立资产可被外部引用）。实测 `Assets/Resources/GameData/EnemyFx/Events/**` 下所有 `EVT_*` 的 `go: []` 全为空 —— 正是这个限制。
- 因此这不是 "SO vs UnityEvent" 之争，而是「共享配置不能存实例层级引用」。

### 给出的方案（待用户选择）
- **A（推荐）实例层数据列表**：在 `EnemyControllerFX` 上加 `[SerializeField] List<FxLocalObjectSet>{occasion, List<ArmorBreakEffect>}`（prefab-local）。prefab 内引用子物体合法、可拖拽、survive prefab 变体/复制；运行时与 SO 合并（SO 管通用音效/粒子，实例管本单位层级）。注意 `TriggerFX` 当前 `if (value == null) return;` 要改成先执行实例层、SO 为空也照跑。
- **B SO + 间接引用**：`go` 换成 key/相对路径，运行时 `transform.Find` / 字典解析（SO 保持可共享，代价是字符串易写错，需编辑器校验）。
- **C UnityEvent**：仅在需要调用「任意组件的任意方法」（如 `VoidSpread.SwitchToShrink()`）时才用；只做 SetActive 这种纯数据需求不该用它。缺点：persistent call 存方法名字符串，改名/移脚本会**静默失效**；无法批量复用与校验；prefab 变体难追踪。

### 沉淀为长期原则（已写入 MEMORY.md「数据分层原则」）
SO 只放与实例无关的数据；与实例层级绑定的数据必须留在 prefab 组件上；共享又想引用层级时用间接引用。

### 补充：划分唯一依据（回答用户追问"是不是再加一个结构类似的字段"）
- 是"分层"而不是"同样内容存两份"：实例层**只放必须引用 prefab 层级的字段**（`OccasionTypeEnum` + `List<ArmorBreakEffect>`），`FxSetConfig` 的 SG/cilp/ps/trans **不需要**在实例层重复。
- 判定标准一句话：「这条配置改的时候，是否希望同类单位一起吃？」是→SO；否→实例。
- 合并策略建议**叠加**（SO 管生成/播放，实例管本单位物体开关，语义不同，无冲突判定），不做覆盖。
- 若某单位所有死亡表现都是实例级 → 该 occasion 的 SO 条目留空即可，不必硬塞。

## 修复：AirdropPod 对同一单位重复造成伤害
文件：`Assets/Scripts/02Game/Gameplay/Projectile/AirdropPod.cs`

- 现象：空投舱下落时每帧做 `SphereCastAll`（长度 `displacement+0.1f`，相邻帧扫掠段首尾重叠），且命中后只做"穿透继续下落"，同一碰撞体（大单位/慢速下落）会被连续多帧命中 → 多次直击伤害 + 多次爆炸结算 + 多次 `OnHit` 回调。
- 修复：新增 `HashSet<GameObject> m_HitUnits`（键为 `I_Damagable.ActorGo`，与 `ProjectileStandard.m_hasHits` 同套路）+ 复用 `m_IgnoredColliders`：
  - `Hit()` 内先调 `RegisterHit(collider)`：碰撞体加入 `m_IgnoredColliders`，其单位加入 `m_HitUnits`；
  - `IsHitValid()` 增加两条过滤：碰撞体在忽略列表、`I_Damagable.ActorGo` 已在 `m_HitUnits`（覆盖同一单位多个肢体碰撞体）；
  - `Launch()` 里 `m_HitUnits.Clear()`（对象复用时清残留）；`ResolveHit` 的单向盾分支改为 `Contains` 后再 Add，避免重复项。
- 备注：落地 `Land()` 的爆炸伤害是独立结算，未做去重（属预期行为）。

## 实现：VFXAirdropEffect 三处"武器强化影响战备"的 TODO（56-74）
文件：`Assets/Scripts/Effect/VFX/VFXAirdropEffect.cs`、`Assets/Scripts/02Game/Gameplay/Projectile/AirdropPod.cs`

- **关键发现（原代码是死代码）**：原判定 `gameObject.TryGetComponent(out WeaponPlayerController weapon)` 中的 `gameObject` 是信标特效物体本身（`VFX_AirdropPoint.prefab`，全工程仅该 prefab 挂了 `VFXAirdropEffect`，且不含任何武器组件）→ 三个 TODO **永远不会执行**。武器参数实际来源是 `SetOwner(owner, weaponRoot, ...)` 的第二个参数（两个调用点都传武器根：`FpsHelper.Hit` 传 `hitData.weapon.gameObject`；`AirdropController.OnWaitRelease` 传信号枪 `GetWeapon(FlareGun).gameObject`）。已改为 `weaponRoot.IsValid() && weaponRoot.TryGetComponent(...)`。
- 三个强化的落点（都是"runtime AirdropData 覆盖"，Idempotent 且以 `cfg` 为基准，不写 SO）：
  1. `取消空投准备时间`（仅 `type==Blue`）→ 置 `m_SkipDeployWait`，在 `Init()`（`SetDisplay` 之前）调 `ApplySkipDeployWait()`：`data.arriveTime = data.time =`(Pod:`max(1,ceil(落体时间))`／其他投送:`0`)。**必须同步 `data.time`**，因为释放时 `OnRelease` 已把 State 置 Arrive 并按旧 arriveTime 写入剩余时间；若直接置 0，空投舱分支永远不创建（`UpdatePod` 只认 State==Arrive）且会误入 Sustain 兜底分支。
  2. `自费空投`（Blue）→ `data.cool = RoundToInt(cfg.cool*0.9f)`（用 cfg 基准，避免每次呼叫连乘 0.9）。
  3. `空投降落速度`（Pod）→ `m_PodFallScale = 2f`，下发到 `AirdropPod.SetFallSpeedScale()`。
- `AirdropPod` 新增 `SetFallSpeedScale(float)`：**高度不变时把重力按倍率²放大**（V=√(2gh)、t=√(2h/g)）→ 落地速度恰好×2、落体用时÷2。Awake 缓存 `m_BaseGravity`，实际重力存 `m_Gravity`（不写回序列化字段，避免池化实例被反复叠加），`OnEnable` 复位倍率，`Launch` 时换算。`VFXAirdropEffect.PodFallTime()=√(h*0.1)/倍率` 同时用于 `m_ExpectedDuration`（决定何时投放空投舱）与跳过等待的部署时间，两者保持一致 → 空投舱正好在部署阶段结束时落地。
- 复位：三个强化状态在 `OnDisable` 开头复位（该处原 `if (!m_creatObject.IsValid()) return;` 早退必须在复位之后，否则池化复用会串状态）。
- 边界：Medivac(`deliveryType=3`) 只有 Orange/Yellow 类型，不受 Blue 守卫影响（`data.arriveTime=0` 会让 `SetDiveDuration(-2)`，已确认该函数对 ≤0 做了兜底）。

## 修复：爆炸伤害点（伤害数字/受击反馈位置）显示错误
文件：`Assets/Scripts/00Tools/FpsHelper.cs`（`Hit()` 爆炸结算循环）

- 现象：`DamagePacket.Pos` 直接传爆心 `point` → 大范围爆炸时所有目标的伤害数字堆在同一点；改传 `exolosionCollider.bounds.center` → 打巨型单位（整片大护盾球）时数字显示在包围盒球心，离实际命中面几十米，看不出打中了哪。
- 根因：`Pos` 的正确语义是"被命中碰撞体表面、朝向爆心的最近点"（`packet.Pos` 最终流向 `Health.TakeDamage` 的 `OnHit` 与 `Tool.DrawLabel`，见 `Health.cs:199/232`）。
- 修复：新增 `FpsHelper.GetExplosionHitPoint(Collider, Vector3 explosionCenter)`：
  - 凸碰撞体/盒/球/胶囊用 `collider.ClosestPoint(explosionCenter)`（表面最近点，巨型护盾会精确落在朝爆心的护盾面上）；
  - 非凸 `MeshCollider`（`ClosestPoint` 会原样返回入参）退化为 `ClosestPointOnBounds`；
  - 爆心落在碰撞体内部（最近点≈爆心）或 collider 为空时回退爆心。
  - `explosionPacket.Pos = hitPoint`（旧两行以注释形式保留对比）。
- 未改动（如需再议）：伤害衰减仍按 `bounds.center` 距离判定内半径（`centerDisance`），巨型单位因此几乎永远吃不到内圈满伤；此为数值平衡问题，与显示点无关。
