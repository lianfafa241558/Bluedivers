## 修复：ToonLit 附加光阴影不生效

现象：`Assets/Shader/ToonLit/Main/ToonLit_Shared.hlsl` 的 ForwardLit 里，附加光（Point/Spot/额外 Directional）没有阴影。

根因（三重掐断，前两条都是必须的）：
1. **缺 `_ADDITIONAL_LIGHT_SHADOWS` 关键字**：URP `Shadows.hlsl:21` 用 `#if defined(_ADDITIONAL_LIGHT_SHADOWS) → #define ADDITIONAL_LIGHT_CALCULATE_SHADOWS` 把关；`AdditionalLightRealtimeShadow()` 整段在 `ADDITIONAL_LIGHT_CALCULATE_SHADOWS` 内，否则直接 `return 1.0`。各 .shader 里 `//#pragma multi_compile_fragment _ _ADDITIONAL_LIGHT_SHADOWS` 被注释掉了。
2. **用了 2 参 `GetAdditionalLight(i, positionWS)`**：`RealtimeLights.hlsl:249` 该重载不填 `shadowAttenuation`（恒 1.0）；只有 3 参重载 `GetAdditionalLight(i, positionWS, shadowMask)` 才走 `AdditionalLightShadow()`。
3. 原代码里注释掉的 `AdditionalLightRealtimeShadow(lightIndex, shadowTestPosWS)` 本来就替代不了上面两点。

修改：
- `ToonLit_Shared.hlsl` `ShadeAllLights`：加 `half4 shadowMask = CalculateShadowMask(inputData);`，改用 3 参 `GetAdditionalLight(lightIndex, lightingData.positionWS, shadowMask)`。注意**不要**传 `shadowTestPosWS`——它含 `+ _IsFace`（面部材质 = 1 单位），会把点光源的距离/衰减算歪，只该用于阴影采样。
- `ToonLit.shader` / `ToonLit_Hair.shader` / `ToonLit_Colour.shader` / `ToonLit_Face.shader` / `ToonLit_MouthEye.shader` 的 **ForwardLit** pass 补 `#pragma multi_compile_fragment _ _ADDITIONAL_LIGHT_SHADOWS`。Outline pass 未加（描边壳不需要）。

遗留/提醒：
- 附加光阴影观感天生偏弱：`ShadeSingleLight` 里是 `lerp(_ShadowMapColor=(0.8,0.8,0.8), 1, litOrShadowArea)` + `_ReceiveShadowMappingAmount=0.65`，全阴影只掉 ~13% 亮度，且附加光是叠加项。需要更强的附加光阴影要调 `_ShadowMapColor` / `_ReceiveShadowMappingAmount`（会同时影响主光）。
- 前置条件已满足：URP Asset（`Assets/Setting/New Universal Render Pipeline Asset.asset`）`m_AdditionalLightsRenderingMode:1` + `m_AdditionalLightShadowsSupported:1`；URP 14 的 `USE_STRUCTURED_BUFFER_FOR_LIGHT_DATA` 硬编码为 0（走 UBO），与 C# 侧 `RenderingUtils.useStructuredBuffer=false` 一致。

关键 URP 14 事实（可复用）：
- `GetAdditionalLight` 有 2 参（无阴影）/ 3 参（含阴影）/ 4 参（+ AO）三个重载。
- `LIGHT_LOOP_BEGIN` 宏体内部直接引用名为 `inputData` 的变量（Forward+ 的 `ClusterInit` 要用），所以调用处必须先声明 `InputData inputData`。
- 本 shader 没声明 `_ADDITIONAL_LIGHTS` 关键字，但 `_AdditionalLightsCount` / `unity_LightIndices` / `AddtionalLights` CBUFFER 都是无条件声明的，所以灯循环照常工作，只是无法在打包时剥离。

## 修复：ToonLit 背光面也受光（与 URP Lit 不一致）

现象：URP Lit 里背光/法线背对光源的面完全不亮，ToonLit 里却有一大片随点光源衰减的亮斑。

根因（`ToonLit_LightingEquation.hlsl: ShadeSingleLight`，两个叠加）：
1. `_CelShadeMidPoint` 默认 **-0.5**（wrap lighting）：`smoothstep(-0.55, -0.45, NoL)`，NoL 到 -0.45（≈117°）都算"亮面"，光会绕到背面。
2. `_ShadowMapColor` 默认 **(0.8,0.8,0.8)**：`litOrShadowColor = lerp(_ShadowMapColor, 1, litOrShadowArea)` —— **判成暗面时这个光仍保留 80% 的贡献**（不是 0）。全项目 ~490 个 ToonLit 材质 `_CelShadeMidPoint: -0.5` + `_ShadowMapColor≈0.8`（个别 0.745/0.85/暖色）。
- 结论：在这套模型里"暗面 = 该光源的 0.8 倍颜色"，所以要"背光完全不受光"必须让 `_ShadowMapColor` 参与归零；只调 `_CelShadeMidPoint` 没用。

修改：`ToonLit_LightingEquation.hlsl` 在 `litOrShadowColor` 之后加 `litOrShadowColor *= step(0.0, NoL);`（背光半球归零，语义对齐 URP Lit 的 saturate(NoL)；`_CelShadeMidPoint>0` 仍可把交界往亮面推，但不能越过几何交界）。

备选/后续：
- 若想"背光+投影阴影都只吃环境光"（最接近 URP Lit），直接批量把材质 `_ShadowMapColor` 调黑即可，不必改 shader；但要批量改 ~490 个材质（可用 `PrefabBatchToolBase` 之类工具）。
- `_ShadowMapColor=0.8` 同时导致**太阳投影只掉约 13% 亮度**（`litOrShadowArea *= lerp(1, shadowAttenuation, _ReceiveShadowMappingAmount=0.65)` 后 lerp(0.8,1,·)）——投影偏弱要一起考虑。
- `ToonLit.shader` 的 Properties 里 `_DirectLightMultiplier` / `_IndirectLightMultiplier` / `_MainLightIgnoreCelShade` / `_AdditionalLightIgnoreCelShade` **没写进 `ToonLit_Shared.hlsl` 的 CBUFFER** → 是死属性，调了没反应（新增 CBUFFER 字段必须同时写进每个 .shader 的 Properties，否则 SRP Batcher 填不到值）。

## 排查：ToonLit 材质不投射阴影

结论：**这套 shader 里唯一能"决定不投影"的材质级东西是 shader 变体**，不是任何 `_xxx` 参数。

- `ToonLit_MouthEye.shader`（guid `afe1998a2df3bc8429cf1e9c9d048910`）**整个 SubShader 只有一个 ForwardLit pass**（全文只有 1 处 `#include "ToonLit_Shared.hlsl"`）→ 没有 ShadowCaster、也没有 DepthNormals → 用它就永远不投影。现有 11 个材质用它：`Assets/Art/Modle/Student/*/*EyeMouth*.mat` / `Kei_Mouth.mat`。
- 其余 4 个变体（ToonLit / _Hair / _Face / _Colour）都有 ShadowCaster pass。
- 主 shader 的 ShadowCaster pass **不读任何 UnityPerMaterial 变量**：`VertexShaderWork` 里用到材质参数的代码全在 `#ifdef ToonShaderIsOutline` 内（ShadowCaster 不定义该宏，它定义的是 `ToonShaderApplyShadowBiasFix`）；片元 `BaseColorAlphaClipTest` 直接 `return half4(input.normalWS,1);`，`DoClipTestToTargetAlphaValue` 被注释掉。→ 参数无法影响投影。
- 澄清：材质面板最上面的 `_MAIN_LIGHT_SHADOWS` 勾选框管**接收**阴影（`[Toggle(_MAIN_LIGHT_SHADOWS)]`，本地关键字覆盖 `#pragma multi_compile`），不是投射；`ToonLit_Face`/`ToonLit_MouthEye` 的自定义 GUI 里根本没画它。
- URP 侧：`MainLightShadowCasterPass` 用 `context.DrawShadows(ShadowDrawingSettings)` 剔除 → **Render Queue 不影响投影**（别往 Transparent 队列上想）；`useRenderingLayerMaskTest = asset.useRenderingLayers`（本工程未开 Light Layers）。
- 非材质候选：MeshRenderer Cast Shadows=Off / 超出 `m_ShadowDistance:100` / 灯光 Culling Mask 不含该 layer / **ShadowCaster pass 里 `Cull Back` 写死**（单面片背对光源时在阴影贴图里被剔除）。

顺带发现的两个真问题（同一个 ShadowCaster pass / shader）：
- `BaseColorAlphaClipTest` 的 clip 被注释 → 溶解/嘴部裁切在阴影贴图里不生效，已溶解消失的物体仍投完整阴影。
- 5 个变体都只有 `DepthNormalsOnly`（LightMode 同）而**没有 `DepthOnly`** → URP 只用纯深度 prepass 时（`DepthOnlyPass` 找 `ShaderTagId("DepthOnly")`）这些物体不写深度。
- 附带：`Assets/Shader/Editor/ToonLitShaderGUI.cs` 整个 class 被 `/* */` 注释掉，但 `ToonLit.shader` 仍写着 `CustomEditor "ToonLitMainShaderGUI"` → 实际走默认 Inspector（所以 `_MAIN_LIGHT_SHADOWS` 勾选框反而可见）。

### 真凶（用户给的具体材质）：`disabledShaderPasses: - SHADOWCASTER`

`Assets/Art/Test/Hull2Test.mat:37-39`：
```
  disabledShaderPasses:
  - DepthOnly
  - SHADOWCASTER
```
- 这是**材质级 pass 开关**（`Material.SetShaderPassEnabled("ShadowCaster", false)` 的序列化结果），**不是 shader 属性**，所以材质面板上看不到、调任何 `_xxx` 都无用；URP 用 `ShaderTagId("ShadowCaster")` 找 pass，被材质禁用就完全不进阴影贴图。
- 全项目 89+ 个 .mat 带这条（`Polt0/School_01|Desert_01|Bbackstreet_01|KaiserBoss2|PlanetGloss*.mat` 等实体材质也中招；VFX/贴花那批是有意关的）。对照：`Polt0/Standard_9.mat` 是 `disabledShaderPasses: []`（正常）。排查用 `grep -n "^\s*-\s*SHADOWCASTER"` 找 .mat，别用 `disabledShaderPasses:\s*\n` 这种跨行正则（我这边 multiline 没命中过）。
- 修法：删掉 .mat 里 `- SHADOWCASTER`（`- DepthOnly` 对本 shader 是空操作，因为本 shader 没有 `DepthOnly` pass）；或 `mat.SetShaderPassEnabled("ShadowCaster", true)`。批量要按 shader/路径过滤，别一刀切。

### DepthNormalsOnly vs DepthOnly（URP 14）
- 都被 URP 当"预写"pass，`BeforeRenderingPrePasses` 执行，`RenderQueueRange.opaque`（`UniversalRenderer.cs:244-245`）。
- tag 与 Pass 类：`DepthOnlyPass` 找 `"DepthOnly"`（`DepthOnlyPass.cs:15`）；`DepthNormalOnlyPass` 找 `{"DepthNormals","DepthNormalsOnly"}`（`DepthNormalOnlyPass.cs:22`，两个 tag 等效——URP 自己 Lit 用 `DepthNormals`，Unlit/BakedLit/ComplexLit/粒子用 `DepthNormalsOnly`）。
- 输出：DepthOnly = 只写深度（`ColorMask 0`）→ `_CameraDepthTexture`；DepthNormals(Only) = 一次写**深度+法线** → `_CameraDepthTexture` + `_CameraNormalsTexture`（SSAO/贴花法线混合/软粒子/RendererFeature 声明 `ScriptableRenderPassInput.Normal`）。
- 同一帧只跑一个（`UniversalRenderer.cs:1007-1045`）：需要法线 → DepthNormalOnlyPass（顺带写深度）；否则 → DepthOnlyPass。→ **只提供一种 tag 的 shader 在另一种情形下完全不写**。相机"是否需要深度纹理"是相机级设置（URP12+ 在 Camera → Rendering → Depth Texture）。
- 本项目 ToonLit 5 个变体都只有 `DepthNormalsOnly`、无 `DepthOnly` → 相机勾了 Depth Texture 但没开 SSAO/贴花时，这些物体不在 `_CameraDepthTexture` 里（影响 SSAO/软粒子/体积云手比深度）。补一个 `DepthOnly` pass 可解。
- `ToonLit.shader:353` 的 DepthNormalsOnly pass 定义了 `ToonShaderIsOutline` → 写进深度/法线 buffer 的是描边外扩后的几何。

### 已做：溶解/嘴部裁切在阴影与深度 pass 里生效

`ToonLit_Shared.hlsl` 的 `BaseColorAlphaClipTest` 原来是 `return half4(input.normalWS,1);` + 注释掉的 clip → ShadowCaster / DepthNormalsOnly / DepthOnly 三个 pass **都不裁切**，溶解掉的物体照旧投影、照旧写深度。现改为先 `DoClipTestToTargetAlphaValue(GetFinalBaseColor(input).a);` 再 `return half4(input.normalWS, 1);`（DepthNormalsOnly 要靠这个返回值写法线；另两个 pass 是 ColorMask 0，返回值被丢弃）。复用 ForwardLit 同一套函数/阈值 → 可见轮廓与投影轮廓严格一致。代价：这三个 pass 现在会多采样 `_BaseMap`（必要时 `_AlphaMap`）。

### 已查清：`disabledShaderPasses` 到底是怎么来的（用户最关心的点）

结论：**这个字段属于"材质"，不属于 shader；换 shader 不会清空它，复制材质会连它一起复制。** 所以它是历史残留，不是当前哪个参数。

证据链：
1. 写入途径只有 `Material.SetShaderPassEnabled()`（脚本/编辑器 GUI）。全仓搜 `SetShaderPassEnabled` / `OnPostprocessMaterial` / `disabledShaderPasses`（Assets + Packages，任意文件类型）**0 命中** → 现在没有任何代码在写它（曾经存在过、后来删掉的工具无法追溯）。
2. `Assets/Art/Modle/Scene/Hull_Light.mat` 现在用的是 **Unity 内置 shader**（`m_Shader: {fileID: 200, guid: 0000000000000000f000000000000000}`），却仍带着 `- DepthOnly`。`DepthOnly` 是 URP 专属 tag（内置管线的 `_CameraDepthTexture` 是靠 ShadowCaster pass 写的）→ 这条必然是"当年用 URP shader 时"写进去的残留。
3. `Art/Modle/Scene/Hull.mat` 与 `Art/Test/Hull2Test.mat` 同名同尺寸（6.17KB）、禁用列表一模一样 → `Hull2Test` 就是从 `Hull.mat` 复制/另存出来的，`m_DisabledShaderPasses` 被一起复制。
4. 213+ 个 ToonLit 材质残留 `_ShowX` / `_UseMosaic` / `_Discoloration` / `_ColourOutlineWidth`，而**当前所有 .shader / .cs 里都没有这些属性** → 这批材质都换过 shader（原 shader 已不在项目里），属性和 pass 黑名单一起残留。
5. 同一 shader 下有的中招有的正常（`Polt0/Standard_9.mat` 是 `[]`）正是这种历史残留的分布特征。

**工具经验**：`search_content` 的 glob 不支持 `*.{a,b}` 这种花括号（会假 0 命中），要一个个写 `*.shader`、`*.cs`。
