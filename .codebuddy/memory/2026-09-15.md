## 修复：敌人受击闪白"执行到一半就停住（残留亮斑）"
文件：`Assets/Scripts/02Game/AI/FxCont/RendererSet.cs`

### 现象
MPB 触发器渐变（`EFD_Enemy.asset` 条目2：type=Trigger/occasion=Hit/colorName 空→`_HitColor`/duration=0.1，渐变 黑→灰0.5(0.23)→灰0.5(0.8)→黑(1.0)）有时播不完、有时停在"亮的部分"不动。

### 根因
`Update()` 只在 `(Time.time - lastTriggerTime) <= Config.duration` 时写颜色，**超时后没有收尾分支**。
`Renderer.SetPropertyBlock` 是把块**拷贝存到 Renderer** 上，之后没人写就一直留着 → 最后一帧算出的颜色（progress ∈ (1帧/duration, 1)，即 0.83~1.0 的渐变尾段，亮度 0~0.42 灰）被**永久钉住**。触发相位随帧随机 → 表现为"有时候"。
另：`duration` 很小时首帧就超时 → 一帧都不写，整个闪变被跳过（同源问题）。
隐含冲突：同一 Renderer+materialIndex 只有一个 PropertyBlock，多条目（EFD_Enemy 条目2/3 都 `material: 无`）会整块互相覆盖，残留在别的条目写入时才被顺手抹掉。

### 修复
- 新增 `private bool playing` 显式播放态；`Trigger` 命中时置 true。
- `Update` 首行 `if (!mpb.IsValid() || !playing) return;`
- 两个分支都用 `Mathf.Clamp01` 求进度，**超时那一帧也写一次终点色**（Trigger=`gradient.Evaluate(1)`，Switch=`Color.Lerp` 收敛到目标色），随后 `playing=false`。
- 抽出 `ApplyColor(Color)`（SetColor + ApplyToRenderers + mpb.Clear）；Switch 的魔数 2 提为 `const float SwitchDuration = 2f`。

### 相关常识
- `_HitColor` 在 `ToonLit_Shared.hlsl:409` 是**自发光叠加**（`result = _HitColor;`），默认 `(0,0,0)`＝无闪光，故终点写黑即"无效果"。
- `mpb.Clear()` 在 `ApplyToRenderers()` 之后是安全的（SetPropertyBlock 是拷贝语义）。

## 重构：MPB 所有权从"条目"下沉到"渲染槽位"（解决多条目互相整块覆盖）
文件：新增 `Assets/Scripts/02Game/AI/FxCont/RendererSlot.cs`；改 `RendererSet.cs`、`EnemyControllerFX.cs`

### 问题
`Renderer.SetPropertyBlock(mpb, index)` 是**整块替换并拷贝到 Renderer**：同一 (Renderer, materialIndex) 上原来每个 RendererSet 条目各持一个 MPB，各自 Flush → 后写的把前一个条目设的属性整块抹掉。
`EFD_Enemy.asset` 条目2（`_HitColor` 受击）与条目3（`_DissolveValue` 死亡）都是 `material: 无` → 命中同一槽位 → 条目1 的 Switch 自发光（`_EmissionColor` 警戒白）会被受击闪白顺手抹掉。

### 方案（槽位为中心）
- 新类 `RendererSlot{Renderer, MaterialIndex, mpb, dirty}`：`SetColor(id,color)` 写块+置脏；`Flush()` 把整块 `SetPropertyBlock` 回渲染器（无写入/渲染器已销毁则跳过）。
- `RendererSet`：删掉自持 `mpb`、`List<(Renderer,int)>`、`ApplyToRenderers()`；改为 `List<RendererSlot> slots` + `AddSlot(slot)`；`ApplyColor` 只往各槽位 `SetColor`；`mpb.IsValid()` 的"有无匹配槽位"判断改成 `slots.Count > 0`。
- `EnemyControllerFX`：新增 `List<RendererSlot> slots`；`InitRS` 的外层循环正好每个 (renderer, materialIndex) 访问一次 → 在该层 `RendererSlot slot = null;` 惰性创建、命中条目共用同一个 slot 引用（**无需字典**）；`UpdateRS` 在**所有条目 Update 之后**统一 `Flush()` 各槽位。
- 槽位块跨帧保留 → 多个条目的属性天然共存（这既是修复点，也是新约束：条目必须在自己动画收尾写回"无效果值"）。

### 附带收益
一个槽位每帧最多一次 SetPropertyBlock（原来 N 个条目 N 次），且不再互删属性。

## 排查：unity-mcp「连不上 Unity 实例」
- 现象：CodeBuddy 能调用工具（`manage_scene`/`read_console` 都能发出），但一律返回 `No Unity Editor instances found`；`mcpforunity://editor/state` 字段全 null。
- 证据链：Unity 进程在跑；但 **6400（stdio 桥）/ 8080（HTTP 服务器）都没监听**，`~/.unity-mcp/` 无 `unity-mcp-status-*.json`，`Assets/UnityMCP/` 无日志 → Unity 侧桥**根本没启动**。
- **根因**：v10 默认走 **HTTP 传输**，而两个开关都是「默认不启动」——
  - `EditorConfigurationCache.UseHttpTransport = EditorPrefs.GetBool("MCPForUnity.UseHttpTransport", **true**)` → 默认 HTTP
  - `StdioBridgeHost.ShouldAutoStartBridge() => !useHttpTransport` → HTTP 模式下 **stdio 桥不自启**
  - `EditorPrefKeys.AutoStartOnLoad`（`MCPForUnity.AutoStartOnLoad`）默认 **false**，且**只对 HTTP 生效**
  → 默认配置下 Unity 侧什么都不起；而 CodeBuddy 的 mcp.json 是 **stdio** → 两头都对不上。
- 关键源码位置：`Packages/com.coplaydev.unity-mcp/Editor/Services/Transport/Transports/StdioBridgeHost.cs`（`[InitializeOnLoad]`，TCP `IPAddress.Loopback:6400`，握手 `WELCOME UNITY-MCP 1 FRAMING=1`，状态文件 `%USERPROFILE%\.unity-mcp\unity-mcp-status-{projectHash}.json`）、`Services/EditorConfigurationCache.cs`、`Helpers/HttpEndpointUtility.cs`（默认 `http://127.0.0.1:8080`）、`Constants/EditorPrefKeys.cs`。
- 两种修法：**A** Unity 窗口 `Window → MCP for Unity` → Connection 里把 Transport 切 **Stdio**（stdio 桥随即自启，CodeBuddy 配置不用动）；**B** 保持 HTTP → 窗口点 **Start** 或勾 Advanced 里的 Auto-Start on Editor Load → CodeBuddy 的 mcp.json 改成 HTTP 端点 `http://127.0.0.1:8080/mcp`。
- 诊断技巧：`Get-NetTCPConnection -State Listen` 查 6400/8080；`Test-Path "$env:USERPROFILE\.unity-mcp"` 判断 Unity 桥是否起过。

## 修复：Unity 警告「meta 存在但文件夹不存在」+ MCP 包编译失败（严重）
现象（用户贴的 Console 警告）：`A meta data file (.meta) exists but its folder 'Packages/com.coplaydev.unity-mcp/Editor/Tools/Build' can't be found, and has been created.`

### 根因（两层，缺一不可）
1. **`.gitignore` 第 5 行 `[Bb]uild/` 未锚定** → 匹配任意层级名为 Build 的目录，把 `Packages/com.coplaydev.unity-mcp/Editor/Tools/Build/`（**包源码**）整目录静默忽略。上次把该包提交进 git（今天 C1 提交）时，只有 `Tools/Build.meta` 入了库，目录内 4 个 `.cs` 被跳过。
2. 该目录下 4 个脚本后来从工作区消失（被忽略的未跟踪文件，`git clean -xfd` 之类清理即可删掉）→ Unity 只剩 `Build.meta`、没有 `Build/`，于是自动建空文件夹并告警。

### 后果（Editor.log 实证）
`Packages\...\Editor\Tools\ManageBuild.cs(9,32): error CS0234: 命名空间"MCPForUnity.Editor.Tools"中不存在类型或命名空间名"Build"` → **MCPForUnity.Editor 程序集整体编译失败**（`Library/ScriptAssemblies` 里只有 `MCPForUnity.Runtime.dll`，无 Editor.dll）→ MCP 全部工具不可用。

### 修复
- 从上游 `main` 取回 4 个脚本 + 4 个 `.meta`（`BuildJob.cs` 6593B / `BuildRunner.cs` 10893B / `BuildSettingsHelper.cs` 4342B / `BuildTargetMapping.cs` 6587B，meta 各 240B），放入 `Editor/Tools/Build/`，并 `git add` 纳入版本控制。
- 本机 GitHub 直连被 reset，**镜像是 `cdn.jsdelivr.net/gh/CoplayDev/unity-mcp@<ref>/<path>`**（ghproxy.net 也可）；文件清单可用 `data.jsdelivr.com/v1/packages/gh/<owner>/<repo>@<ref>?structure=flat`。
- 版本核对：本地包与上游 `main` **逐文件一致**（`ManageBuild.cs`/`ManageScene.cs`/`McpLog.cs`/`GenerateAudio.cs`/`UnityCompatShims.cs` 规范化换行后完全相同）→ 取回的 Build 四件套正是对应版本；静态校验 `ManageBuild.cs` 依赖的 21 个成员全部存在；新 meta 的 GUID 在包内唯一。
- **`.gitignore` 修正**：所有 Unity 生成目录规则加根锚定 `/Library/ /Temp/ /Obj/ /Build/ /Builds/ /Logs/ /UserSettings/`，杜绝同类误忽略（附中文注释说明原因）。

### 顺带发现（已按用户要求入库）
`Assets/Art/Anim/Build/`（Beacon/Door/KeyScreen 的 controller+anim，14 文件）与 `Assets/Art/Modle/Enemy/Build/Factory/`（fbx+5 贴图+2 材质+meta，17 文件）此前**同样被误忽略、从未入库** → 已 `git add`（共 31 文件）纳入版本控制；全库已无被忽略的 Build 目录。

### 教训
- Unity 里「meta 存在但文件夹不存在」的警告**极少是纯空目录问题**，先查 `.gitignore` 是否误忽略了该目录内的文件（空目录 git 不存，但源码被忽略更常见）。
- `.gitignore` 里的 Unity 生成目录规则一定要 `/` 锚定，否则会命中 `Packages/**/Build`、`Assets/**/Build` 这类源码/美术目录。
- 排查上游包缺文件：`git ls-files <包路径>` 与镜像清单比对，再逐文件规范化换行后比对哈希。
- 恢复后需回 Unity 触发重编译（`Library/ScriptAssemblies/MCPForUnity.Editor.dll` 出现即正常，MCP 工具即可用）。
