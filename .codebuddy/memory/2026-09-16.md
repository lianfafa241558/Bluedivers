## UIImageChannelMix.shader 不响应 RectMask2D 的修复
- 现象：`Assets/Shader/UIImageChannelMix.shader` 的 Image 溢出父级面板边框，不被 RectMask2D 裁掉
- 根因：**RectMask2D 不用模板缓冲**。它走 `MaskableGraphic.SetClipRect` → `CanvasRenderer.EnableRectClipping(rect)`，原生把裁剪矩形注入为 `_ClipRect` 并打开 `UNITY_UI_CLIP_RECT` 关键字，要求 shader 自己在片元里做 alpha 软裁剪。原 shader 只有 `_Stencil*`（那套只对 `Mask` 组件生效），既没声明 `_ClipRect`、也没该关键字变体、更没把位置传进片元 → RectMask2D 完全失效
- 修复（已改文件）：加 `#pragma multi_compile_local _ UNITY_UI_CLIP_RECT`；`float4 _ClipRect` 放在 HLSL 里（**不进 Properties**，与内置 UI/Default 一致）；v2f 加 `float2 clipPos : TEXCOORD2` 取 `v.vertex.xy`（**必须与 `_ClipRect` 同空间＝对象/Canvas 局部空间**，不能用 URP 的 `positionWS`）；片元 `finalAlpha *= Unity2DClipping(i.clipPos, _ClipRect)`（`UnityGet2DClipping` 内联实现，避免 URP 头与 `UnityUI.cginc` 混用）
- 校验依据：拉取 Unity 内置 `UI-Default.shader` 源码（jsDelivr 镜像 TwoTailsGames/Unity-Built-in-Shaders）逐字对照，确认 `multi_compile_local`（非 global）、`_ClipRect` 不在 Properties、`OUT.worldPosition = v.vertex`
- 另外两个同类失效点（排查时先看）：Graphic 的 `Maskable` 是否被取消勾选；该 Image 是否挂在**子 Canvas** 下（RectMask2D 只作用于同一 Canvas 的后代）

## AirdropConfigWnd 展示模型：不再执行任何 Awake
- 需求：展示模型要关掉根物体上除 Animator 以外的组件，且希望这些组件连 Awake 都别执行
- 关键点：**`enabled = false` 拦不住 Awake**（Awake 只看 GameObject 是否 activeInHierarchy），`SetActive(false)` 若在 Instantiate 之后也来不及（Awake 已在 Instantiate 时同步跑完）
- 做法：① 运行时先建一个 `_modelHolder`（挂在 `_modelRoot` 下并 `SetActive(false)`）② `Instantiate(prefab, _modelHolder.transform)` —— 实例不在激活层级中，所有组件的 Awake/OnEnable 都不执行 ③ `StripModelRoot` 用 `Tool.Destroy`（延迟到帧末生效）移除根物体上除"渲染/动画"白名单（Transform/Animator/Renderer/MeshFilter/LODGroup/ParticleSystem）以外的全部组件 ④ 协程 `ActiveModelNextFrame` 等一帧再 `holder.SetActive(true)`，确保被移除的组件已经真正销毁、不会抢到 Awake ⑤ `ClearModel` 一并销毁 holder
- 代价：模型晚一帧显示（无闪烁风险时也可改 `DestroyImmediate` 立即激活）
- 未覆盖：**子物体上的 MonoBehaviour 仍只是 `enabled = false`**，激活时它们的 Awake 依旧会执行一次；要彻底干净需把 Strip 扩到整棵子树
- 顺带发现（与本改动无关，疑似旧代码遗留）：Console 有两条 `MissingReferenceException: The object of type 'Actor' has been destroyed`，栈为 `Furniture_Door.Update`(:24) → `BaseMono.get_Pos`(`GameRootBase.cs:84`)，即全局 Actor 列表里残留了已销毁的 Actor

## AirdropConfigWnd 展示模型：按体型自适应缩放（FitModelScale）
- 需求：不同体型的战备在展示区里大小要一致
- 实现 `FitModelScale()`：① 先把 `localScale=one / localPosition=zero` 复位再量尺寸（保证重复调用幂等）② 合并所有 `Renderer.bounds` 求世界包围盒 ③ 用相机在"到挂点距离"处的视野半高/半宽算缩放：**水平按 XZ 半对角线**（绕 Y 拖到任意角度都不出框）、**竖直按 Y 半高**，取两者较小值 × `_modelViewFill` ④ `localPosition = -包围盒中心 * scale` 把包围盒中心对齐到挂点原点（`_modelRoot` 有 yaw / 父级有缩放时该式依然成立，因为 `_model.localRotation` 恒为单位四元数）
- 调用时机：`ActiveModelNextFrame` 激活之后（**`Renderer.bounds` 在未激活时是零体积**，必须激活后才能量）；`SyncViewAspect` 检测到展示区比例变化时再调一次；量不到有效包围盒时保持原状不覆盖
- 新增 Inspector 字段 `_modelViewFill`（`[Range(0.1,1)]`，默认 0.85，中文名"模型展示占比"）；正交相机走 `orthographicSize`
- 校验：`validate_script` 0 error、重编译后 Console 0 error

## AirdropConfigWnd：默认朝向 180° + 模型"靠下"的根因（相机没正对挂点）
- 关键实测：`AirdropConfigWnd.prefab` 里 **cam pos=(-5,-10,0)、fwd=(0,0,1)、_modelRoot=(-5,-10.5,3.5)** → 相机视线中心比挂点高 **0.5**（`rootOffsetFromViewCenter.y=-0.5`），即相机并不是正对挂点
- 于是上一版"把包围盒中心对齐到挂点"会让所有模型偏下 0.5；无人机（`Healdrone_*`）本体中心在挂点上方 **1.63**，一居中就被整体压下 ~1.6（约 40% 视野高）→ 用户看到"几个无人机都靠下"
- 另外：这些战备预制体的根节点 localPosition 大多是"随手存下来的怪值"（Healdrone (3.675,-3.582,21.338)、Flag (192.48,26.8,153.4)、Machine (8.93,37.22,2.13)），`ShowModel` 里本来就归零，不用管
- 修法：① 新增 `[SerializeField] Vector3 _modelBaseEuler = (0,180,0)`（"模型默认旋转"，模型正面朝镜头用 180），抽 `ApplyModelRotation()` 把 `_modelRoot.localRotation = Euler(base.x, base.y + _yaw, base.z)`，ShowModel/ClearModel/HandleModelDrag 三处统一走它；朝向放在**挂点**上，模型自身 `localRotation` 保持 identity ② `FitModelScale` 改用**相机视线中心**做对齐目标：`depth = dot(root - camPos, fwd); focus = camPos + fwd * depth`，视野半高也按这个 depth 算；定位改为 `tr.position = focus - tr.rotation * Vector3.Scale(center, tr.lossyScale)`（`center` 是复位状态下 `InverseTransformPoint(bounds.center)` 得到的模型局部坐标，对任意朝向成立）

- 需求：预制体根节点自带旋转要叠加到「模型默认旋转」上，如 prefab(0,45,0) + base(0,180,0) → (0,225,0)
- 实测：48 个战备模型里 **8 个炮台预制体根节点自带 `(0,45,0)`**（G_Flame/Gatling/Laser/Machine/Mortar/Rocket、GE_AT、Y_Machine），根节点 scale 全为 1
- 实现：`ShowModel` 不再把 `_model.localRotation` 归零（原来会把这 45° 抹掉），只把预制体根节点那串随手存下来的位置归零，并缓存 `_modelBaseScale`；`ApplyModelRotation()` 仍只改挂点 → 模型世界旋转 = 挂点(默认朝向+拖动) ∘ 预制体自身旋转（纯 Y 轴即角度相加：180+45=225）
- 关键细节：**量包围盒时要临时把模型自身旋转归零**（量完还原），否则世界包围盒会被这层旋转撑大（炮台 1.49×3.08→3.23×3.23），缩放从 0.70 掉到 0.53（小 25%）；`center = tr.InverseTransformPoint(bounds.center)` 也要在这个"旋转归零"状态下算（那才是模型的局部坐标），之后用 `tr.rotation` 换算回世界偏移
- 自适应缩放最终写成 `tr.localScale = Vector3.Scale(_modelBaseScale, Vector3.one * (scale * 0.7f))`，其中 `0.7f` 是**用户手改的余量系数**，别当垃圾删掉
- ⚠ 用户还在这个文件里手改了两处：新增 `_bg` 字段 + `SetSprite(_bg, FpsHelper.CameraCaptureToSprite(Camera.main))`（窗口背景截图）。改这个文件前先 `git diff` 确认，别覆盖用户手改

## 诊断：RobotMine 爆炸后不消失
- 根因：`DeployableMine.Explosion()` 爆炸后只调 `VFXManager.Release(gameObject)`（:164），而该 API 仅处理**根物体**上的 `ParticleSystem`（`Stop`）或 `LimitedLife`（`allowRelease=true`）（`01Manager/Battle/VFXManager.cs:96-108`），两者都没有时**整个方法空转**，不销毁也不停用
- `Assets/Resources/Prefabs/Enemy/Robot/Royal/RobotMine.prefab` 根节点组件：Transform/Animator/Damageable/HealthOther/Actor/DeployableMine/ApplayMapTextureVariant/VerticalTerrain/SphereCollider → **无 ParticleSystem、无 LimitedLife**；且 `HealthOther.AutoDestroy: 0`，Actor 死亡也不销毁
- 它还是 `PMC_Nest{Small,Medium,Large}.prefab` 里预置的 PrefabInstance 子物体（非运行时 `VFXManager.Creat` 创建）→ 即使加了 LimitedLife 也没人轮询（`LimitedLife.IsAlive()` 只被 VFXManager 的池 `Update()` 调用），照样不会消失
- 对照组：玩家地雷 `Assets/Resources/Prefabs/Airdrop/Sub/Mine.prefab` 根节点**有** LimitedLife(LiftTime 360)，且它是池对象 —— `Resources/Weapons/Grenade/Mine.prefab` 的 `DamageData.ImpactVfx` 指向 Mine.prefab 根物体，落点由 `FpsHelper.Hit`(:291) 的 `VFXManager.Creat` 创建、再由 `GetComponentInChildren<IVfxEffect>().SetOwner` 部署 → `Release` 设 `allowRelease` 后池的 `ItemUpdate` 判定失活并 `SetActive(false)` 回收。所以"同样代码，玩家雷正常、巢穴雷不消失"
- 后果：残留 GameObject 的 SphereCollider(r=0.8) 继续挡子弹/触发投射物碰撞（Health 已 m_IsDead 不再结算），Actor 仍留在 ActorsManager（`ActorState=Dead` 只是让 `FpsHelper.VaildTarget` 过滤掉它）
- 修法（未实施）：A. 预制体勾 `HealthOther.AutoDestroy`（零代码，符合设计：`HealthOther.HandleDeath` 在触发 OnDie→Explosion 之后再销毁）；B. `DeployableMine.Explosion` 兜底：非池化实例（无 LimitedLife 且根上无 ParticleSystem）直接 `Tool.Destroy(gameObject)`
