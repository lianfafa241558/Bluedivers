## 咨询：如何让另一个 Unity 工程也用上 MCP for Unity

### 结论
**客户端配置不用改，工程侧各装一份。**

- 客户端（`C:\Users\admin\.codebuddy\mcp.json`）只需一份：`uvx mcp-for-unity` 这**一个** server 进程会自动发现**所有**运行中的 Unity 实例 —— 每个工程在 `%USERPROFILE%\.unity-mcp\` 下写自己的 `unity-mcp-status-<工程路径hash>.json`。
- 每个 Unity 工程要各做两件事：① 装包 ② Transport 切 `Stdio`。

| 路径 | Unity 版本 | Packages 现状 |
|---|---|---|
| `D:\Project\RTSClient` | **2022.3.62f3**（与 Bluedivers 同版本） | astar；无 unity-mcp、无 newtonsoft-json |
| `E:\rtsclient` | 2022.3.34f1c1（Unity 中国版） | astar、NB_FX |
| `D:\Project\TestProject` | 无 `ProjectSettings/ProjectVersion.txt`，疑似非 Unity 工程 | — |

### 接入步骤（目标工程视角）
1. **从本工程复制包**（才会带上已做的汉化）：
   `Copy-Item -Recurse "e:\Bluedivers\Packages\com.coplaydev.unity-mcp" "<目标>\Packages\com.coplaydev.unity-mcp"`
   ❗ 别改用 git URL 从上游装 → 拿不到汉化。
2. 目标工程 `Packages/manifest.json` 加两行：
   `"com.coplaydev.unity-mcp": "file:com.coplaydev.unity-mcp"`、`"com.unity.nuget.newtonsoft-json": "3.0.2"`
   （RTSClient 原本两者都没有；其 `com.unity.test-framework` 已是 1.1.33 ≥ 包要求的 1.1.31，不必动）
3. 打开目标工程 → `Window → MCP for Unity` → Connection → Transport = **Stdio**。
   ⚠️ **每个工程都要单独切一次**：`MCPForUnity.UseHttpTransport` 是 EditorPrefs、**按工程隔离**，新工程会回到默认 HTTP → 桥不自启 → 照样报 `No Unity Editor instances found`。
4. 多实例路由：`set_active_instance`（支持 `Name@hash` / hash 前缀 / **端口号**），或另配一个 server 条目加 `--default-instance`。
5. 端口不打架：stdio 默认 6400，被占用时 `PortManager.GetPortWithFallback()` 自动让到 6401、6402…
6. 风险：包是**按工程各存一份副本** → 汉化会**分叉**，日后升级需逐个工程覆盖，且别用旧副本覆盖新副本。

## 诊断：屏幕空间贴花（SimpleDecal）的两个视觉问题

用 MCP 查了当前场景（`Utnapishitim.unity`，非 Play）：全场只有 **1 个** `Decal/SimpleDecal` 渲染器 = `Dec_Pylon/Dec_Pylon/Cube`（材质 `Assets/Art/VFX/WarpIn/PylonPower.mat`，lossyScale 20/20/15）。它的参数正好对上截图现象。

### 现象一：开雾后整个贴花足迹变成肉眼可见的色块
- 材质：`_DecalSrcBlend=5`（SrcAlpha）、`_DecalDstBlend=7`（**DstAlpha**）→ 那个 `dst*dstA` = 背景被完整保留 ⇒ 实际是**加法式**混合（HDR 相机色 RT 无 alpha 通道时 dstA=1）。
- 纹理 `pylon_alpha1_orange.dds` 是 **DXT1**（无 alpha，名字里的 alpha1 也说明 alpha=1），`_Color.a=1`/`_EmittierColor.a=1` ⇒ `col.a=1`，末尾那句 `col.rgb *= col.a` 在本材质里是**空操作**。
- 于是黑底区域（贴花本来"什么都不加"）在开雾后，`MixFog` 把**雾色**插进输出并被加进画面 → 整块足迹变雾色方块；关雾时该区域只加自身颜色（≈黑）→ 看不见。⇒ **根因是"加法混合 + MixFog 混雾色"，不是预乘**。
- 正确写法（加法层只能被雾衰减、不能再叠一份雾色）：`col.rgb = MixFog(col.rgb, f) - MixFog(half3(0,0,0), f);`（数学上 = `col.rgb * 无雾强度`）。

### 现象二：相机进到 cube 内部就看不见印花
- 原因：`PylonPower.mat` 的 `_Cull = 2`（**Back**）。贴花靠 cube 罩住目标区 + 屏幕空间投影；相机在外部时 Back 面正好铺满足迹，一旦进到内部，所有面都变成背面 → 全剔除 → 一个像素都不栅格化。
- `SimpleDecal_Colour` 那批材质（如 `Assets/Art/VFX/VoidColour/ColoureDecal.mat`）`_Cull = 0`（Off），Off/Front 在内部都还能画 ⇒ 所以"不会消失"。
- 修法：`_Cull = 1`（Front，shader 默认值，每像素只画一次）或 `0`（Off，但外部双面会叠两次颜色）。

### 顺带（同源隐患，不必马上改）
- `SimpleDecal` 末行 `col.rgb *= col.a` 预乘 + 硬件 `SrcAlpha` 再乘一次 = **alpha²**；对 `_DecalDstBlend=OneMinusSrcAlpha` 那批材质（DecalLargeA/B/C 等）alpha<1 时雾只按 alpha² 生效，同样会出现"雾被吃掉"的边缘色块。要么删掉这行，要么改 `Blend One OneMinusSrcAlpha`。

### 已实施（同日）
- 贴图实测（Python 手解 DXT1）：`pylon_alpha1_orange.dds` 512²，四角/边缘**纯黑**、**alpha 全图恒 255**（DXT1 不透明模式，无透明通道）⇒ 整块方形都在输出，坐实"开雾后贴图黑处变雾色方块"。
- 全仓只有 `PylonPower.mat` 用加法混合（`_DecalDstBlend: 7`），其余 20 个 SimpleDecal 材质都是 10 ⇒ 只有它出这个方块。
- `SimpleDecal.shader` 新增 `[Toggle(_DecalAdditiveFog)] _DecalAdditiveFog` + `#pragma shader_feature_local _DecalAdditiveFog`，开启后 frag 改为 `col.rgb = MixFog(col.rgb,f) - MixFog(half3(0,0,0),f)`（恒等于 c × 无雾强度）；默认 0，不影响其它材质。
- ⚠ 本工程 toggle 关键字就是**原名**（`_DecalAdditiveFog`），**没有** `_ON` 后缀：`Material.EnableKeyword("_DECALADDITIVEFOG_ON")` 无效，得用 `Material.SetKeyword(ref LocalKeyword, true)`（CodeDom 编译时**必须带 `ref`**，`IsKeywordEnabled(ref k)` 同理）。
- `PylonPower.mat` 现状：`_Cull: 1`、`_DecalAdditiveFog: 1`、关键字 `_DecalAdditiveFog` 已 enable（走 MCP `execute_code` 写入 + SaveAssets，Console 无报错）。

### 为什么 SimpleDecal_Colour 不会出方块（推导结论，可复用）
- `ColoureDecal*` 材质是 `SrcAlpha / OneMinusSrcAlpha`：`out = C*A + B*(1-A)`，而 `B = F(1-i) + 地形*i`、贴花内部经 MixFog 得到 `C = F(1-i) + 颜色*i` ⇒ 代入后 `F(1-i)` 项被 `A + (1-A)` **彻底抵消**，只剩 `i*A*(贴花色-地形色)` → 雾在贴花足迹里既不增也不减。
- `DstAlpha` 是 `out = C*A + B`：`F(1-i)` 那份**没人抵消** → 纯额外叠加一份雾色 = 方块。
- 另外 Colour 路径的 alpha 还要乘 `_MainMaskTex`/`_ColourMaskTex` 遮罩，雾的贡献随之归零，边缘更看不到。
