## FakeAreaLight.shader 菲涅尔支持负值反向
- 文件：`Assets/Shader/FakeAreaLight.shader`（全仓唯一使用该段 fresnel 代码的 shader）
- 原逻辑：`NdotV = saturate(abs(dot(N,V)))` → `fresnel = pow(1-NdotV,_FresnelDecay)`（边缘→1，正对相机→0），`col.a = lerp(col.a, col.a*fresnel, _FresnelScale)`。`_FresnelScale<0` 时 lerp 会外插成 `a*(2-f)`，alpha 溢出 >1，不是想要的反向。
- 改法：符号决定方向、绝对值决定强度
  ```hlsl
  half fresnelDir = (_FresnelScale >= 0.0) ? fresnel : (1.0 - fresnel);
  col.a = lerp(col.a, col.a * fresnelDir, abs(_FresnelScale));
  ```
  正值行为与原来完全一致（scale=0 时 `abs=0`，依然无效果）。
- 负值下调参含义：`_FresnelDecay` 越大 → 不透明中心区越大、只在极边缘透明；越小 → 整片都偏透明。
- 顺带发现（未改）：CBUFFER 里声明了 `_FresnelWave` / `_FresnelWaveTime`，但 Properties 里没有 → 恒为 0，`if(_FresnelWave)` 的呼吸块实际永不执行（属"未写 Properties 的属性＝死属性"老坑）。

## 炼油任务（MissionOilRefining）补全 Repair 阶段

## 新增工具：材质引用查询窗口 `Assets/Editor/MaterialUsageFinder.cs`
- 菜单 `Tools/材质引用查询`：指定材质 → 列出所有使用它的预制体与资产，分四组（预制体直接引用 / 预制体变体与派生 / 其他资产 / 仅资产级依赖）。**不做场景扫描**（用户明确不需要）
- 两段式：先建两张表，再逐候选加载验证定位。表一「材质/模型 → 引用它的资产」；表二「预制体/模型 → 依赖它的预制体」（派生表）。全仓 5865 个资产约 1.8~2.5s，可取消。索引缓存在窗口字段里，`EditorApplication.projectChanged` 置 `_indexStale`，下次查询重建
- **预制体变体**（用户要求追加，且明确「不需要嵌套引用」）：变体若没覆盖材质，它自己的 `GetDependencies` 里**查不到材质**（`baseMatsAlsoInVariantDeps=0` 实测），只能靠预制体之间的依赖边反查。做法：建索引时对 `isPrefab` 的资产记录「dep 是预制体或模型 → 记 `_prefabUsers[dep] += path`」（不区分种类），查询时从候选集沿该表 BFS，每个可达预制体**加载后判 `PrefabUtility.GetPrefabAssetType == Variant`**：只有变体才收录并继续往下走（多级变体链可行），嵌套容器直接丢弃且不继续遍历；再用渲染槽位/序列化字段验证是否真的用到该材质（变体把材质覆盖成别的会被排除，实测 `KeyPlatform_Kaiser` 即被排除）。共 870 个预制体，其中 329 个依赖其它预制体、84 个是变体。实测 `AirdropGeneric_ncl`：直接 47 条 / 变体 22 条（12 个变体，含以 FBX 为基体的 `OilPlane`/`Lamp`/`EvacuationBeacon` 与以预制体为基体的 `FlagKaiser`），校验「变体分组内非变体条目＝0」
- 定位方式：① `Renderer.sharedMaterials[i]`（含 SkinnedMesh/Particle/Trail/Line/Sprite）② `Terrain.materialTemplate`（地形不走 Renderer 家族）③ `Graphic` 的 `m_Material`（**必须**用序列化字段校验：`Graphic.material` 未赋值时会回退默认 UI 材质，直接用属性判会有大量误报）④ 非渲染组件的 `SerializedObject` 全属性树扫 ObjectReference（脚本字段如 `BuildingFXController.fxMaterial` 就是这条路径找到的）
- **FBX 内嵌材质**：模型资产的 `GetDependencies` 报的是模型路径而非材质子资产路径 → 建表时额外记 `_modelRefs[模型路径]`（用 `TryGetModelContainer` 按 `.fbx/.obj/.dae/...` 扩展名切容器），查询时把「引用了该模型」的资产也纳入候选再验证。模型资产本身归「其他资产」（不是"未定位"）
- ⚠ **踩到的坑（已修）**：
  1. `EditorUtility.DisplayCancelableProgressBar` 会**派发编辑器事件**，导致本窗口 `OnGUI` 在索引还没建完时重入 → 再触发 `RunSearch` → `BuildIndex` 被重入 `Clear()`，把已建好的反查表清空（症状：候选数 0、结果全空，但 `_indexedAssetCount` 看着正常）。修法：`_searching`/`_indexBuilding` 重入锁 + 索引先建在**局部字典**里最后一次性替换字段

  3. 派生条目的说明只取文件名会在同名预制体上撞车（项目里有多个 `Artillery.prefab`）→ 用「上级目录/文件名」
- 只覆盖静态引用；运行时动态赋值（MPB、`new Material`、`Graphics.DrawMesh`）、场景中的对象、嵌套了候选预制体的外层预制体（用户明确不要）都不在范围内
