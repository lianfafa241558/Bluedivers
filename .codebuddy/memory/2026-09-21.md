## 【诊断】"子弹和人都能穿过树、别处却有空气墙"——MCP 实测结论

用 Unity MCP（实例 `Bluedivers@4a3e6a7b`，port 6400，projectRoot 已核对）在 Play 模式下读了真实状态：

### 1. 树穿模的根因：树的碰撞体压根没生成
- `TerrainCollider.m_EnableTreeColliders = 0`（**Enable Tree Colliders 没勾**）→ 地形树碰撞体是"运行时由 TerrainCollider 按 TreePrototype 复制生成"的，开关关着就一个都没有 → 在树原型预制体上加的 CapsuleCollider **完全无效**，子弹/玩家都穿
- Terrain 对象：`Terrain`，layer=3(Ground)，`preserveTreePrototypeLayers=False`（=树实例会被强制改成 Terrain 的层 Ground），`treeInstances=374`，`treePrototypes=11`
- 实例分布：`[0]=37 [1]=36 [2]=43 [3]=50 [4]=42 [5]=41 [6]=37 [7]=22 [8]=22 [9]=25 [10]=19` → 与"0-6 石块 / 7-10 树"完全吻合（石块 286 + 树 88）

### 2. 运行时层掩码（GameContract.LayerDefinition @ 01_GameContract）
| 属性 | 值 | 层 |
| --- | --- | --- |
| HittableLayers（子弹） | 73 | Default + Ground + Unit |
| HittableHighSpeedLayers | 601 | + Water + OnlyProjectile |
| MoveableLayers（玩家移动） | 8265 | Default + Ground + Unit + **AirWall** |
| UnitSeeLayers | 16393 | Default + Ground + Smoke |
| GroundLayers / UnitLayers / AirWallLayers | 9 / 64 / 8192 | Default+Ground / Unit / AirWall |

→ 结论：Terrain 在 Ground 层、树实例也会落到 Ground 层，**只要开启 Enable Tree Colliders，子弹和玩家就都会正确撞树**，无需改 LayerConfigInitializer。
另外 `Physics.queriesHitTriggers = True` → 武器射线默认**会命中 Trigger**，而可命中层含 Default，容易被误判为"子弹打在空气上"。

### 3. 树原型上挂的碰撞体（实测，全部 layer=Default，含"树冠级"大碰撞体）
- [7] `PP_Birch_Tree_05 2`：Capsule r=0.6 h=8 c=(0,4,0) ＋ **Sphere r=3 / r=2 / r=2 / r=2.5**
- [8] `PP_Birch_Tree_06 4`：Capsule r=0.6 h=8 c=(0,4,0) ＋ **Capsule r=5 h=12 c=(0,12,0)**
- [9] `PP_Tree_02 4`：Capsule r=0.8 h=8 c=(0,4,0) ＋ **Capsule r=4 h=10 c=(0.63,9,0.43)**
- [10] `PP_Tree_10 2`：Capsule r=0.8 h=8 c=(0,4,0) ＋ **Capsule r=3 h=10 c=(0.63,7,0.43)**
- 石块侧同样带碰撞体：[0] `Rock1LOD_grup1`(Box 1.88×1.09×1.57 + 3 Sphere)、[1] `Rock1LOD_grup2`(4 Sphere)、[3] `RockLod1C`(Box 1.67×1.01×1.96)、[4] `RockLOD1E`(Box 1.45×0.78×1.02)、[5] `RockLOD4B`(Box 2.19×1.62×2.26)、[6] `RockLOD6C`(Box 3.15×1.55×2.30)；[2] `Rock1LOD_grup3` 无碰撞体
- ⚠ 命名带" 2"/" 4"后缀 = 复制出来的 prefab；按 pack 原路径 `Assets/Pure Poly/Free Low Poly Nature Pack/Prefabs/PP_Birch_Tree_06.prefab` 已找不到文件（可能被移走/删除），**"大碰撞体是套餐自带还是后加"未能确认**
- ⚠ 一旦开启树碰撞体：这些 r=2~5、高 7~12m 的"树冠碰撞体"会变成**半空中半径 2~5m 的隐形墙**（还要乘树实例的 widthScale/heightScale 0.7~1.5）；且开关是全局的，**0-6 石块会一起变实心**

### 4. 当前（开关关闭时）能撞到的"空气墙"清单
| 层 | Collider 数 | 内容 |
| --- | --- | --- |
| Default(0) | 285 | `OilPlane(Clone)` / `Turret_Mission_Machine(Clone)` 等建筑的**隐形碰撞代理**：`PlaneA1/B1/C1/D/E/F`（薄板 2.6~6.9m）、`Spine2`（r=2.3 h=10 胶囊）、`StairsA1..C2`（4~5m 方块）、`GunArmor/BodyArmor`、3 个 trigger 盒子 |
| Ground(3) | 19 | 地形 + **6 个无渲染器阻挡体**（属 `EntityRoot`：`KeyScreen` 终端 + 2 个无名 `GameObject` 箱，6.19×1.63×3.40 与 5.98×1.63×6.62，位于 (207,7,279)/(208,7,267) 与 (220,7,143)/(230,7,136)） |
| AirWall(13) | 18 | **正好等于 `MapRoot.CreatAirWall()` 的墙数**（360/20=18）→ 地图边界空气墙，运行时才创建 |
| Unit(6) | 135 | 单位/玩家 |

- `MoveableLayers` 含 Default + Ground + Unit + AirWall → 上表四类**都会挡玩家**
- "找不到是什么东西的碰撞体"的机制原因：① 地形树碰撞体**不是 GameObject**（Physics Debug 才能看/选）② airWall 是运行时创建 ③ 建筑隐形代理**没有 Renderer**，场景视图点不中 → 只能靠 Physics Debug 或按名字在 Hierarchy 搜（`PlaneF`/`Spine2`/`StairsC2`/`KeyScreen`/`airWall`）

### 4.5 【落地】细节（草/花）擦除：`08Map/TerrainDetailEraser.cs`
需求：爆炸弹坑与 `ModifyTerrain` 都要清掉范围内的细节（草），避免"地形被挖/被替换后草悬空"。

- 新文件 `Assets/Scripts/08Map/TerrainDetailEraser.cs`（`FpsGame.MapUtils`，与 TreeDestructor 同 asmdef）：
  - `[AddComponentMenu("地形/细节擦除", 41)]`，静态 `Instance`/`ClearedCells`，`Rebuild(Terrain)` 由 `GenerateNoiseTerrain` 生成后自动 AddComponent（与 `TreeDestructor.Rebuild` 并排）
  - 静态 API：`ClearInRadius(center, radius)`（圆）/ `ClearInRectXZ(center, halfSize)`（矩形，给附加地形用）；入队 + `LateUpdate` 合并提交，`_maxCommitPerSecond = 8`（草是纯视觉，限流给得比树的 4 高）
  - 实现要点：世界 → 细节格坐标时 **Terrain.transform.position 是角点**（`(world - origin) * detailWidth / size.x`）；圆形请求在 patch 内用**格中心反算世界坐标**做距离判定（坑边自然）；**只对非零格写回**，`changed == 0` 就不调 `SetDetailLayer`（避免无谓重建 patch）；逐层 `GetDetailLayer(xBase,yBase,w,h,layer)` → 清零 → `SetDetailLayer(...)`，rect 先 `Mathf.Clamp` 到 `detailWidth/detailHeight` 内
  - 地形来源：`TerrainUtils.Main`（`00Tools/Test/TerrainMainUtils.cs` 里的 `public static Terrain Main`）优先，回退 `Terrain.activeTerrain`
- 接入三处：`00Tools/FpsHelper.cs` 的 `destructe > 0` 分支（与树同半径）、`Scripts/Effect/ModifyTerrain.cs` 弹坑循环（`data.outerRadius`）、`ModifyTerrain` 附加地形（与树的 `ClearInRectXZ` 同矩形）
- 注意：草的擦除不影响碰撞/寻路（Details 本来就没碰撞体）；换局 `SpawnDetails` 会重写所有 detail 层，草自动恢复
- 验证：4 个文件 `read_lints` 0 诊断（**未编译**——用户当时在 Play 模式，不宜用桥强制 `refresh_unity` 打断；等其退出 Play 自行编译）
