## 【功能】`DeployableMine` 加"爆炸延迟 + 触发爆炸的 UnityEvent"（编译 0 error）
文件 `Assets/Scripts/02Game/Gameplay/Projectile/DeployableMine.cs`（`Mine.prefab` / `RobotMine.prefab` / `spore.prefab` 三个用）。改动：
- 新字段（`[Header("爆炸")]`）：`ExplosionDelay`（默认 0=触发即爆，保持旧 prefab 行为）、`OnTriggered`（「触发爆炸时」）、`OnExploded`（「爆炸时」），都带 `[InspectorName]`/`[Tooltip]`。
- 触发链路收敛到**幂等的** `public void TriggerExplosion()`（外部/其它物体的 UnityEvent 也能直接调）：`m_Exploded || _triggered` 早退 → `OnTriggered?.Invoke()` → `ExplosionDelay > 0` 时 `StartCoroutine(DelayExplode())`（`WaitForSeconds`，对齐 `SympatheticDetonation` 的"殉爆延时"写法）否则同帧 `DoExplosion()`。
- 原私有 `Explosion(GameObject)` 拆成 `OnHealthDie(GameObject)`（→ `TriggerExplosion`）+ `DoExplosion()`（结算伤害 → `OnExploded?.Invoke()` → `VFXManager.Release`）。**`OnExploded` 刻意放在 Release 之前**，监听者还能拿到存活物体。
- `TryHit()` 命中后 `m_health.Kill();` **再补一发** `TriggerExplosion();`：`Health.Kill()` 在 `m_IsDead` 已为 true 时不会派发 `OnDie`（`Health.cs:297-319`），只靠订阅会漏引爆（幂等，不会重复伤害）。
- 池化安全：`OnEnable`/`SetOwner` 复位 `_triggered`/`m_Exploded`；`OnDisable` 里 `StopExplodeRoutine()`。
- `OnLifeEnd()`（`LimitedLife` 到寿）：已触发 → 停协程并**立即引爆**（避免"响过却没炸"，也因为 `LimitedLife.EndDelay` 默认为 0、到寿随即回池会杀掉延迟协程）；未触发 → 原样 `Tool.Destroy`。
- 命名：新序列化字段跟随本文件既有风格（`ExplosionDelay` PascalCase），新增运行时状态用 `_triggered`/`_explodeRoutine`；原有 `m_*` 字段未动。
- 兼容性核查：全仓无 C# 代码按类型引用 `DeployableMine`；三个使用它的 prefab 都没有 `m_MethodName: Explosion` 之类的序列化回调 → 拆方法/改名安全；新字段在 prefab YAML 里缺行时 Unity 保留 C# 初始化器值（`ExplosionDelay=0` = 仍旧"触发即爆"），无需批量改 prefab。
- 未做（用户没要求，留作可选项）：延迟期间被摧毁是否提前引爆 —— 现在是"触发后不可打断"，只有 `LimitedLife` 到寿会提前炸。
