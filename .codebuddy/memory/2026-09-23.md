## 咨询：Unity 能否用脚本注入 Terrain 树与细节
- 结论：能，且是官方运行时 API。项目已有完整落地实现，可作为范式参考。
- 树的 API：`TerrainData.treePrototypes`（原型，可脚本赋值）/ `treeInstances` / `SetTreeInstance(i)`（单实例，**不可改 position/prototypeIndex**）/ `SetTreeInstances(arr, snapToGround)`（整表，可改一切）；**无 `RemoveTreeInstance`** → 删除只能整表重写（项目用"scale 置 0"隐藏，索引不变以便 `RestoreAll`）；`TreeInstance.position` 是**归一化 0~1**，`rotation` 是 X-Z 弧度。
- 细节的 API：`detailPrototypes` / `detailResolution`(+) / `GetDetailLayer` / `SetDetailLayer`（每次一层）/ `RefreshPrototypes`。
- 项目实现位置（证据）：
  - 生成：`Assets/Scripts/08Map/GenerateNoiseTerrain.cs` `SpawnVegetation`(≈1455-1480 构造 `TreeInstance`，逐格概率+坡度/高度约束) → `SetTreeInstances(trees.ToArray(), true)`(:814)；`SpawnDetails`(≈1500) 逐层 `SetDetailLayer`(:1572)。
  - 运行时改树：`08Map/TreeDestructor.cs` `SetTreeInstances(_instances, false)`(:565/:620)。
  - 运行时改细节：`08Map/TerrainDetailEraser.cs` `GetDetailLayer`(:207)→清零→`SetDetailLayer`(:233)，入队+按帧合并(限流 8/s)。
- 关键坑（项目已踩，写进 MEMORY.md）：① `SetTreeInstances` 后**树碰撞体不更新**，必须 `TerrainUtils.RebuildTreeColliders(terrain)`（切 enabled，约 10.75ms）；② 原型索引必须已存在于 TerrainData（0-6 石块 / 7-10 树）；③ 性能：`SetTreeInstances(3650)`=0.08ms 但碰撞体重建 10.75ms，细节逐层提交慢 → 必须按帧合并限流。

## 追问澄清：把 List<GameObject> 塞进"Terrain 树的层"
- 用户真实意图 = 用一组 GameObject（20 个）当 Terrain 的 TreePrototype（树原型）。
- **可以**，但原型是 **prefab asset**、且 prefab **必须带 `LODGroup`** 才会被地形渲染；场景实例不能直接当原型。
- 赋值方式（`treePrototypes` 是 struct 数组，getter 返回副本 → 必须整体赋回）：
  `var protos = new TreePrototype[n]; protos[i] = new TreePrototype{prefab=go, bendFactor=0f}; data.treePrototypes = protos;` → 再 `SetTreeInstances` 用 `prototypeIndex` 引用。
- ⚠ 关键区别：**地形树不是 GameObject 实例** —— prefab 上的 MonoBehaviour 完全不执行、没有对象生命周期，只有 LODGroup 的 mesh 被按实例矩阵绘制；碰撞体只认 CapsuleCollider。
- ⇒ 若要"物体真存在、跑脚本/可交互/可摧毁"，正确做法是 `Instantiate`（项目先例 `GenerateNoiseTerrain.PlaceRockCovers`：注释明写"预制体不是地形树"、Instantiate + `SetLayerRecursively` 到地面层 + `RockCoverDestructor.Register` 占地圆互斥）。
- 项目现状：全仓**没有**脚本给 `treePrototypes`/`detailPrototypes` 赋值的代码，原型都在 TerrainData 资产里预配。
- 追加确认：`TerrainData.treePrototypes` / `detailPrototypes` 都是 **public get/set**，脚本可直接赋值（非只读）；改完建议调 `terrainData.RefreshPrototypes()` 并重写 `treeInstances`（旧 prototypeIndex 会错位）；编辑器下改资产需 `EditorUtility.SetDirty`+`SaveAssets` 持久化；本 API 项目内**未实测**，属 Unity 官方文档结论。

## 树原型没有 LODGroup 会怎样（查证 2022.3 官方手册，2026-09-23）
- 官方定性：LODGroup **不是"必须"**，而是 Terrain 引擎**区分树类型的唯一判据** —— 根节点**有** LODGroup → 判为 **SpeedTree 树**（走自身 LODGroup）；**无** → 判为 **Tree Editor 树**（走 Terrain 内置"2D billboard ↔ 3D 模型"过渡带）。
- 但"Tree Editor 树"有一整套硬性配套要求，缺一即"渲染不正确"：① 必须用 `Nature/Soft Occlusion Leaves` + `Nature/Soft Occlusion Bark` 两个 shader ② 资产必须放在名为 `Ambient-Occlusion` 的文件夹里 ③ 每个 mesh 恰好两个材质（树体+叶子）④ 锚点在树根部 ⑤ billboard 不接收局部光（点光/聚光），仅方向光且随相机旋转才更新光照 ⑥ 只有这类树有 Bend Factor。
- ⇒ 对本项目（URP14 + 自定义 FBX + `ToonLit_*` shader）**完全不满足**上述配套 → 无 LODGroup 的树原型基本=**不渲染**（静默跳过/警告），不会崩溃、不会显示方块。编辑器 Paint Trees 里加无 LODGroup 的 prefab 通常被提示/拒绝。
- ⚠⚠ 最危险的副作用：**树碰撞体链路不看 LODGroup**（来自原型 prefab 的 CapsuleCollider + `TerrainCollider.m_EnableTreeColliders`）→ 很可能出现"看不见的树 + 隐形胶囊墙"，正是本项目历史踩过的坑。另外 `treeInstances` 数据照常占内存、照常参与整表提交与 `TreeDestructor` 销毁逻辑。
- 正解：给 prefab 加 `LODGroup`，把子 MeshRenderer 拖进 LOD0（只有一级也够）。项目现有原型 `PP_Tree_*`（4 棵）/`Rock1LOD_grup*`（7 个）/`RockLOD*` 实测**全部带 LODGroup**（`Assets/Art/Nature/` 下匹配 13 个 prefab）。
- 参考：`docs.unity3d.com/2022.3/.../terrain-Trees.html`；`TreePrototype.prefab` 脚本文档**未提** LODGroup（只有一句描述），别拿它当依据。
