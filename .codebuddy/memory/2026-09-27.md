## 排查：积雪能覆盖地形的树、覆盖不到地形细节（草/花/荆棘）
用户问题：`Assets/Scripts/Rendering/SnowRendererFeature.cs` 的积雪能影响地形上的树，但影响不了地形细节（草）。

核查到的事实：
- 雪 Feature 是"重画一遍"模式：`SnowRenderPass.Execute` 用 `context.DrawRenderers(cullResults, DrawingSettings{overrideMaterial=雪材质}, FilteringSettings(RenderQueueRange.all, snowLayerMask))`。
- URP renderer 资产 `Assets/Setting/New Universal Render Pipeline Asset_Renderer.asset`：`snowEntries[0]` mask=65(=Default 层0 + Unit 层6)→`SnowOverlay_Unit.mat`；`snowEntries[1]` mask=8(=Ground 层3)→`SnowOverlay_Ground.mat`；`renderPassEvent: 300`。
- `ProjectSettings/TagManager.asset` 层表：0 Default / 3 Ground / 6 Unit。
- `Assets/Scene/TestScene.unity`：Terrain 物体 `m_Layer: 3`（Ground）→ 落在 entry[1]，所以地形本体有雪。
- `Assets/Pandazole_Ultimate_Pack/.../Tree/Prefabs/Polar/Tree_23_Spring.prefab`：`m_Layer: 3`（Ground）→ 地形树实例同样落在 entry[1] ⇒ 树有雪。
- 地形细节（草/花/荆棘）是 `Assets/Pandazole_Ultimate_Pack/Pandazole Nature Environment Pack/Details/Prefabs/*.prefab`（47 个，`m_Layer: 0`/Default，共用材质 `PandaMat2.mat` = `ToonLit/ToonLit_Scene`），它们没有实例 GameObject/Renderer，由 Terrain 按 `TerrainData.detailPrototypes`+每层密度图（本项目 `useInstancing=true`）内部绘制，不进 SRP 渲染器列表 → `overrideMaterial` 与 layerMask 都够不到。

结论：雪 pass 只作用于"进 culling 结果渲染器列表且层掩码命中的 Renderer"；草原型层是 Default（entry[0] 的 mask 65 本来就含 Default），若它在列表里早就被画成雪了 —— 反证它不在列表里，改 mask 也没用。

给用户的方案（未实施，等确认）：
- A（推荐）：在草材质/Shader 侧加雪 —— 把 `Assets/Shader/Feature/SnowOverlay.shader` 的"朝上程度 × 噪声阈值 × `_GlobalSnowAmount` × 遮罩"抽成 include，按 `ToonLit_Stone.shader` 的 `#define` 先例（宏只写目标 shader 自己的 HLSLINCLUDE/pass，`ToonLit_Shared.hlsl` 里只新增 `#ifdef` 块）在 `ToonLit_Scene` 的 ForwardLit 里把 `GetFinalBaseColor` 结果 lerp 向雪色；⚠ 草走 GPU 实例化，`SnowOverlay.shader` 没有 `#pragma multi_compile_instancing`/`UNITY_SETUP_INSTANCE_ID`（全仓 ToonLit 都没有），要加；`PandaMat2` 被 47 个细节 prefab 共用，注意别把雪加到其它用该材质的物体上。
- B（零 shader）：下雪时按层 `SetDetailLayer` 清草、化雪前 `GetDetailLayer` 缓存回填（可复用 `08Map/TerrainDetailEraser.cs` 的限流批量清零）。

验证手段建议：把 entry[1] 的雪材质临时换成不透明纯红 shader，一眼看出该 pass 到底重画了哪些几何；或用 Frame Debugger 看 "Draw Snow Overlay" 事件下的 draw call。

## 方案 A 落地：草（地形细节）在自己 shader 里叠雪

## ModifyTerrain 支持矩形（`ShapeType.Rectangle` 一直没生效）

1. `ModifyTerrain` 第 48 行**硬编码** `ShapeType.Circle`，`ModifyTerrainData.shape` 字段从没被用过；
2. `TerrainUtils.ModifyHeightMap` 的守卫是 `shape != Circle && shape != Ellipse` → **Rectangle/Prismatic 直接进错误分支、什么都不做**（原来连 `yield break` 都没有，只打 error）。
   另外原实现里 `ShapeType.Ellipse` 的公式是 `max(|dx|,|dy|)*2*invRadius` = **切比雪夫距离 = 正方形**（名字骗人），真正用它的调用方目前为 0。

改动（2 个文件，编译已验证）：
- `Assets/Scripts/00Tools/Test/TerrainMainUtils.cs`
  - 新增公开 API `ModifyHeightMapRect(Vector3 pos, float innerRadius, Vector2 halfSize, float depth, bool isSet, bool refresh)`；原 `ModifyHeightMap(Vector3, …, float outerRadius, …)` 签名不变，内部改为转发 `new Vector2(outerRadius, outerRadius)`。
  - 核心 `ModifyHeightMap(Vector2 uv, float baseHeight, float innerRadius, **Vector2 halfSize**, float depth, ShapeType, bool, bool)`（原来第 4 参是 `float outerRadius`，无外部调用方）；守卫加 `Rectangle`，并且**补了 `yield break`**。

  - `normalizedDistance` 新增 `Rectangle => Mathf.Max(|dx|/(float)outerRadiusRes, |dy|/(float)outerRadiusZRes)`（**必须转 float**，`WRToHR` 返回 int，否则整数除法）；`innerScale` 矩形按 `innerRadius / Max(halfX, halfZ)`。

### 补记 2：矩形的淡化改成显式「内框 / 外框」（22:20~22:25）

- `TerrainMainUtils.cs`

### 补记 5（09-28 凌晨）："矩形切割不对"其实不是矩形的问题（AbandonedCampsiteB 环形沟）
用户报"切出来的矩形不对"，想要"一条四边连起来的壕沟"。目标 prefab = **`Assets/Resources/Prefabs/InterestPoint/AbandonedCampsiteB.prefab`**（transform 在 (280.1, 15, 466.8)、无旋转无缩放），5 个条目：
| # | 形状 | localPos | 内外半径 | rectHalfSize(外框) | rectInnerHalfSize(内框) | depth |
|---|---|---|---|---|---|---|
| 0 | Circle | (0,0) | 12 / 20 | 残留 **(1.3, 8.5)**（被忽略） | 残留 **(1, 8)** | **0** |
| 1,2 | Rectangle | (0,±10) | 1 / 2 | (11.5, 1.3) → 23×2.6 | (11, 1) → 22×2 | 1 |
| 3,4 | Rectangle | (±10,0) | 1 / 2 | (1.3, 8.5) → 2.6×17 | (1, 8) → 2×16 | 1 |

- **结论 1：4 个矩形条目切割是对的**。用真实 `TerrainUtils.RectFalloffPower`（反射调用）按 0.5m 网格算出落地范围 = **闭合的方形环沟**（外 ~23×23、沟宽 ~2.5m、`power` 全为 1 ⇒ 整深 1m）。四角只有 0.2m 的缝（横条 z∈[8.7,11.3]，竖条 z∈[-8.5,8.5]）——想让四角严丝合缝，把竖条的 `rectHalfSize.z` 从 8.5 提到 ≥11.3（建议 11.5）。
- **结论 2：真正破坏观感的是 `#0` 圆形条目**：`isSet=true` 时 `centerHeight = 中心旧高 - depth`，**`depth = 0` 并不是"不改高度"**，而是把 `heights=Lerp(旧高, 中心旧高, power)` ⇒ **r≤12 的圆盘被整体拉平到中心高度**、12→20 线性过渡；同时 `ClearInRadius(20-5=15)` 把范围内的草/石/树清光 ⇒ "一大块又平又秃的地"（用户图 1 里那块被当"切出来的矩形"看的大平台）。环沟正好嵌在这块平地上。
- **结论 3：`transitionDistance = 5` 对细条等于"不清地表物"**：清除半尺寸 = `外框半长 - 5` = (11.5-5, 1.3-5) = (6.5, **-3.7**) → `TreeDestructor.QueueInRectXZ` 直接 `return 0`（`halfSize<=0` no-op）⇒ 4 条沟范围内的树/石/草**一律没清** ⇒ 沟挖 1m 后它们悬空/半埋（就是记忆里那个"167 处悬空"）。它也是 **prefab 级唯一值**、圆条目还要靠它（20-5=15），细条沟建议单独降到 0.5。
- **附带发现**：`#0` 上残留 `rectHalfSize/rectInnerHalfSize` 非 0（形状=圆时被忽略，而且被 `[Compare]` 藏起来看不见）→ 属于"切形状时留下的幽灵值"，容易以后切回矩形踩雷，建议置 0。
- 验证手段：`AssetDatabase.LoadAssetAtPath<GameObject>(prefab)` + `GetComponent("ModifyTerrain")` + `SerializedObject` 读 `datas`，然后用**反射调用真实的** `TerrainUtils.RectFalloffPower` 在网格上画 ASCII 落地图（第一次画图网格以原点为中心、而 prefab 在世界 (280,466) → 全空，改用 `localPos` 相对坐标才对）。

### 补记 6（09-28）：矩形跟随物体世界 Y 旋转（"位置不对"的真正原因）
用户发图："`AbandonedCampsiteB.prefab` 实际的位置不对，可能和物体的世界旋转有关吗" —— **猜对了**。
- 根因：`ModifyTerrain` 的矩形分支只把中心交给 `transform.TransformPoint(data.localPos)`（中心跟着实例旋转 ✓），但**矩形本身当初只做世界 XZ 轴对齐**的判定 ⇒ 4 条带子"中心转了、方向没转" ⇒ 拧成**风车**（每条都轴对齐、四角错位），与用户截图完全一致。兴趣点/任务点实例运行时会被**随机 Y 旋转**（这就是为什么在 Prefab Mode 里看 gizmo（实例旋转 0）是正环、实机是风车）。
- 改动：
  - `TerrainMainUtils.ModifyHeightMapRect` 新增 `float angleDeg = 0f`（第 5 参，位于 `depth` 后）；核心 `ModifyHeightMap`(uv) 与 `ModifyAlphaMap` 也各加一个 `float angleDeg = 0f`（尾部默认参数 ⇒ 旧调用零影响）。
  - 旋转实现：`rotateRect = shape==Rectangle && !Approximately(angleDeg,0)`；预计算 `cosA/sinA`；每个像素把世界偏移旋进本地：`lx = px*cosA - pz*sinA; lz = px*sinA + pz*cosA`（`px,pz = 像素相对中心`），随后 `normalizedDistance`（矩形取 `max(|lx|/ox, |lz|/oz)`）与 `RectFalloffPower(lx, lz, …)` 都用本地坐标 ⇒ 圆/椭圆路径零变化。
  - 补丁半径：**仅旋转时**改用外接圆半径 `sqrt(ox²+oz²)`（否则转 45° 会露角），轴对齐时仍是 `max(ox,oz)` ⇒ 存量轴对齐行为逐字节不变。
  - `ModifyTerrain` 传 `transform.eulerAngles.y`；Gizmo 的 `DrawRect` 改用**物体自己的 `transform.right/forward`** 画四角（与切割同步转）。
- 验证（MCP）：内联式 vs `Quaternion.Inverse(Quaternion.Euler(0,a,0)) * offset` 在 a=30/90/137/-25 上最大误差 **9.5e-7** ⇒ 方向约定正确；ASCII 拼图对比：修复前 = 4 条轴对齐带子在旋转后的中心 → 风车，修复后 = 整体旋转 30° 的**闭合方环**。`validate_script` 0 诊断、dll 已更新、Console 仅 1 条与本改动无关的 `Import Error Code:(4)`。
- ⚠ **遗留**：`TerrainClearer.ClearInRectXZ` 及三个消费者（`TreeDestructor`/`TerrainDetailEraser`/`RockCoverDestructor`）**仍只支持轴对齐矩形**（`TerrainDetailEraser` 的矩形路径甚至是"直接清整个 AABB"、连矩形判定都没有）。对细条沟现在无感（`transitionDistance=5` 让清除范围算成负数 → no-op），但一旦把 transition 调小、物体又带 Y 旋转，清掉的区域就和沟对不上，需要后续给这条链加 `angleDeg`。
