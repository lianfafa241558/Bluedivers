## `terrainData.heightmapResolution` 翻倍的代价（实测）
用户问："我把 terrainData.heightmapResolution ×2 对性能有很大影响吗"。
来源确认：`BattleManager.InitTerrain`（`01Manager/Battle/BattleManager.cs:208-217`）`mapRes = SizeType.Large ? 1024 : 512` → `heightmapResolution = mapRes + 1`（1025）、`alphamapResolution = mapRes`（1024）
⇒ **当前 `heightmapResolution-1 == alphamapResolution` 1:1**（这是下面那条单位 bug 一直没暴露的原因）。

MCP 实测（临时 TerrainData，`size=(640,96,640)`，同世界半径 20m 的 patch，8 次取平均）：

| heightmapResolution | TerrainData 内存 | 整张高度图初始化 + Sync | 20m patch | patch 格数 | GetHeights | SetHeights+SyncHeightmap |
|---|---|---|---|---|---|---|
| 1025（网格 1024²） | 2.1 MB | 417 ms | 64×64 | 4,096 | 0.02 ms | **5.96 ms** |
| 2049（网格 2048²） | 8.3 MB | **4631 ms（×11）** | 128×128 | 16,384（×4） | 0.04 ms | **23.63 ms（×4）** |

结论：
- **内存 ×4**（N² 线性）；**每个弹坑 / 每个 `ModifyTerrain` 条目的"写 + SyncHeightmap" ×4**（≈6ms → ≈24ms，爆炸时会明显掉帧）。
- **整张高度图写入 + Sync 是 ×11（超线性）** —— 这一步直接加在**开局生成地形**上（`GenerateNoiseTerrain` 是分块提交高度图，与我这次测的写入口径相同），是翻倍最痛的地方。
- 同量级增长的还有：`Terrain.Flush()`（实测 0.69ms @1025，O(N²)）、`UpdateNavMesh`（实测 5.6~8.8ms，体素化受分辨率影响）、TerrainCollider 的三角形数（物理查询/内存）、`RebuildTreeColliders`（它重建的是整个地形碰撞体）。
- **不受影响**：树实例、细节（草）层（各自独立分辨率：`detailResolution=512`）、地形渲染的 draw call（顶点自适应 LOD）、以及地形形状 —— `GenerateNoiseTerrain.mapscale = heightmapResolution / size.x` 只用在 `TerrainPosToWorldPos`，所有换算都按分辨率自适应，噪声频率不变。

## 新增：踩踏/冲撞持续伤害（`TrampleEffect`）

需求：踩踏/冲撞持续造成伤害；**不要爆炸伤害**，而是对范围内**任意单位逐个**造成**动能**伤害；排除自己；0.5s 一跳；允许重复结算；可选击退；复用 `SustainedDamageData`。

### 为什么不能直接复用 `SustainedEffect`
- `SustainedDamageData` 明确"不做直击伤害"（`GetDirectDamage()==0`、`DamageGroupDirect` 恒空），prefab 里默认成分是 `{Explosion,1}+{Destruction,1}`；`SustainedEffect.ApplyEffect()` 只构造 `collider=null` 的 `ProjectileHitData` 丢给 `FpsHelper.Hit` ⇒ 走**爆炸分支**：`isDirect=false` ⇒ 吃 `ExplosionResistance` + 做 `ExplosionBlocking` 遮挡射线；范围选定用 `TargetCfg=new()`（`targetType=All`，友军也吃，仅友伤减伤）。
- **"非爆炸伤害"的正确姿势（`Damageable.InflictDamage`）**：`packet.isDirect=true` ⇒ `hitExplosionResistance=1`，完全绕开爆炸抗性/遮挡；`DamageGroups={Gun,1}` 就是动能（`DamageTypeEnum.Gun`=动能，`ResCfg.cs:122`）；仍按 `AP` 走护甲/穿甲；同队时自动 50% 友伤减伤。
- `FpsHelper.Hit` 的**直击分支只处理单个 collider**，天然无法"对范围内多个目标逐个结算"。

## 追查：击退"填 10000 只飞几米" → 重做为真·受力模型

### 根因（旧 `IPhysical.ApplyForce`）
- `BaseSelfMoveableController.ApplyForce` 先把入参当速度：`ApplyForceVelocity += vector / Weight`，**再硬钳到 `MaxSpeedInAir*3`**（默认 6*3 = **18**）⇒ 填 10000 与填 20 无区别（`Min(10000,18)=18`）。
- 该速度再按 `Vector3.Lerp(v,0,decay*dt)` 衰减（`decay = 接地?3:1`），逐帧 ×dt 积分 ⇒ **位移 ≈ v₀/decay**：接地 18/3 ≈ **6 米**、空中 18/1 ≈ 18 米。这就是"几米"。
- 旁证：`FpsHelper` 爆炸冲击波原本就用 `... * 10`，即该接口的常规量级是"十几"，10000 属量纲用错。
- ⚠ 另一坑：**全项目只有 `BaseSelfMoveableController` 实现 `IPhysical`** ⇒ 敌人 AI 单位 `TryGetComponent<IPhysical>` 直接失败，**对敌人完全不能击退**。

### 改法（已落地）
1. `00Core/Interfaces/CoreInterfaces.cs`：`IPhysical` 新增 **`void ApplyImpulse(PEVector3 impulse)`**；`ApplyForce` 语义明确为"持续力(牛顿)，逐帧施加、由实现方积分"。
2. `BaseSelfMoveableController`：
   - 新增 `private PEVector3 m_PendingForce`（本帧累积的持续力）+ `GroundDrag = 3f` / `AirDrag = 1f`（Inspector 可调）；
   - `ApplyForce(force) => m_PendingForce += force;`，在 `HandleCharacterMovement` 里积分：`ApplyForceVelocity += m_PendingForce / max(Weight,0.1) * Time.deltaTime`（**Δv = (F/m)·dt**，随即清空）；
   - `ApplyImpulse(impulse) => ApplyForceVelocity += impulse / max(Weight,0.1)`（**Δv = J/m，无上限**）；
   - 衰减由 `Lerp(v,0,k·dt)` 换成真正的指数阻尼 `v *= Mathf.Exp(-drag·dt)`（`IsGrounded ? GroundDrag : AirDrag`），数值与旧的 3/1 基本一致；
   - **删除了 `MaxSpeedInAir*3` 硬上限**与那个 `if (vector.Magnitude > Weight)` 门槛。
3. 两个既有调用点改为冲量语义：`FpsHelper` 爆炸冲击波 `ApplyForce(vector)` → `ApplyImpulse(vector)`（向量仍是 `... * 10`，10 < 旧上限 18 ⇒ **行为不变**）；`TrampleEffect` 的击退 → `ApplyImpulse`（`KnockbackForce` 现在是**冲量**：Δv = 冲量/重量）。
- 新的可预期手感：**接地位移 ≈ 冲量/3 米、空中 ≈ 冲量/1 米**（重量=1 时）。要更远就调大冲量或调小 `GroundDrag`。
- ⚠ 无上限后大冲量可以把玩家打飞天（由 CharacterController 负责不穿墙）；需要兜底可再加一个可选 `MaxForceVelocity` 安全钳。

### 实现要点
- `ApplyImpulse` → `_knockbackVelocity += 冲量 / max(_knockbackWeight,0.1)`；`ApplyForce` → 累积 `_pendingForce`，逐帧 `Δv=(F/m)·dt`。

- 早退：`!FpsHelper.HaveNavMeshAgent(NavMeshAgent)`（未启用/不在 NavMesh 上）⇒ 清空受力；敌人死亡时 `_OnDie` 会 `NavMeshAgent.enabled=false` ⇒ **死后不再受力**。

### 推挤期间暂停寻路重算（本次需求）
- 内建 `NavMeshAgent.autoRepath` 走"偏离路径就自动重算"，**不经过项目的 `PathRequestManager`**（后者只管 `SetDestination` 那条线，带去重/失败重试/限流）⇒ 一次踩踏同帧推飞多个 `autoRepath=1` 的单位会触发多次内部重算尖峰。
- 实现：`_pauseAutoRepathWhileKnocked`（默认 true）→ `PauseAutoRepath()` 在**有受力速度时**把 `autoRepath` 置 false 并**记录原值**，速度归零/agent 失效时 `ResumeAutoRepath()` **还原原值**。
  - ⚠ **必须还原成"原值"而不是硬写 `true`**：查 prefab 得知 `GuardTower_Fusillade/Grenade`、`Enemy_Build_Factory` 的 `m_AutoRepath: 0`，硬写 true 会改掉它们的配置。
  - ⚠ `OnDisable` 必须兜底 `ResumeAutoRepath()` + 清空受力：否则带着"重算已暂停"被回收/池化复用会让单位**再也不自动找路**。
- prefab 事实：绝大多数移动敌人 `m_AutoRepath: 1`（`Dec_Stalker.prefab:269`、`Dec_Ultralisk.prefab:1201`、`Droid_SMG`、`Goliath`…），固定炮台为 0。
- 目标点不受影响：`Move` 不碰 `destination`/`m_lastDestination`（`SetNavDestination` 的 `<1m` 去重键）/`PathRequestManager.active` ⇒ **AI 的"想去哪"不变，只有路径折线可能在恢复重算后变**。
- 追加开关 `_knockbackImmune`（Inspector「完全不受力」，默认 false）：`ApplyForce`/`ApplyImpulse` 直接忽略；`UpdateKnockback` 开头也拦一道并 `ResumeAutoRepath()`（防止推挤途中才勾上时残留受力/重算被停）。

## 追查：巡逻队"站在原地发呆"（MCP 实测定因）

用户问：`PatrolContriller` 刷出来的单位**有时**原地发呆，有 `PatrolPos` 但 NavMeshAgent 没在走；**被打一下就会正常追玩家**。

## "枪声警告（BulletHit）没触发" 排查（2026-09-28 晚）

**问题**：`FpsHelper.cs:268-274`（`//警告` 段，条件 `BattleManager.IsValid() && soundRadius>0` → `BattleEventSub.BulletHit(soure,(PEVector3)point,soundRadius)`）在"子弹落在单位旁边"时，看 `DetectionModule.cs:465-478` 的 `BulletHit` 没反应。

**实测（MCP `execute_code` + 运行时反射，Play 中，DLL 16:38 新编）**
1. `PEMaths` 量纲确认：`PEVector3.Distance((0,0,0),(3,4,0)).RawFloat=5`、`(PEInt)20.RawInt=20`、`RawFloat==RawInt` ⇒ PEInt/PEVector3 就是**米**，(473) 行 `Distance - rauids < HearingRange` 表达式**没问题**（1.5m 时 `1.5-20<25` 为 true）。

3. 队伍：`ActorsManager.Player` = `Player(Clone)`、**team=0、该物体上有 `Actor`**；敌人 team=2 ⇒ 队伍判定通过。
4. 玩家武器 `WeaponPlayerController.Owner` = `Player(Clone)`（= 根物体，有 `Actor`）、`DamageData.SoundRadius=20` ⇒ `soure`/`soundRadius>0` 两个前置**都满足**。
5. **受控实验**：对某个单位手动 `BattleEventSub.BulletHit(player, 单位+1.5m, 20)` → 该单位 `BewarePoint` 立刻被写上 ⇒ **465-478 确实会执行**；且扫描时本来就有 **7 个单位的 `BewarePoint != null`**（全场唯一写点就是 `BulletHit`）⇒ 真实子弹路径**已经触发过**。

**结论（真正原因）**：`DetectionModule.BulletHit` 只是 `Beware(pos,false)` → 只写 `BewarePoint`（非序列化、非 `[DisplayField]`、无 Gizmo ⇒ Inspector 完全看不到）。而 `BewarePoint` 在 AI 侧只有 **`EnemyMobile.OnLostTarget()`（588-593，要求 `AiState==Follow||Attack`）** 会消费；`UpdateAiStateTransitions`（403-465）的 switch **只有 Beware/Return/Follow/Attack 四个 case，没有 Idle/Patrol 分支** ⇒ 站着没锁过目标的单位听到枪声只会记下点，**既不切状态也不移动**，看起来就是"没触发警告"。

**可选修法（未落地，需用户定）**：在 `UpdateAiStateTransitions` 给 `case AIState.Idle` / `case AIState.Patrol` 加 `if (DetectionModule.BewarePoint.HasValue) SwitchState(AIState.Beware);`（注意 `IsFixed` 固定炮台要不要跟去、以及 `BewareReachRadius/BewareStayDuration` 的节奏）。

**副产品**：`git grep` 把 `Assets/Scripts/02Game/Util/WindowStateController.cs` 当二进制跳过；`Select-String`/文件搜索**找不到** `PlayerWnd.BulletHit`（运行时反射显示它确实存在，签名为 `(GameObject, PEVector3, PEInt)`）⇒ 文本搜索结论必须用运行时反射复核。
