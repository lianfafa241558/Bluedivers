## 答疑：`UnitSkill_ShieldRestore` 为何不继承 `UnitSkill_Base`
- 结论：不是漏写，是**契约不匹配**。`UnitSkill_Base : TickBehaviour` 是"AI 战斗技能"框架 —— `Start` 是 `sealed` 且当场 `GetComponent<EnemyController>()` 并订阅其 `OnDetectedTarget/OnLostTarget/OnDie`（无 EC 直接 NRE），还强制 `Cool/Duration/releaseType/接战时间/Range/tag` + `CanExecute()→SkillStart/SkillTick/SkillEnd` 的 1s 状态机。
- `UnitSkill_ShieldRestore` 是**纯事件驱动 + 协程延时**：订阅 `Damageable.OnDestroyPart`（护盾/发射器肢体），`WaitForSeconds(restoreDelay)` 后 `shield.RestoreArmor()`；无目标、无冷却、无需 tick。硬套基类要 override 掉整个 `Tick` 并空转 `SkillStart`，得不偿失 → 作者写成独立 `MonoBehaviour`。
- 证据（重要，避免误判）：
  - 同目录 6 个 `UnitSkill_*` 全继承基类，只有它不继承：`search "class UnitSkill_"` → Charge/OrbitArmor/CallReinforcement/Blink/Summoner/Taunt。
  - 它的唯一挂载点：`Assets/Resources/Prefabs/Enemy/Zerg/DEC/Dec_Colossus Boss.prefab`（`shield`=fileID 8360213434925449639、`emitter`=7030608752648199200、`restoreDelay: 15`，同物体还挂着 `UnitSkill_OrbitArmor`）。
  - 该物体（prefab variant 里 stripped 的 `6783624127424309880`）源对象是 `Dec_Colossus.prefab` 的 `3494390850417595609` = 净化者本体根，**上面确实有 `EnemyController`（guid `3de939d976a5bb0419ccd8dbd0b6836b`）** ⇒ "继承会 NRE"在本 prefab 上不成立，真正理由只是契约不匹配。
- 新增方法论：查"某脚本有没有被用/被谁用"要拿 `.cs.meta` 的 **guid 全文搜**；搜类名会误命中 prefab 里的同名字段（如 `Player.prefab` 的 `ShieldRestore:` 是 AudioClip 字段）。

## 改造：`Assets/Shader/Texture2.shader` 加 ToonLit 同款溶解
- 需求：把 `ToonLit.shader:63-68` 的溶解属性 + `ToonLit_Shared.hlsl`/`ToonLit_LightingEquation.hlsl` 的溶解算法搬进 `LX/Texture2`。
- 实现（全部落在 `Texture2.shader` 单文件）：
  - Properties 加 `[Toggle(_UseAlphaClipping)]`/`[Toggle(_UseAlphaUV)]`/`_AlphaMap`/`_DissolveValue`(Color)/`_EdgeWidth`/`[HDR]_EdgeColor`；`#pragma shader_feature_local` 两个 Toggle。
  - CBUFFER 加 `_AlphaMap`/`_AlphaMap_ST`/`half3 _DissolveValue`/`half _EdgeWidth`/`half3 _EdgeColor`。
  - 复制 `vertexToHalf2Method1(worldPos)`（伪三平面 UV）+ `GetDissolveMask()`；v2f 新增 `float3 dissolveWS : TEXCOORD5`，vert 里 `#if _UseAlphaClipping` 填 `posInputs.positionWS`。
  - frag 在基础色相乘之后：`dissolve=_DissolveValue.r*1.2-0.1`、`v=GetDissolveMask(i)`、`clip(step(dissolve,v)-dissolve+_EdgeWidth)`、边缘 `lerp(col, _EdgeColor*lerp(dis+_EdgeWidth,dis,v), 1-step(dis+_EdgeWidth,v))`。
  - 与 ToonLit 唯一有意的差异：**不覆盖 `col.a`**（本 shader 是 Blend 透明特效，保留原 alpha 混合；溶解靠 `clip` 裁切）。
- 踩坑（已修，已写进 MEMORY.md「Shader 坑」）：一开始同时写了 `#pragma shader_feature_local _UseAlphaClipping` 与 CBUFFER 里的 `float _UseAlphaClipping;` → `redefinition of '_UseAlphaClipping'`。**Toggle 关键字不能与同名 uniform 并存**。ToonLit 之所以能在 CBUFFER 声明同名字段，是因为它的 `#pragma shader_feature ..._UseAlphaClipping` 被注释掉了（改用运行时 `if`）。本 shader 改成纯关键字 `#if` 路线（与文件既有 `_UseFresnel`/`_Transpose` 一致），删掉 CBUFFER 里的两个 float。
- 验证：MCP（钉 `Bluedivers@3d9f2357`）`execute_code` 里 `AssetDatabase.ImportAsset("Assets/Shader/Texture2.shader", ForceUpdate)` → `isSupported=True`，`read_console(filter "Texture2")` 0 条 error/warning。

## 设计讨论：ArtifactPlane 的护盾"换成独立单位"行不行
- 用户觉得现状设计别扭，问根因 + 能否把护盾做成独立单位。
- **根因**：项目里"能被打的东西"只有一种合法身份 = **Actor 的肢体/护甲**。① 直击路径虽只查 `I_Damagable`，但 `Damageable.InflictDamage` 首行 `if (!Health) return;` 把门槛转移到 Health；② 范围/爆炸必须先 `FindUnits` → `I_Actor.Damageables`（`Actor.Awake` 只收 `GetComponentsInChildren<Damageable>()`）。⇒ **"无 Actor 也能被战斗系统正常打"的路径不存在**。`ArtifactPlane` 是纯布景（无 AI/队/移动），硬要护盾可打就只能伪造单位身份 → 别扭感来源。附加错位：`UnitSkill_` 命名/菜单（实际是肢体级被动）、`armorValue=0`+`armorBreakEffect=[]`（空壳）。
- **结论：能，且零代码改动**（系统本就是围绕 Actor 设计的）。两个方案，判据是"本体要不要也能被打":
  - A 护盾自己当单位：`Magic shield` 上挂 `Actor + Health`，`UnitSkill_ShieldRestore` 保持不动。
  - B（推荐，与 `Dec_Colossus` 净化者同范式）：`ArtifactPlane` 本体当 `Actor+Health`，护盾作为它的护甲肢体（`armorValue>0` + `armorBreakEffect`），技能放本体上。
- **`type` 选择**（`TargetCfg.EnemyAI = All & ~Other`，`UnitQueryGrid.cs:276`）：`Other` → AI 不打、不吃 `HitAreaKinetic`、爆炸能打（`FpsHelper.Hit` 爆炸用默认 `new TargetCfg()`=All）、小地图不显示（用 `TargetCfg.Enemy`）；`SpecUnit` → AI 会打；`Enemy` → 小地图+任务计数也会受它影响。`Other` 还要不勾 `AutoRegister` 才不触发单位创建事件。
- **必须一起配**（否则从"打不动"变"掉地上/空引用"）：① **勾 `AllowFloating`**（`Actor.WaitSetPos` 会 `NavMesh.SamplePosition(…,100,…)` 吸附到地面，ArtifactPlane 在 y≈27 空中）；② **Actor 与 Health 同物体**；③ 填 `aimPoint`（`HpPos => AimPoint.position` 无判空，`UseHpBar` 默认 true）；④ `shape`/`rangeLength`(≈2.5)/`halfHeight`（网格注册与查询用 `range.Overlaps(unit.Range)`）；⑤ `team`；⑥ `armorValue>0` + `armorBreakEffect`；⑦ `Health` 具体子类 + `MainPart` 填护盾 Damageable。
- 依赖链（网格注册）：`Actor.Awake`/`WaitSetPos` → `BattleEventSub.UnitPosChange` → `BattleManager.OnUnitPosChange`（`Type != None` 才更新）→ `UnitQueryGrid.UpdateNodes`→`AddUnit`；查询在 `QueryUnits` 里再筛 `IsValidMono && ActorState.HasFlag && range.Overlaps(unit.Range) && customFilter`。

## 修：ShieldRebuild 复活后 ActorState 仍 Dead + 隐藏护盾需要延迟字段
- 报障：时间到了护盾重现但单位状态还是 dead；且隐藏护盾需要 float 延时字段控制动画表现。
- **根因1（判死取值器用错）**：`Rebuild()` 里写的是 `if (_health.GetHpMax() <= 0) _health.Revive();` —— `GetHpMax()` 返回 `MaxHealth`（恒 > 0）⇒ **`Revive()` 永不执行** ⇒ 护盾被 `SetActive(true)` 了但 `ActorState` 一直 Dead（`FindUnits` 按 `ActorState.HasFlag(Normal)` 过滤 ⇒ 从此打不到/AI 不理）。改成 **`GetHpCurrent() <= 0`**（死时 CurrentHealth 被 `HandleDeath` 归 0）。
- **需求2（延迟收起）**：新增 `[SerializeField] float _hideDelay`（InspectorName「隐藏延时」，0=立即收起），并把"收起"拆成两个入口：
  - `HideVisual()`：**只** `SetActive(false)`，不碰计时 —— 延迟收起走它（`Invoke(nameof(HideVisual), _hideDelay)`），否则会把待重塑也 `CancelInvoke` 掉（我自己第一版就踩了这个）；
  - `HideShield()`（public，外部总开关/卸下/发射器被毁）：先 `CancelInvoke(HideVisual)`+`CancelInvoke(Rebuild)` 再收起；
  - `Rebuild()` 时刻 = `Invoke(Rebuild, Mathf.Max(_rebuildDelay, _hideDelay))`，即两个计时都从击毁时刻起算，配置反了也不会"刚重塑又被隐藏"。
- 附带加固：`ResolveHealth()`（`_healthGo` → 自身 → `GetComponentInChildren<IHealth>(true)`），修掉 `_healthGo` 未配时 `_healthGo.GetComponent<IHealth>()` 直接 NRE 的隐患（旧 `_health`/`_healthGo` 改名后三个 prefab 都重配过，但兜底更稳）。
- 验证：`refresh_unity(force)` 后 0 error；MCP 查三个 prefab：`ArtifactPlane`（宿主=自身、`_healthGo`=自身、`_shieldVisual`=Sphere、rebuild=15）、`ShieldBag`（`_healthGo`=Sphere、rebuild=10）、`Dec_Colossus Boss`（宿主=根、`_healthGo`=`Colossus_Shield`、`_shieldVisual`=`Colossus_Shield`、`emitter`=shield、rebuild=15）；`_hideDelay` 三处都为 0（保持原行为）。`Colossus_Shield` 现已自成单位：`Transform ParticleSystemRenderer ParticleSystem SphereCollider IgnoreHitDetection AudioSource Damageable Actor HealthShield`。
