## CountDownWnd 归零不关闭（bug 修复）+ activeBelow 可随 StartDown 传入

- **归零不消失的根因**（`10UI/Wnd/CountDownWnd.cs` `Update`）：原判据是 `if (nowcd != countDown) { if (countDown == 0) SetWndState(false); else { countDown = nowcd; ApplyValue(nowcd); } }`。
  `countDown` 在上一步刚被赋成 provider 读数 ⇒ 归零那一帧走 else 只刷出 `00:00`，之后 `nowcd == countDown` 恒真，窗口永不消失。改为：`if (nowcd == countDown) return; countDown = nowcd; if (nowcd <= 0) { Stop(); SetWndState(false); return; } ApplyValue(nowcd);`
- **activeBelow 传参链路**（阈值 ≥1 覆盖 Inspector 的 16，≤0 沿用序列化值）：
  `CountDownWnd.StartDown(provider, type, int activeBelow = -1)` → `WndHub` 里 `WindowRegistry.CreatCountDown` 的 lambda → `WindowRegistry.CreatCountDown: Action<Func<int>, CountDownTypeEnum, int>` + `CountDown(provider, type, activeBelow = -1)` → `WndManager.CreatCountDown(func, type, activeBelow = -1)`。
  `StartDown` 内同时 `countDown = this.activeBelow`，避免首帧把残留值误判成跳变（否则会先闪一次）。
  **现有两处调用点（TaskManager:399、DeathUI:74）未改**（仍走 Inspector 值），需要时补第 3 个实参即可。
- 验证：`plans/offline_compile.py 01_GameContract 09_Managers 10_UI` → 总错误 0。补丁脚本 `plans/patch_countdown_wnd.py`（字节级、带锚点断言、幂等可重跑）。

## InformationItem.prefab 中段文字被挤（UI 布局修复，2026-10-03）

- 需求：`Assets/Resources/UI/Information/InformationItem.prefab` 中间的 Text 想自适应宽度，实际被挤/折行。
- 结构：root(InformationItem, Image 占位 sprite=null + LayoutElement MinHeight44) → Image(FX_TEX_Lock 九宫格, 锚拉伸 sizeDelta 4, **HorizontalLayoutGroup** cW=True/cH=False/feW=False) → 左 grad1 条 + Text(TMP) + 右 grad1 条(scale -1,-1)。
- **根因（MCP 实测，非推理）**：两条装饰条是 `Simple` 类型 + grad1(512px) ⇒ `Image` 作为 ILayoutElement 报 **preferredWidth=512/条**（用 sprite 像素宽，**不吃 PixelsPerUnitMultiplier**），文本 TMP prefW=192 ⇒ 总 preferred=1216，而可用宽只有 652=root648+4。UGUI 空间不足时**按 preferred 等比压缩全部子物体**，实测系数 652/1216=0.536 ⇒ 文本只拿 192×0.536≈**103**（折行），装饰条各 274.5。
- 修复：两条装饰的 `LayoutElement.PreferredWidth: -1 → 0`（flexibleWidth 保持 1）。**关键机制：LayoutElement 的 layoutPriority=1 > Image 的 0，高优先级直接覆盖低优先级的值**，所以能把 Image 的 512 压掉。修复后实测 648 宽下 = 230/192/230 ✓；文本更长时先吃装饰余量，超过总宽才折行。
- 手法：用 `execute_code` + `PrefabUtility.InstantiatePrefab(asset, EditorSceneManager.NewPreviewScene())` + 手动 `hg.CalculateLayoutInput*()/SetLayoutHorizontal()` 量化布局（**不会弄脏用户场景**）；落盘用 `AssetDatabase.LoadAssetAtPath`(同一内存实例，避免 LoadPrefabContents 覆盖未保存的 Inspector 改动) + `SaveAssetIfDirty` + `ImportAsset(ForceUpdate)`。
- ⚠ 遗留/待确认：该 prefab 目前**全仓无引用**（无脚本/场景/prefab 用它）；root 上那个 `Image`(sprite=null, 色 0.5/0.25/0.25) 是占位；若用户想要的是"整条背景随文字变宽"，需结构改动（背景 Image 上移到 root + HLG padding 2/2 + ContentSizeFitter H=PreferredSize），已告知待其拍板。
