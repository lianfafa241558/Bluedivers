## 修复：子弹/命中两端不一致（"B 打中、A 看不见命中"）

用户报：B 端瞄敌人本地命中，A 端看到没命中，导致同步出错。

### 真因（两条，都在"命中"这条链上；子弹表现是另一条线）

1. **`EnemyNetBridge.OnRemoteHit` 是"静默结算"**：`DamageSource = null; NoSource = true` ⇒ 房主侧那只怪
   **只是默默掉血** —— 不播受击特效、不刷新血条、不给仇恨 ⇒ 房主屏幕上"像没打中"。
   （`EnemyController._OnDamaged` 里那两段表现/统计都挂在 `damageSource != null` 上。）
2. **房主打出的伤害从不下发**：命中同步只有 **成员 → 房主**（`EnemyHitMsg` 4025），
   房主自己那一枪没有任何下行 ⇒ 两侧副本血量各算各的（A 那边怪快死了、B 这边血条还是满的）。

### 落地（6 文件，口径：血量统一"房主权威"，双向都走）

## 修复：`HealthEnemy` 难度缩放只缩了上限、没写回当前血（血超上限的真因）

- 真因（`05UnitCore/Health/HealthEnemy.cs:46` 原样）：`MaxHealth = showHealth = (CurrentHealth * scale).RawInt;`
  —— **只赋值 `MaxHealth`/`showHealth`，`CurrentHealth` 没写回** ⚠；而它的 `base.Awake()`（`Health.cs:143`）刚做过
  `CurrentHealth = showHealth = MaxHealth`（= 预制体上的**未缩放**基础值）⇒ 血停在未缩放值、上限缩放了。
- 表现：系数 <1 的档（Normal 0.5 / Hard 0.6 / VeryHard 0.7 / **HardCode 0.85**）⇒ **血 > 上限**；
  系数 >1 的档（Insane 1.15 / Torment 1.2 / Lunatic 1.35）⇒ **出生不满血**（血=基础值、上限更高）；
  只有 Extreme(1.0) 不多不少 ⇒ 所以平时不易察觉。
- 数字铁证（用户日志 3 条比率全是 **0.8496094** = `(PEInt)0.85f` ⇒ **确认是 HardCode**，用户记忆正确）：
  200×0.8496094=169（日志 200/169）、70×=59（日志 70/59）、1000×=849（日志 452.125/849）；
  78 个含 `HealthEnemy` 的预制体基础值里正好有 200×4 / 70×6 / 1000×8。
- 修（对齐 `Damageable.cs:148-150` 护甲的 `remainArmor = maxArmor = armorValue * scale` 口径）：
  ```csharp
  PEInt scaled = CurrentHealth * scale;
  MaxHealth = showHealth = scaled.RawInt;
  CurrentHealth = MaxHealth;      // 缩放后满血出生
  ```
- 验证：离线 `05_UnitCore/01_GameContract` **0 error**；Unity 编译（`05_UnitCore.dll` → 00:28:09）；数字对账见上。
- ⚠ 副作用（有益）：Insane 及以上档位的敌人**以前出生就不是满血**（血=基础值、上限更大）⇒ 这次一并修好。
