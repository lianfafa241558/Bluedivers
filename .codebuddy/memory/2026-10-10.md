## 🎯 「疯狂断开」诊断：幽灵会话复发（ep 分支未被去重）

> 用户报"控制台疯狂断开"。用 MCP 实时取数（编辑器当时是**房主**、Play 中、场景 `Utnapishitim`）。

### 实测数据（权威，直接读运行中的对象）

- `NetHostSvc.Instance.RoomInfo != null` ⇒ **本编辑器是房主**；`_players = [3366740185]`（只有一个玩家，稳定）。
- `KCPNet<HostSession,NetMessage>`：`GetSessionCount()=2`、`sessionDic.Count=2`、`sidToKey.Count=2`、`clientKeyDic.Count=2`：
  | key | sid | 性质 |
  | --- | --- | --- |
  | `cid:36c2a6d2bbab494cab0c0bf6a77b1761` | `3366740185` | **真玩家**（在 `_players` 里） |
  | `ep:192.168.1.4:64156` | `3120579841` | **幽灵**（从未入房） |
- 两条会话的 `m_remotePoint` **完全相同** = `192.168.1.4:64156`。
- `Get-NetUDPEndpoint -LocalPort 64156` **本机无命中** ⇒ 对端是**另一台机器**（不是本机自连）。
- 断开速率：`HostSession` 的**静态**计数 `s_disconnectCount` 两次相邻输出为 614 → 663（相隔 ≤10s，节流是"≤1 行/10s"）⇒ **≈5 次/秒**；日志里 sid 在 `3120579841` / `2140566683` 之间交替（同一对端）。

### 机理（IL 反汇编 `KCPNet<T,K>.BuildIdentityKey`，token 0x06000012）

```
if (!string.IsNullOrEmpty(clientId)) return "cid:" + clientId;
return "ep:" + EndpointKey(endPoint);
```
⇒ `ep:` 键意味着**那批握手没带 clientId**（走了"老客户端兼容"回退分支）；`cid:` 那条是稳定的、就是入房的玩家。

### 结论

- **不是玩家在掉线**：真玩家会话（`cid:`）稳定、`_players` 只有一个。
- 刷屏来自**同一条 socket 上不带 clientId 的握手**：库为 `ep:` 键**反复"新建会话 → 关掉旧的"**（sid 在固定集合里循环），每次关都触发一次 `HostSession.OnDisConnected`。
- 这正是 **2026-10-09 已定性过的库侧缺陷**（当时记录：同一对端 socket 反复「接入→断开→接入」、sid 循环、只靠库超时回收；sid 集合 `2140566683/3120579841` 本次复现）。
- ⇒ 新库的 `clientId` 去重**只治了"玩家那条"**，`ep:` 回退分支仍是"新建+断开"，没做幂等复用。

### 待确认 / 下一步

1. ⏳ **对端 `192.168.1.4` 跑的是哪个包**（有没有带 `NetClient` 里那两行 `ClientId`）—— 这决定是"老包兼容分支"还是"库内部重试不带 clientId"。
2. 若对端已是新包 ⇒ 交库作者修：`ep:` 分支也要"已存在即复用/替换"，且**未完成握手的会话要能被及时回收**。
3. 我们侧只做**降噪**（如 `HostSession` 断开日志改成"每 sid 只报一次 + 定期汇总"），**不动库**。
4. 需要盯的连带风险：若库把报文归到幽灵会话，会出现 `NetHostSvc` 的"收到消息但找不到玩家（忽略）"；本次未见。

### 归属结论（用户追问"是 KCPNet 的问题还是什么"）

- **主责 = KCPNet 库**：`clientId` 去重**只在"带 clientId"的那条上生效**；**不带 clientId 的握手走 `ep:` 回退分支时不做幂等复用**（每次"新建 sid + 关旧 sid"）⇒ 每秒约 5 次 `OnDisConnected`。库的会话表没泄漏（`clientKeyDic` 只有 2 条），但**行为不收敛**。
- **我们侧无责**：当时我们是房主，自己的 `NetClient` 全程 `IsConnected=false`、`KCPNet=null`；`ClientId` 两行是**修好玩家会话**的原因。
- **触发源未钉死**：谁在反复发"不带 clientId 的握手"（对端老包 / 库自身握手重试 / KCP 分包）—— 需要 Play 中逐秒采样 `sidToKey` 看 `cid:` 是否也在换。
- 已把机理 + 给库作者的三条诉求写进 `topics/net.md`（2026-10-10 那条 ⭐⭐）。

- **轴 2：伤害归属 —— 不是"客机等房主算"**（这条推翻了猜测，已核实 `EnemyController.cs:355-370`）：
  · `bool toNetwork = !ApplyingRemoteDamage && netId != 0 && dmg > 0;` + 日志 `本地命中结算 … (上报房主 / 下发给成员 / **不往网络走**)`；
