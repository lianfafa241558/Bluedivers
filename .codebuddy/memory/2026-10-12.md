## 咨询（用户提问，只读调研，未改代码）：P2P 是不是只能局域网

- 结论：**不是**。"只能局域网"来自「发现层 = UDP 广播」，不是 P2P 本身。三层定位：发现（`LanBroadcaster`/`LanDiscoverer`，255.255.255.255:29800，只在本广播域 ⇒ **唯一硬限制**）/ 建连（`NetClient.ConnectToRoom(room)` 只读 `room.HostIp`+`room.HostPort`，`StartAsClient` 公网可用，**若无 NAT 可零改动直连**）/ 传输（KCP over UDP，公网本就可用）。
- ⇒ **换发现层即可上公网**：`LanRoomInfo.FromJson` 是公开静态方法，可从一台 HTTP/WS 房间列表服务构造房间对象，`NetSvc/NetRoomFlow/NetClient` 一行不用改；真正的新工作量在**NAT 穿透**（STUN 拿映射 + 信令交换 + 互发打洞；对称 NAT 失败要中继 = 02_Net 加第三种传输实现）。
- 给用户的分档：①虚拟局域网（ZeroTier/Tailscale 等，0 成本 0 改动，当下就能用）②公网 IP / IPv6 直连 ③自建信令（1C1G 轻量服务器）+ 打洞（+ 中继兜底）④Steam/EOS 免费 P2P 与中继（需把传输层抽象成接口后换实现）⑤现成中继 SDK（与 KCPNet 冲突，不推荐）。用户未拍板走哪条。
- 相关现实约束（已提醒）：房主上行即全房天花板；无 host migration（`net-flow.md §6`），公网掉线率高于局域网；中继兜底才有 100% 连通性但要烧带宽。
