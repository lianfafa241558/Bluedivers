## 咨询：让网友提前内测，是否必须用内网穿透（只读调研，未改代码）

- **核心结论**：不是必须；而且**常用的免费"内网穿透"（ngrok / 花生壳 / cpolar 免费版）对本项目基本无效** —— 它们只转发 TCP，而联机层是 **UDP**（KCP 主通道 17666/udp + 发现 29800/udp 广播）。自建方案里只有 **frp** 能做 UDP（`type = udp`），但需要一台公网服务器，而且**广播包转不了** ⇒ 玩家只能用刚做好的「手动直连」。
- **推荐次序**：① **虚拟局域网**（ZeroTier / Radmin VPN / Hamachi / 蒲公英）—— 0 成本 0 代码，把对方直接当成同一局域网；⚠ ZeroTier 是 L2（广播**可能**可用，未实测），**Tailscale 是 L3/WireGuard、不转发 255.255.255.255 广播** ⇒ 必须走直连。② 房主有公网 IPv4（找运营商要）或双方有公网 IPv6 ⇒ 端口映射 + 直连，延迟最低。③ frp 中转（云服务器成本 + 流量/延迟吃亏）。④ Steam Playtest（免费 + Valve 中继，但要接 Steamworks SDK 并上架）。
- ⚠ **本项目该层的已知限制（未修）**：`NetHostSvc.StartHost` 固定 `StartAsServer("0.0.0.0", 17666)`（全网卡监听 ⇒ 虚拟网卡也能收，OK）；但 **`ServerListPanel.TryParseDirect` 不支持 IPv6** —— 它用 `s.LastIndexOf(':')` 切端口，`::1` 会被切成 ip=":" / port=1，`[::1]:17666` 虽切得对但 `IPAddress.TryParse("[::1]")` 会失败 ⇒ **走 IPv6 内测前必须先修**（识别方括号 / 多冒号时按括号切）。
- 顺手提议（未做）：房间列表面板显示"本机 IP"，方便房主把地址发给网友。
