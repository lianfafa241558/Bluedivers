## ✅ 落地：机甲"输入有但走不动"= 假空中 + 空中加速度 0（用户当场复现，已修）

### 实测签名（`MoveWatch`）
- `inp=(0.40,0.05,0.92)`（按键链路正常、非 0）、`game IsGrounded=False`、**`cc.isGrounded=True`**、`ccVel=(0,0,0)`、`flags=Below`、`0.4s 内水平位移 0.000m`、`gapToGround≈0.103`（正好 `skinWidth`）。
- 即 **Unity CC 说"贴在地上"，游戏自己的接地判定说"在空中"** ⇒ 每帧走 `AirMove()`。

### 根因（两个环节必须同时成立）
1. `GroundCheck` 的接地探测：**空中把距离压到 `k_GroundCheckDistanceInAir=0.07`（+0.05 = 0.12m）**，而 CC 天然离地一个 `skinWidth=0.1`（实测 0.103）⇒ **余量仅 1.7cm**；且探测只是**一条竖直线**（`GetCapsuleBottomHemisphere()`），CC 半径 1.3m 会"踩在半径内某凸起上、探测点下方低几厘米" ⇒ 整段漏掉 ⇒ `IsGrounded` 卡 false（平地无视觉障碍也复现）。
2. 机甲 prefab **`AccelerationSpeedInAir = 0`** ⇒ `AirMove()` 里 `accelerate = 0` ⇒ **"水平加速度"与"水平速度向 `MaxSpeedInAir` 收敛"同时失效**（`:597-609`）⇒ 空中零水平控制；`ApplyGravity()`（`:782-785`）无条件加重力 ⇒ `gameVel` 一直 -y 但被 CC 挡住 ⇒ 原地不动。玩家 `AccelerationSpeedInAir` 非 0 ⇒ 同样假空中也能走（与"玩家没事、只机甲卡"完全对应）。

### 修法（`06_Gameplay`，已编译）
- `chosenGroundCheckDistance` **不再分空中/接地**，统一 `Controller.skinWidth + GroundCheckDistance`；删除常量 `k_GroundCheckDistanceInAir`（留注释说明原值 0.07 的坑）。
- 新增**射线兜底**：当胶囊探测"一个候选都没有" + `Controller.isGrounded` + 已过跳跃保护期 ⇒ 从 `GetCapsuleBottomHemisphere()` 向下射线（`skinWidth + GroundCheckDistance + 0.15`），命中面朝上且不超 `slopeLimit` 才算接地（`hasGroundHit=true` 的陡坡分支不受影响 ⇒ 陡坡仍按原样滑落）。
  - 顺带把 `hit` 改名为 `groundHit`（`hit` 与外层 `NavMesh.SamplePosition(out var hit)` 重名 ⇒ CS0136），探测结果提到 `if` 外（CS0103）。
- 验证：`offline_compile 06_Gameplay` **0 error**；Unity 重编 `06_Gameplay.dll` mtime **00:53:49**；Console `types=[error]` **0 条**。⚠ 重编会退出 Play。
- **未做（备选兜底）**：机甲 prefab `AccelerationSpeedInAir` 0→2（用户可在 Inspector 自行改；根因已修，不再必需）。

## ✅✅ 真根因（第二次修）：`s_GroundHitBuffer` 被自身碰撞体吃满 ⇒ 地面命中被截断

- 用户反馈"修完还是这样：**走两步 → 进空中 → 滑一段 → 走不动**"。复算 `GroundCheck` 的那条 `CapsuleCastNonAlloc`：
  **19 条命中** —— `[0..16]` 共 **18 条 `self=True`、`dist=0.000`、`point=(0,0,0)`**（机甲自己的 `bone_*` / `Exo_Gatling|Fire` / `Back` / CC，因为探测胶囊半径 1.3 把整个机体套住了，全是"初始重叠"），**真正的地面 `EvacuationArea L3 dist=0.101 normal=(0,1,0)` 排在 `[17]`**。
- 而缓冲区是 **`static readonly RaycastHit[] s_GroundHitBuffer = new RaycastHit[16]`** ⇒ NonAlloc **按缓冲区长度截断** ⇒ 地面那条被丢掉 ⇒ `hasGroundHit=false` ⇒ `IsGrounded=false`（**PhysX 不保证顺序 ⇒ 时好时坏 = "走两步卡住"**；只有机甲中招，因为只有它的胶囊里塞着十几个自身碰撞体）。
- ⚠ **我上一轮加的"射线兜底"是错的、等于没写**：从 `GetCapsuleBottomHemisphere()`（离地还有一整个 `radius=1.3m`）只探 `skinWidth+GroundCheckDistance+0.15=0.35` ⇒ 复算输出 `no hit`，够不到地面。诊断探针要**验证它真的会触发**，别只看代码"看起来对"。
- **修法（`06_Gameplay`）**：① `s_GroundHitBuffer` 16 → **64**（真修复）；② `s_OverlapBuffer` 16 → **64**（同一截断坑，`IsPenetrating`/`HaveObstacle` 也用，机甲实测 14~18 命中已逼近上限）；③ 兜底改成**直接采纳 `Controller.isGrounded`**（只在"一个候选都没找到"时、且过跳跃保护期），并在注释里写死"别再改成从底部半球中心打短射线"。
- 验证：`offline_compile 06_Gameplay` **0 error**；Unity 重编 `06_Gameplay.dll` mtime **01:00:18**；Console `types=[error]` **0 条**；新代码已确认加载（复算探针里 `k_GroundCheckDistanceInAir` 字段已不存在 = False）。
- ⭐ **口径**：`Physics.*NonAlloc` 的缓冲区**必须按"目标自己会产生多少命中"来定**——带骨碰撞体的大单位（机甲 18 个）会先把缓冲占满；判"探测到底有没有生效"要**复算同一条查询并打印每条命中的 `self/isSelfChild/dist/point/normal`**。

## ✅✅✅ 真根因之三（"半悬空 + 卡在 Lamp / 平地走两步就停"）：CC 没忽略自身子碰撞体

- 现场（机甲 `Exosuit`，`pos.y≈19.0`，`Lamp` 就在 1.77m 外）：`game IsGrounded=False`、**`cc.isGrounded=True`**、`ccVel=(0,0,0)`、`flags=Below`、**`gameVel=(0,-42.93,0)` 且已累 126 秒**（`_lastGroundedTime` 落后 `Time.time` 126s）⇒ 一直走 `AirMove`；机甲 `AccelerationSpeedInAir=**0**` ⇒ 空中零水平控制、只剩惯性 = **走不动**（用户描述的"走两步→进空中→滑一段→走不动"完全对上）。
- 探测本身是**对的**：`WINNER=EvacuationArea dist=0.206 dotUp=0.999 angle=2.7 可走`，但 `needVerify=true` ⇒ 吸附验证要**向下 Move 0.186** ⇒ 实测 `Move` 连 1mm 都走不动 ⇒ 位移 0 ⇒ `snapGrounded=false` ⇒ 判不接地。
- ⭐⭐ **谁在挡：它自己的骨碰撞体**。`Physics.ComputePenetration(cc, 自子碰撞体)` ⇒ **12 个穿透**：`bone_Root(1.590) bone_Spine(1.482) Back(0.681) bone_Leg_L1/R1(0.322) … Exo_Fire(0.266)`；`最低自碰撞体 bone_Leg_L4.min.y=18.967 < ccBottomY=19.022` ⇒ **CC 一直"踩在自己腿上"**（`flags=Below`/`isGrounded` 是假象）= 玩家说的**半悬空**。Unity 的 CC **与同层级子碰撞体不默认互斥**（项目里全仓 `Physics.IgnoreCollision` 只有 RootMotion 插件用了一处）。
- **判据**：① `groundCheck` 有合格候选却 `snapGrounded=false`；② 脚下无外来碰撞体但 CC 沉不下去（`cc.isGrounded=True` + 离地 >skin）；③ `CharacterVelocity.y` 长期单调累积（-42.9）⇒ 就是"向下 Move 恒被挡"。现场验证：**加上 `IgnoreCollision` 后同一帧 `IsGrounded` 立即变 true、`gameVel.y` 从 -42.9 归零**。
- **修法（`06_Gameplay`）**：① `BaseSelfMoveableController` 新增 `IgnoreSelfCollisions()`（`GetComponentsInChildren(true, buffer)` 后逐个 `Physics.IgnoreCollision(cc, c, true)`，跳过触发器），`Awake` 调一次 + **在 `GroundCheck` 开头每 1 秒重刷**（⚠ `IgnoreCollision` 关系在碰撞体 enable/disable 后会失效，而运行时挂模型/换武器都会 toggle）；② `GroundCheck` 的兜底从"只在 `!hasGroundHit` 时生效"放宽为"**只要最终没判接地且不是陡坡**就采纳 `Controller.isGrounded`"（陡坡滑落行为不变）。
- ⚠⚠ **探针口径教训（很重要）**：**从 `EditorApplication.update` 里直接调 `cc.Move` 测"能不能动"是不可靠的** —— 实测请求 (0.01,0,0) 只走 0.00001，把机甲 20 个自碰撞体**全部 disable** 后依然是 0，可游戏里它明明在走 ⇒ 这类 Move 探针会给出"全方向被挡"的假象。要看"CC 到底动没动"只能看**游戏自己的状态**：`CharacterVelocity.y` 是否长期累积、`cc.isGrounded` 与离地距离、`IsGrounded` 与 `_lastGroundedTime` 落后多少秒。
- 顺带查明：小物件 `EntityRoot/StartPoint(Clone)/Lamp` = `BoxCollider` **layer 0(Default)**、`isTrigger=false`、**无 Rigidbody**，世界尺寸 1.17×0.90×1.17（离地 0~0.9m 的实心方块，localScale 0.3）；机甲 `stepOffset=1` > 0.68 ⇒ 本来就能跨上去，之前的"卡 Lamp"只是接地判定的连坐。若仍被它卡，选项：改 trigger / 换到不参与 CC 碰撞的层 / 抬 stepOffset。
