## "又出现一堆异常" 复盘（结论：一半是噪音放大，一半是真 bug）
- 🔴 **噪音放大的根因**：`NetIdProbe.Enabled` 被改成 `false`（05UnitCore/Actor/NetIdProbe.cs）。
  但它当时同时管三件事 ⇒ `Born/Dead/Died` 全早退、账本空 ⇒ `IsNormalMiss` 恒 false ⇒
  所有"打尸体 / 消息迟到"都被升级成 `Warn`（`远端死亡落地 找不到 netId=…`、`远端伤害落地 挂起重试`），
  同时 `netid_map_* / netid_probe_*` 全部停写（文件时间戳停在昨天）。
  **修**：`Enabled` 语义收窄为"只控制写盘 + 详细明细"；`Born/Dead/Died`、`IsNormalMiss` 不再看它；
  `Explain` 在关闭时仍返回结论字符串（不落盘、不记详细）。
  ⇒ 教训：**诊断开关不能同时承担"日志分级"的判定依据**，否则关掉开关等于把噪音全放出来。
- 🔴 **真 bug**：`[异常/生成/收·单位] … 复刻失败（生成器=CreatSmall）` + `CreatUnit: tier 'Small' 在当前模板配置中不存在，降级到默认 tier`。
  房主侧 `TakeTierUnit` 在 tier 缺失时**降级抽了别的 tier 的单位**，但 4052 里 `slot` 仍是 `(int)tier=1(Small)`
  ⇒ 成员侧 `FindTierPrefab(Small, "robot00")` 直接返回 null ⇒ 该怪在成员端**根本没建出来**，
  之后它的移动/伤害/死亡消息全部"找不到本端副本"（一长串 Warn 的源头之一）。
  **修**：`WaveManager.FindTierPrefab` —— tier 不在表里时**按 4052 里的 prefabId 全表找**（消息本来就带 prefabId）；
  全表也找不到才告警返回 null。
- 其余告警定性：`Failed to create agent because there is no valid NavMesh`（刷怪点不在 NavMesh 上，未处理）；
  `[TeamNetBridge] 本地任务表与房主不同…已按房主内容复现`（设计内）；`[异常/盟友自愈]`（自愈设计）。
- 编译：`05_UnitCore` + `09_Managers` 0 error。
- ⚠ `Enabled` 目前仍是 `false`（只停写盘）。要再抓 dump 就改回 `true`。

## 背包联机：远端重放装到盟友实例上的两个坑（Jetpack NRE / 别人 HUD 亮在我屏幕上）
- 共同根因：**同一件背包会在两端各有一份，且远端那份被 4036 重放装到盟友实例上**（`Furniture_Equip.Operate` → 盟友身上的 `EquipController`；`PlayerFriend.prefab` 确实带 `EquipController` + `PlayerMountPoint` + `HealthPlayer`，**没有** `Damageable`）。
  盟友实例没有 `PlayerController`/`PlayerInputHandler` ⇒ `BagBase.OnInstall` 取到两个 null（`BagBase.cs:75-76`）。
- 🔴 **喷气背包客机 NRE**：`Jetpack.Update` 首句就读 `m_PlayerCharacterController.IsGrounded`（`Jetpack.cs:64`）⇒ 客机上房主那件背包被装上来后每帧 NRE（`[0x00000]` 就是这一句）。
  **修**：`BagBase` 新增 `IsLocalDriver`（= PlayerController + PlayerInputHandler 都取到，`OnInstall` 置位、`OnUninstall` 复位）；
  `Jetpack.Update` / `BlinkBag.Update` 开头 `if (!IsLocalDriver) return;`（`WeaponBag` 早就用 `m_InputHandler != null` 挡过同一个坑）。
- 🔴 **护理包/火箭包 HUD 显示在错的一侧**：四件背包的预制体里各自嵌套一份 `Resources/UI/Vehicle/VehicleCanvas`（`VehicleUI`，`m_RenderMode: 0` = **ScreenSpaceOverlay**，`contGo` 指向背包自己）⇒ **谁的机器上这件背包对象被打了，谁的屏幕就亮**。
  房主打客机时：房主那份护盾罩自带 `Damageable`（`ShieldBag.prefab`），房主本地把伤害结算在**自己那份副本**上 ⇒ `Health.OnHit` → `ShieldBag.Hit` → `OnStateChange(true)` ⇒ 房主的 HUD 亮。
  **修**：`VehicleUI` 缓存 `_bag = controller as BagBase`，`StateChange` 里 `if (_bag != null && !_bag.IsLocalDriver) state = false;`（载具的 `VehicleWeaponsManager` 不受影响）。
- ⚠ 顺带查实（**未修、属既有缺口**）：玩家之间**没有任何伤害同步通道** —— `09Manager/07NetGame` 里只有 `EnemyNetBridge.ApplyRemoteDamage` 一处远端伤害落地；玩家血/盾是"各自机器本地权威 + 4017/4018 只为给别人看"（`topics/net-battle.md`）。
  ⇒ 房主打客机时**客机根本没掉血**（它自己那份护盾自然不亮），UI 修好后两侧都不亮才是与事实一致的表现。要做 PvP 伤害需另开"玩家受击"下行通道。
- 编译：离线 `06_Gameplay` + `10_UI` 0 error；`check_sources.py` 通过。
