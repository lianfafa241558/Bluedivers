## 新增：信号干扰 SignalJammer（战备禁用 + 信标落点作废）

- 新组件 `Assets/Scripts/06Gameplay/AI/Skill/SignalJammer.cs`，菜单 `[AddComponentMenu("单位/_技能/信号干扰", 30)]`，
  命名空间 `FPSGame.AI`（与其它 UnitSkill_* 同目录）。
- **不继承 `UnitSkill_Base`**：那套绑死 `EnemyController` 的目标/接战/冷却判定，而干扰是"宿主活着就一直生效"的区域光环。
  实现方式 = 静态注册表 `_active`（OnEnable 注册 / OnDisable 注销，池化与销毁都覆盖），对外两个静态查询：
  `IsBlocked(Vector3)` / `IsBlocked(IActor)`；宿主有 `Actor` 时按 `ActorState.Dead` 自动失效（不订阅死亡事件）。
- 三处联动：
  ① `AirdropController.IsJammed` 新属性（`SignalJammer.IsBlocked(Player)`）+ `Input()` 开头拦截（**必须挡在这里**，
     只虚化 UI 挡不住键盘输入）；`Open()` 不拦（能开面板看"受到干扰"）。
  ② `VFXAirdropEffect.SetOrigin`：落点被覆盖 ⇒ **必须在 `BattleEventBus.Airdrop` 之前**判（那个事件一抛 data 进 Arrive、
     4027/4028 也已经发出去了）⇒ `CancelAirdrop(origin,data)`（槽位退回 Ready、不扣次数）+ `RecycleSelf()`。
     `TmpAirdrop`（远端复现/任务脚本）同样拦一次，只 `RecycleSelf()`。
  ③ `AirdropWnd`：`jammed` 字段每帧取 `controller.IsJammed`；`UpdateExpand`/`UpdateShow`/`CheckInput` 三处优先判干扰，
     文本统一写"受到干扰"（展开面板每行都写；收起的 HUD 只亮第一条，其余渐出）。
- 已验证：`tmp_compile_newfile.py 06_Gameplay` 0 error；MCP `refresh_unity` 后 06_Gameplay / 09_Managers / 10_UI / 10_Effect
  四个 dll 全部重编（17:19:5x）、Console 无编译错误（仅两条与本次无关的 `CanvasController.Awake` NRE）。
- 未做（等需要再说）：干扰源的视觉表现（力场罩/VFX）、只干扰敌方的队伍过滤（当前"范围内一律干扰"）、
  干扰期间把已选待释放的信标强行取消（目前只在"抛出那一刻"判落点）。

## 补：信号干扰支持 `enabled = false`
- 用户口径：组件禁用也要失效。`_active` 本来靠 `OnEnable`/`OnDisable` 维护（组件 enabled 开关**也会**触发这两个回调），
  再在 `IsBlocked` 里显式加 `if (!jammer.isActiveAndEnabled) continue;` —— 判据只看运行时开关，注册表降级为加速索引。
