## 结论：网络 DTO 的**字段声明顺序无关**，只有 `[Key(n)]` 决定线格式
- `NetMsgCodec.BuildMembers`（`NetTmp/Services/NetMsgCodec.cs:232-234`）反射拿到 `[Key]` 成员后**按 Key 升序排序**，写/读都按这个数组（:106-115 / :154-171）⇒ 把 `PoseSnapshot` 里几行挪来挪去，字节流完全不变，两端天然兼容。
- 真正不能动的三件：**Key 数字**（= array 下标）、**Key 与类型配对**（同位置换类型会读出垃圾）、**新增字段只能占末尾 Key**（旧端靠 `count < members.Length` 补默认值，见 :169）。
- ⚠ `NetMsgCodec` **不校验** Key 的连续/唯一性（只排序）；一旦跳号或重复不会报错，只会静默换位置 ⇒ 别手动跳号。原生 `MessagePackSerializer` 的 int-key 模式反而要求 0..n-1 连续唯一（若哪天切回去会炸）。
- 规范上仍建议声明顺序 = Key 升序，纯为可读性（现在就是这样）。
