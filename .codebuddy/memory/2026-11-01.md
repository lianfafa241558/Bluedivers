## ✅ 新增武器属性「子弹配置序号」`WeaponAttrType.DamageIndex`（28，总是隐藏）
- 用途：一把枪配多条 `Damages`，模组把实际使用的配置换成第 N 条。`WeaponBaseController.cs:128` 的 `UseDamageIndex` 本来就是全链路唯一档位来源（子弹生成 `Shoot(this, UseDamageIndex, muzzle)`、`CurrentDamgeData`、联机开火包 `DamageIndex`），所以**没有新增运行时字段、没有新增网络字段**。
- 枚举/配置：`WeaponAttributeFactory.cs` —— `DamageIndex = 28`（空号；`_fakeAttrs` 按数值序列化，禁止插进已有号段）+ `{ DamageIndex, (false, OnlyInt | IsHide, ModifierType.All) }`（IsHide 由用户指定：参数面板永不显示）。
- 接线（`WeaponPlayerController.cs`）：`InitAttribute` 末尾 `if(!cfg[DamageIndex]) cfg.Add(DamageIndex, UseDamageIndex)` + 订阅 `OnDamageIndexChanged`；回调里 `Mathf.Clamp(value.RawInt, 0, Damages.Count-1)` 后改 `UseDamageIndex` 并 `RebaseDamageData()`；`UnInitAttribute` 整批退订。
- ⭐ **核心坑（本次一并修）**：`InitAttribute` / `UnInitAttribute` / `ApplyUpgrade` 原来全部把伤害类属性绑死在 `Damages[0]`。切到第 2 条后会出现"面板伤害按 0 号算、改装加成写进 0 号、2 号纹丝不动"。做法：
  1. 45 条 `Set(Attr.X, damages.SetY)` 改 `Set(Attr.X, (d, v) => d.SetY(v))`，handler 经 `CurrentDamgeData` 转发（脚本 `plans/patch_damage_index_binding.py`），delegate 存 `_damageSetters` 供退订；
  2. `Set` 里为每条 `Damages[i]` **备份原始值** `_damagePrimeBackup[attr][i]`（必须在任何写回之前读，否则备份到的是已被加成过的值，来回切模组越乘越高）；
  3. `GameAttribute` 新增 `baseSum`（ΣBase 单独记账）+ `Rebase(newPrime)`（`primeValue` 去掉 readonly，prime/base 一起换，Factor/Extra/ΣBase 保留），Rebase 内部的 Recalculate 会经 handler 把结果写回新配置；
  4. `InitAttribute` 里顺手 `UseDamageIndex = Clamp(...)`，防 prefab 手填错序号让 `CurrentDamgeData` 越界。
- ⚠ 信号枪（`FlareGun`）的 0/1 档位由 `PlayerWeaponsManager.OnInputCompletedAirdrop/OnCancelAirdrop/OnAirdrop` 运行时直接赋 `UseDamageIndex` ⇒ 这类武器别配该模组。远端表现 `FriendWeaponView.PlayVisual` / `NetVehicleBridge` 也是直接赋字段，所以 `UseDamageIndex` 不能改成只读属性。
- 数据侧用法：武器 prefab 配好 N 条 `Damages` → WMD 的 `modifys` 加 `type=子弹配置序号 / modifier=Base / value=2`（必须 Base 或 Extra，初值 0 时 Factor 恒 0）。
- 验证：`offline_compile 06_Gameplay 09_Managers 10_UI Assembly-CSharp-Editor` 全 0 error。

## ✅ `WeaponFuelCellHandler` 插值源：热量武器改用 HeatRatio
- 挂载：`Assets/Resources/Weapons/` 下 `Weapon_Blaster` / `Weapon_Launcher` / `Weapon_Shotgun`（**无 HeatPerShot**，纯弹匣武器，Magazine=16）+ `CWC`（**热量武器**：HeatPerShot 4.5 / CoolDelay .25 / CoolSpeed 100 / OverheatDuration 2 / Magazine 300 能量池 / Ammo 0 / WeaponFlag 0）。
- 结论：原逻辑 `m_Weapon.Magazine.ScaleValue` 是 FPS Sample 遗留，对三把老枪正确；对 CWC 错 —— 它的 Magazine 只是能量池，且 `WeaponFlag=0`（无 AutomaticReload）+ `Ammo=0` ⇒ `ReloadEnd` 没备弹直接 return，Magazine 只会单向归零，电池视觉与"过热→冷却"循环完全脱节。
- 改法：抽 `float GetRemainScale()` = `m_Weapon.HasHeatSystem ? 1f - m_Weapon.HeatRatio : m_Weapon.Magazine.ScaleValue.RawFloat`，两处 Lerp 都改用它（方向与弹匣版一致：消耗/发热 → 靠近 `FuelCellUsedPosition`）。老枪零变化。
- ⚠ CWC 数据疑点（未改）：`Ammo=0` 且非无限弹匣（300>0）⇒ 300 发打完后无法换弹。若它应该是"无限能量池"，把 `Magazine` 配成负数（`InfiniteMagazine` 判据）。
- 验证：`offline_compile 06_Gameplay` 0 error。

### 追加：电池弹出"一顿一顿" → 加指数阻尼
- 根因：热量是**离散跳变**（每发 `AddHeat(4.5)` = 4.5% 一档），`Update` 里直接把比例塞进 `Vector3.Lerp` ⇒ 每发跳一档；叠加散热阶段的"`CoolDelay` 0.25s 静止 + CoolSpeed 100/秒直线回落"，观感就是卡顿。旧版 Magazine 一档 1/16 也不平滑，只是不明显。
- 改法：新增 `SmoothSpeed`（默认 12，0 = 关）+ `m_DisplayedScale` 帧率无关阻尼 `Mathf.Lerp(cur, target, 1 - Mathf.Exp(-k*dt))`，首帧 `m_ScaleInited` 直接对齐（避免开场从默认值滑一段）。两个分支都用阻尼后的值。

## ✅ `WeaponUIComponent` 冷却条加平滑（2026-11-02）
- 只给 `I_CoolRatio`（图片填充）加了 `CoolRatioSmoothSpeed`（默认 12，0 = 旧行为）：热量武器一发 4.5% 的阶梯跳变经帧率无关阻尼 `1-e^(-k·dt)`；`_displayedHeat` **填充与取色共用**，否则出现"条子慢慢走、颜色已跳档"的错位；沿用 `_lastCoolRatio` 的 0.001 阈值，静止时不标脏 Canvas。
