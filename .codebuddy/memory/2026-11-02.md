## 坑：DayNightBrain.Update 每帧 250KB GC —— 天空盒材质「每帧重建 + 名字无限变长」

判定方法：MCP `execute_code` 反射取 `DayNightBrain._modules`，逐模块 `tick.Invoke` 夹 `GC.GetTotalMemory(false)` 差值 ⇒ 只有 `EnvironmentLightingModule.Tick` 分配，实测 262144 B/帧，其余 4 个模块 0 B。

根因在 `EnvironmentLightingModule.GetSkyboxForWrite()`（:339-359）的脏检查自成死循环：`source = RenderSettings.skybox`，而它上一帧刚把 `RenderSettings.skybox` 换成自己的副本，`_skyboxSourceAsset` 又被赋成**副本**（不是原资产）⇒ 下一帧 `_skyboxSourceAsset != source` 恒成立 ⇒ 每帧 `ReleaseSkyboxInstance()` + `new Material(source)` + `Destroy` + `name = source.name + " (Runtime)"`。

- 名字每帧 +10 字符（实测 `RenderSettings.skybox.name.Length` 64261 → 64281，两次 Tick），材质实例 ID 每帧都变。
- 每帧 GC ≈ `4 × name.Length` 字节（`Material.name` getter + 字符串拼接各分配一次全长字符串）⇒ 250KB 对应 L≈64000，即已跑约 6400 帧；**越玩越卡**是线性增长。
- 连带后果：`_skyboxSourceAsset` 指向已 Destroy 的副本，退出 Play 时还原不回原资产；`destroy 后 new` 每帧也白烧 0.64ms CPU + 一次 native 材质拷贝。
- 修法：脏检查改成 `if (_skyboxInstance != null && source == _skyboxInstance) return _skyboxInstance;`（副本已接管就直接复用），名字不要用 `source.name + 后缀` 递推。

### ⭐ 读 Profiler 的关键技巧：`GC.Alloc` 子行 = 分配次数 × 均摊字节

`LogicFrameHost.Update 19.5KB` 下挂 `GC.Alloc 1000 次 / 19.5KB` ⇒ 平均 **19.5B/次 = 装箱**；`Actor.Update` 261 次/16.3KB ⇒ 62B/次；`ProjectileStandard` 67 次/3.7KB ⇒ 56B/次。**看次数就能区分"一个大字符串"还是"上千次小装箱"**。

**装箱元凶（1000 次的来源）**：`GameAttribute.HasFlag(AttrTag) => tag.HasFlag(flag)`（`WeaponAttributeFactory.cs:586`），而 `FinalValue` 的 getter 每次都调 `HasFlag(AttrTag.OnlyInt)`、`GameCurrentAttribute.CurrValue` 的 setter 每次写都调 `tag.HasFlag(AttrTag.LimitCurr)` ⇒ **读/写一次武器属性就分配一次**。已改：`(tag & flag) == flag`、`(allowModifier & modifier) == modifier`、`(tag & AttrTag.LimitCurr) == AttrTag.LimitCurr`、`AttrInfo.HasFlag` 同改。
⚠ 位运算写法必须用 `(a & b) == b`，不能用 `!= 0`：对**组合掩码**（如 `ModifierType.All`）两者不等价。`WeaponController.HasFlag`、`Furniture_Attached.HaveFlag` 之前写成 `!= 0`，本轮已纠正为 `== flag`。
⚠ **`ActorState` 是普通枚举**（None=0/Normal=1/Dead=2/Hide=3），`Enum.HasFlag` 是位包含语义（Hide=3 会匹配 Normal/Dead），改成 `==` 会改行为 ⇒ `UnitQueryGrid` 里那处**故意没动**，属于待拍板的语义问题。

**地雷的 20 行 0.5KB 不是"每帧"**：同一批部署的雷相位相同 ⇒ 每 0.1s 在**同一帧**一起查网格（尖峰）。已按 `GetInstanceID() % 10` 把相位打散（`OnEnable`/`SetOrigin` 两处）。

### 四轮采样：122KB → 10.2KB/帧（收尾）

`BehaviourUpdate 9.5KB` = `Actor.Update` 5.1KB（211 次 × **24B**）+ `InterestPointUpdate` 3.1KB（19 次 × 163B）。

- **24B = 恰好一次装箱**。反射确认 `PEMaths.IPERange` 的签名是 `bool Overlaps(IPERange other)` ⇒ `GetOverlapsNodes` 里 `range.Overlaps(nodes[i,j].rect)` **每次都把 `PERect` 结构体装箱**。已加 `UnitQueryGrid._nodeRanges`（`GenerateGrid` 时箱一次，之后复用）。
- `InterestPoint.Update` 每帧 `ActorsManager.Players.Min(item => Vector2.Distance(...))` → 捕获闭包 + 枚举器。已改手写循环。

⭐ 通用结论（本日最大收获）：**Unity 项目里 90% 的"每帧几百字节"都是两类**——
① `Enum.HasFlag(...)` 装箱（`GameAttribute`/`WeaponController`/`Furniture_Attached`/`Actor`/`BulletFlag`/`ActorState` 共 6 处，占了一千多次/帧）；
② 值类型结构体传给接口参数（`IPERange`/`IDamageable` 等）⇒ 每次装箱 24~40B。
排查手法：Profiler 看 `GC.Alloc` 子行的**次数**，`总字节 ÷ 次数 ≈ 24` 就是装箱。

### `RenderChunkCuller` 升级为三档（激活/预备/惰性）

`RenderChunkTier` = `Active`（渲染+正常投影）/ `Ready`（仍渲染、关投影）/ `Lazy`（`forceRenderingOff`）。
参数：`ChunkSize=32` / `ActiveDistance=110` / `ReadyDistance=150` / `Hysteresis=10` / `MoveThreshold=16` / `RebuildInterval=30` / `UsePlayerPosition=true`（退化到 Main Camera）。
核心是**双边界 Schmitt 滞回**：`OverBoundary(d, boundary, wasOver) => wasOver ? d > boundary - H : d > boundary + H`，两个边界各算一次 ⇒ 站阈值附近不会反复开关。距离口径 = 到区块**包围盒边缘**。每块记录 `ChunkItem{Renderer, 原Shadow}`，升回 Active 时还原**原本**的投影模式（有些物体本来就是 Off）。
`Dump()` 输出 `区块=N(激活a/预备r/惰性l) 渲染器=… 常驻=…`。
⚠ 若 URP `shadowDistance=70` 而 `ActiveDistance=110`，则预备档（110~150）关投影**没有视觉差异**（那段本来就不投影），此时 Ready 只是纯缓冲带；想让 Ready 真的省阴影提交，得把 Active 设到 70 以内。

### 三条硬经验（下次别再踩）

1. **衰减必须放贴图 alpha，不能放 RGB**：放 RGB × 半透明混合 ⇒ 柔边变"黑边"。
2. **横截面要"平顶 + 边缘 ~40% 柔性"**：纯 `pow(1-c,1.6)` 高斯会让人看成一条细线。
3. **第一人称永远是一条线**：相机基本贴着束轴看，任何"体积感"几何（空心圆柱 / 扁平锥带 / 径向锥体）顺轴看都会退化成一点或一片墙；立体感只在侧视角成立，别指望几何解决 FPS 观感——那要靠枪口特写 + 命中特效 + 颜色纹理。

### 束形纠正（用户第三次校准）

正解是 **枪口最宽 → 远端收成一条越来越透明的细线**，且波纹是**沿光束平行方向**的纵向气流，不是横向环纹。最终参数：

- `widthCurve`：0→**0.14m**、0.25→0.10、0.6→0.055、1→**0.02m**（宽度大＝枪口处）。
- `colorGradient` alpha：0.85 → 0.60 → 0.26 → 0（越远越透明）。
- 贴图改为：v（宽度）方向 5 条**平行**细流 + u（长度）方向相位错开的慢波；`textureScale=(0.55,1)`。
- 材质 `_MoveSpeed = -900`（负值）⇒ 纹路朝远端流动。

⚠ 两个反例：① 把 widthCurve 做成"近窄远宽"是反的；② 枪口给到 0.46m 时，第一人称在 0.7m 处约占 36° 视角，直接糊满半屏 ⇒ 0.12~0.15m 才是"看起来宽"又不出格的范围。

### ✅ 修正（用户追问后复核）：控制状态其实**是**同步的
