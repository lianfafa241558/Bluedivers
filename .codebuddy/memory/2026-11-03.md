### 续修：对地射击时光束线甩到世界原点 (0,0,0)
- 现象：低头打地面，`LineRenderer` 的 p1 = `(0.000,0.000,0.000)`，线飞出屏幕
- 实测：细线正常打在 `Terrain @3.906`；球扫另有 3 条 **distance=0** 命中：`WallLenght(道具,有Damageable)`、`Terrain`、`Player(Clone)`，它们的 **`hit.point` 全是 (0,0,0)**
- 根因：Unity 对"球在起点就与碰撞体重叠"的命中只给 distance=0，**point 未填充（=0）**。`end = hit.point` 直接把它当终点 ⇒ 线去世界原点。`ApplyHit` 里早有 `if (hit.distance <= 0)` 的兜底，但 `SampleBeam` 设终点的地方没有
- 修法：distance=0 的命中先判"是不是真在光束上"（细线打的就是同一个 collider 才算，近身目标走这条），否则 `continue`（身边贴着的墙/友军不该吞掉光束）；真命中但退化时 `end = origin`（枪口 + MinRange）。`SampleThinBeam` 同样加"起点嵌在碰撞体里"的退化处理
- 复算（同一条实测数据）：`[skip] degenerate off-line WallLenght` / `[skip] terrain` / `[skip] degenerate off-line Player` ⇒ 线终点 `(556.827, 20.940, 535.189)`（脚下 3.9m 地面）✅
- 通用经验：**Unity `SphereCast*` 的 distance=0 命中不可信**（point/normal 不填），任何拿 `hit.point` 当落点的地方都要先判 distance

## 修：ProjectileGrenade 手雷炸在 (0,0,0)（"像被提前回收"）
- 现象：手雷落地后爆炸/烟幕特效出现在**世界原点**，弹体像是当场被回收
- 根因（`06Gameplay/Projectile/ProjectileGrenade.cs`）：`Collide` 把弹体摆到 `hit.point + normal*Radius` = 与地面**严格相切** ⇒ 下一帧 `SphereCastAll` 的**起点与地面碰撞体重叠** ⇒ Unity 只给 `distance=0` 且 `point/normal 未填充(=0)` 的退化命中；`TryHit` 不判 distance 直接当选中点 ⇒ `transform.position = (0,0,0)+normal*0.2` ≈ 世界原点，引信到点就在原点结算+播特效
- 同一帧内还会顺手 `m_Bounced++` ⇒ 5 次退化命中把弹跳次数吃光、提前 `m_Resting`（解释"被提前回收"的观感）
- 基类 `ProjectileStandard.Hit()` 本来就有 `if (closestHit.distance <= 0f)` 的兜底，**手雷覆写的 TryHit/Collide 这条路漏了**；今天 `ProjectileLaser` 的光束"甩到 (0,0,0)"是同一类根因
- 修法：① `TryHit` 循环里 `if (hit.distance <= 0f) continue;`；② 贴面位置加 `k_SurfaceGap = 0.01f`（相切 ⇒ 起点重叠的源头）；③ 顺手 `SphereCastAll` → `SphereCastNonAlloc` + 静态 `s_HitBuffer[32]`（对齐基类，手雷每帧不再分配数组）；离线编译 06_Gameplay 0 error、BOM 完好

### 续修：改完变成"滚着滚着穿过地面掉下去"
- 根因（上一版"跳过退化命中"的副作用）：球心一旦陷进碰撞体（贴地滚动、落在凹角、球扫近切向掠地形漏检），Unity 之后**每帧都只回 distance=0** ⇒ 被跳过 ⇒ 没有任何东西能再发现它，重力把弹体越拽越深 ⇒ 掉到地下
- 关键认识：**球扫对"起点已重叠"是瞎的**，所以"跳过"只能靠"永远别陷进去"，而这在贴地滚动时不可保证 ⇒ 必须有自救路径
- 修法（同文件）：
  - `RecoverFromOverlap()`：`TryHit` 里只要见到"通过了 `IsBounceValid` 的退化命中"就当球心陷住了 ⇒ 从球心正上方 `3R` 俯投一次 `SphereCast`（距离 `6R`）拿真实的面，再走 `Collide` 那套贴面+反弹（下探起点也在面外 ⇒ 不会再次退化）
  - `Collide` 的 `RestSpeed` 分支：由"只清零速度"改成**同时 `m_Resting = true`**（= 关掉基类 Move 的重力），否则每帧还往下沉 1~2cm，正是"慢慢陷进去"的源头；语义与字段名「静止阈值」一致
- 验证：`offline_compile.py 06_Gameplay` 0 error；`RestSpeed`(0.6) 变大会让手雷更早趴下，手感要实测
- 通用经验（可复用）：**任何"必须跳过 distance=0 命中"的球扫，都要配一条重叠自救**（否则从"误判"变成"永久失明"）；`ProjectileStandard.Hit` 那种"用 Root.position 顶替 point"只是不出错，仍会一路下沉

## 修：UnitAnimatorCuller 冻住入场动画（从天而降卡在天上）
- 现象：单位逻辑坐标在地上、只是动画播一次性 `Appear`（Droid_AR_Appear.anim，2.13s，m_LoopTime=0）；>120m 被 Culler `Animator.enabled=false` ⇒ 状态机钉在第 0 帧 = 模型悬空，玩家走近才落下

- 开销≈0：稳态远单位已 `AnimatorsOff` 走 else 分支，不再读 stateInfo；只有入场那 2s 窗口重复查
