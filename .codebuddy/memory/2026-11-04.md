## 修 `MissingReferenceException: MissionView` (堆栈 GlobalEventBus.Mark)

- 根因：`MissionView` 订阅 `GlobalEventBus.OnMark`（静态事件）**退订是条件式的** —— `Uninit` 里 `if (!discovered) -= Mark`，而 `TryDiscovered` 只在 `!discovered` 时才退订 ⇒ 带 `MissionTag.StratDiscovered` 的任务 `Init` 时 `discovered` 已为 true，订阅了却**永远没人退**。静态事件不随场景卸载消失 ⇒ 任务点销毁后，`VFXHaloEffect.SetOrigin` 触发 Mark 就命中已销毁对象。
- 修法（`06Gameplay/Data/Game/MissionView.cs`）：① `Init` 里 `if (!discovered) += Mark`（对称）；② `Uninit` 无条件退订；③ 新增 `OnDestroy` 再退一次（任务未结束就转场/卸 prefab 走不到 `Uninit`）；④ `Mark` 首行 `if (!this || !target) return;` —— 本帧 `Destroy` 后到 `OnDestroy` 执行前仍可能回调。
- 通用口径：静态 `event` 的订阅/退订必须**成对且无条件**，别把退订挂在业务状态（discovered）上；`enabled=false` 不阻止委托被调用。

## 「0 伤害也发」评估（结论：不直接放开，改发满槽切换）
- 直接去掉 `damage <= 0` 的门**没用**：上报源头在 `Health.TakeDamage` 的 `if (trueDamageAmount > 0)` 里（`Health.cs:279`），0 伤害时 `OnDamaged`/`OnHit`/`UnitEventBus.UnitDamaged` **一个都不发**。
- 放开该 `if` 的连带风险：`OnDamaged` 还挂着 `AIController._OnDamaged`（统计命中次数/仇恨/`DetectionModule.OnDamaged`）、`PlayerSpeechManager`（受击喊话）、`HealthFX`（闪变/音效）⇒ 0 伤害控制命中会把表现与统计口径一起污染。
- 语义冲突：`Damage == 0` 已被 `SendEnemyDied`（`Damage=0, IsDeath=true`，`NetRoomFlow.cs:1046`）占用为"只报死亡"；放开后只能用 `0 && !IsDeath` 表示副作用包，`OnRemoteHit`/`OnRemoteDamaged`/`ApplyRemoteDamage` 三处都要加分支并保持 `IsDeath` 判断。
- 流量：纯控制武器每发一条 4025 + N 条 4040（8 发/秒 × 4 人 ≈ 32 条/秒新增），且免疫命中也会发垃圾包。
- **推荐**：只同步"满/不满切换"——`Health_AboState.NotifyFullChanged` 里发 `AboStateMsg{NetId, Type, Full}`，接收端 `FillAboGauge`/清零。gameplay 效果全挂在满槽，中间值只影响 HUD 条长度；流量 ≪ 每发一条。若坚持中间值逐点一致，必须：不动 `OnDamaged`（新增事件）、三个桥保持 `>0` 早退、并做限流/合并。

## 手雷低速还在高速自转（`ProjectileGrenade`）
- **根因**：`ProjectileStandard.Move` 每帧 `transform.forward = m_Velocity.normalized`。方向变化率 ≈ 重力/速度 ⇒ 速度掉到 1 米/秒时为 ~500 度/秒；弹跳后速度被 `BounceDamping` 衰减到 0.6~2 m/s 这一段最明显（看起来"快停下了还在原地打转"）。同理 `Collide` 里反弹瞬间直接甩 180° 也是"抽一下"。
- **改法**：`ProjectileStandard` 抽出 `protected virtual void FaceVelocity()`（默认保持原行为，其余弹种零影响）；`ProjectileGrenade` 覆写：速度 < `SpinMinSpeed`(默认 2 m/s) 定住不转，否则 `RotateTowards` 限角速度 `MaxSpinSpeed`(默认 240 度/秒)。`Collide` 里那行直接赋 forward 删掉（交给限速路径）。
- 口径：只动表现，不动弹道/碰撞；两个新字段是 `[SerializeField] private` 带初值 ⇒ 老 prefab 没这个 key 也会用代码默认值。
- 验证：`offline_compile.py 06_Gameplay` ⇒ 0 error。

## 修「CreatUnit: tier 'Boss' 不存在，降级到默认 tier」（WaveManager）
- 根因：`WaveManager.Awake` 建 `TierItemWeight` 时 `if (kvp.weight == 0) continue;` —— 把 **tier 权重**当成了"该 tier 有没有单位"。模板里 `首领 / 警戒 / 特殊1` 常配 `weight = 0`（= 不进随机波次构成），但刷怪器 `CreatEnemy` 是**直接指定 tier** 取 prefab 的 ⇒ 这些 tier 查不到就降级抽别的单位（联机还会让成员端 4063 复刻失败）。
- 修法：字典收**所有** `unitWeights` 非空的 tier（顺带跳过 `unit == null`、空列表丢掉）；`weight > 0` 只在 `TierWeight`（随机波次）里过滤，并追加 `TierItemWeight.ContainsKey` 条件，避免"weight>0 但没配单位"的 tier 走到 `InitWaveUnits` 里 `[tier]` 越界。
- 顺手修掉同段的权重 bug：`new KVP<int, UnitWeightCfg>(kvp.weight, cfg)` 用了 **tier 权重**当每个单位的抽取权重 ⇒ 同 tier 内配额实际上全一样（Inspector 里每只怪的"权重"从未生效）。改成 `cfg.weight`。**这会改变波次内单位构成（两端同数据故仍一致）**，要回到旧手感只能改数据不能回退代码。
- 降级 warning 补上"已配置: xxx"列表，下次直接看出是哪个 tier 缺单位。
- 验证：`offline_compile.py 09_Managers` ⇒ 0 error（⚠ 程序集名是 `09_Managers`，写 `09Manager`/`09_Manager` 都"找不到 csproj"却仍打印 0 error = 假通过）。
