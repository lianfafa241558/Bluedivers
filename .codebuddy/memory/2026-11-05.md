### 澄清 + 增强：爆炸伤害到底算没算

- 结论：**一直有算**。`DamagePerProjectile = 直击(满蓄缩放后) + 爆炸`，单发/每次扣扳机/爆发DPS/持续DPS 全部基于它。
  实测证据：书记的惩戒 直击 16×6=96 + 爆炸 4 = 100；光耀·超新星 20×3=60 + 30 = 90；燃烧弹 0+60=60。
- 之所以"看起来没算"：面板只给一个总数。已加一行拆分
  `直击 X + 爆炸 Y（半径 Nm，按爆心满伤）= 单发 Z（直击已按满蓄 ×k）`。
- 三条口径（写进注释）：
  1. **蓄力枪的爆炸不随 ChargeDamageScale 放大** —— 运行时 `DamageData.GetExplosionDamage` 只吃半径衰减，蓄力只放大爆炸半径（`ChargeAOERangeScale`）；
  2. 爆炸按**单目标爆心满伤**计，多目标溅射不叠进 DPS；
  3. 半径内线性衰减不建模（0 距离 = 满伤）。现存带爆炸的武器半径都 > 0（1.3~6m），不存在"有爆炸伤害但实际打不到"的虚算。

### 修正：热量武器不能用弹匣算节奏

- 问题：星辰脉冲等 3 把枪装了热量系统（`HeatPerShot > 0`），弹匣只是能量池；之前直接 `弹匣总伤 ÷ (弹匣发数 × 间隔)` 会把 128 发算成 12.8 秒打空，持续 DPS 虚高 4~5 倍。
- 热量口径（`WeaponBaseController` 热量系统）：热量是**独立 0~100 池**（`MaxHeat = 100`），每发 `+HeatPerShot`（蓄力枪再乘 `ChargeHeatScale`），满 100 过热并锁 `OverheatDuration` 秒（期间热量线性归零）。
  - 一轮发数 = `ceil(100 / 每发热量)`；连射时每发重置 `CoolDelay`，只有 `射击间隔 > CoolDelay` 才扣掉 `CoolSpeed × (间隔 - 延迟)` 的散热；
  - 打空一匣的过热次数 = `ceil(弹匣发数 / 一轮发数) - 1`；持续 DPS 分母 = 射击耗时 + 过热次数×过热时长 + 换弹。
- 实测：星辰脉冲 16.67 热 → 6 发/轮、2.2s 过热、128 发 21 次过热、打空 59s，持续 DPS 602→**130**；光之剑超新星 4.5 热 → 23 发/轮、15 次、65.5s、124.9→53.4；科莱特微波枪 9 热 → 12 发/轮、24 次、89.9s、50.1→23.4。
- 面板补一行明细：`热量：每发 +16.67 热（满 100）⇒ 一轮 6 发（一轮总伤 360）· 过热 2.2s 归零 · 打空一匣 59.0s（含 21 次过热）`。爆发 DPS 仍是"一轮内"速率，持续 DPS 才含过热停顿。

### 再修正：热量武器的"弹匣总伤"按到过热为止

- 用户口径：热量武器的弹匣就是那 100 热 ⇒ **弹匣总伤 = 每次扣扳机伤害 × 一轮发数**（星辰脉冲 60×6=360），不是整池。

  ⚠ 持续 DPS 的分子必须用 `PoolDamage`，否则会被这个口径改成"一轮 ÷ 整池时间"。
- 行标签随武器动态：热量武器显示 `弹匣总伤(一轮)` / `全弹总伤(整池)`；标签列宽 92→110 防挤。
- 实测：星辰脉冲 弹匣 360 / 整池 7680 / 持续 130.3 / 总分 58.1(B)；光之剑超新星 230 / 3500 / 53.4 / 22.7(E)；科莱特微波枪 84 / 2100 / 23.4 / 30.3(E)；非热量武器不变（逻辑 640）。

### 蓄力口径补齐（DPS / 范围伤害）

- 运行时事实（`FpsHelper_Hit` + `DamageData`）：
  - 直击 = `GetDirectDamage(charge) × damageScale`，`_HandleValue(DamageDirect, ChargeDamageScale, charge)` ⇒ **吃蓄力倍率**；
  - 爆炸 = `GetExplosionDamage(charge, dist) × damageScale`，**只乘半径衰减、不吃 ChargeDamageScale**；
  - 半径 = `GetDamageOuterRadius(charge)` = `ExplosionRange × ChargeAOERangeScale`（满蓄）⇒ **半径会放大**。
- 之前缺的是**范围伤害那一项用了基础半径**。已补：`BaseExplosionRange` 存原值，`ExplosionRange = 原值 × ChargeRangeScale` 用于 AOE 评分与显示（面板标 `(满蓄)`）。
- 蓄力判定从 `ShootType == Charge` 改成读私有序列化字段 `Damages[i].UseCharge`（`ReadUseCharge`）—— `_HandleValue` 只在 UseCharge 时 Lerp；测试武器就是「ShootType=蓄力但 UseCharge=false」的反例。
- 实测：光耀·超新星 半径 2→4m、范围分 48→59；书记的惩戒 直击 20×6=120 + 爆炸 5 = 125（爆炸不乘 6），DPS 25；皇室蔷薇 ChargeAOERangeScale=0 但原半径 0，无影响。

### 已修：爆炸伤害值不吃 ChargeDamageScale（2026-11-05 判定为 bug 并修复）

- 改动：`DamageData.GetExplosionDamage` 由 `半径衰减 × DamageExplosion` 改为

  光耀·超新星 单发 90→**150**、范围分 59→79、总分 29.8(E)→**36.8(D)**。
- ⚠ 这是**玩法数值改动**：所有 `UseCharge` 且 `DamageExplosion > 0` 的武器，满蓄爆炸伤害翻 N 倍。

### 蓄力武器双条：满蓄 + 最低蓄力，分数取平均

- `BuildScoreReport(weapon, serialized, chargeRatio)`：新增第三参（0=最低蓄力、1=满蓄），所有蓄力相关量都按 `Lerp(1, 倍率, ratio)` 缩放：
  直击/爆炸 ×ChargeDamageScale、爆炸半径 ×ChargeAOERangeScale、穿甲 ×DirectAPChargeScale/ExplosionAPChargeScale、
  每次消耗 `Lerp(ChargeAmmoOnLowest, ChargeAmmoOnHighest)`、蓄力耗时 ×ratio、每发热量 ×ChargeHeatScale。

  `光耀·超新星 0~4 段`、`皇室蔷薇 0~1 段`；`书记的惩戒 3~3 段` 只能满蓄发射 ⇒ 单条。

  对比表：综合分与各单项分同样取均值，明细数值按满蓄显示，并附一行注释。
- 实测：光耀·超新星 单发 150/50、爆发DPS 48.7/624.4、总分 38.1/54.7 ⇒ **平均 46.4**；皇室蔷薇 137.5/55、总分 36.0/43.5 ⇒ **39.7**。

### Bug：书记的惩戒 一轮伤害显示 1500000

- 根因：热量的"有效每发热量" = `HeatPerShot - CoolSpeed × max(0, 间隔 - 散热延迟)`。当**散热比加热快**（例：冷却延迟填 0）结果 ≤ 0，
  旧代码 `Mathf.Max(0.01f, ...)` 钳成 0.01 ⇒ `ceil(100/0.01)=10000 发` ⇒ 150×10000 = **1,500,000**。
- 修法：有效热量 ≤ 0.0001 ⇒ `BurstShots = 0`（永远不过热），弹匣总伤退回整池、不插过热停顿；有效热量 > 0 时再把一轮发数钳到 `MagazineShots`。
  明细行新增分支：`热量：每发 +X 热，但散热 S/s ≥ 加热速度 ⇒ 连射不会过热，按整匣 N 算`。
- 结构体同步：`HeatPerShot`（prefab 原值）/ `EffectiveHeat`（净攒）/ `CoolSpeed`；`BurstShots == 0` 表示不会过热。

### 清杂改为「输出 × 覆盖系数」

- 用户指出：清杂不能直接拿 DPS，得额外算范围。改为

### 清杂再改：主体换成射速（DPS 不可靠）

- 用户补充：没范围 + 射速慢 ⇒ 清杂基本为零。改为
  `清杂 = clamp(射速分 × 覆盖系数 × 击杀门槛, 0, 100) × 70% + 弹匣总伤分 × 30%`
  - `射速分` = `ScoreCurve(1/Interval, FireRateAnchors)`，锚点 {0.4→0, 1→20, 2→40, 4→60, 8→80, 14→93, 20→100}（log）
  - `覆盖系数` = 0.7 + 0.8×范围分/100（无溅射 0.7、满 1.5）

## 锁定子弹（ProjectileLockStandard）转向 + 子弹标旗收敛

- **背对目标速度诡异**：旧代码 `m_Velocity = Lerp(m_Velocity, 目标方向*|v|, SteeringSpeed*tick)`。目标在正背后时两向量反向 ⇒ 插值穿过零向量，速度每帧衰减 (1-2k) 且方向来回翻，几帧后原地抽搐；任何转弯都会让 `|v|` 单调掉（第二次起目标大小也随当前速度缩），永不恢复。
- 修法（`ProjectileLockStandard.Steer`）：先算**总速度** = `m_Velocity + InheritedMuzzleVelocity`，用 `Vector3.Angle × (1-e^(-SteeringSpeed·tick))` 求本帧转角，`AngleAxis` 只转方向、**大小原样保留**，最后扣回继承速度。正对/正背时 `Cross` 退化 ⇒ 取垂直轴兜住（否则轴为零向量 ⇒ 速度为 0）。收敛系数改成指数式 ⇒ 帧率无关；`SteeringSpeed=15` 的手感与旧 Lerp 系数（≈0.24/帧）基本等价。
- 另外：`OnEnable` 里清 `_target`（**不能**放 `_OnShoot` —— 真弹路径是 `OnBulletShoot`(SetTarget) 先、`Shoot`(_OnShoot) 后，会被当场抹掉；池弹出时 `OnEnable` 早于两者）。
- **穿透标旗**：`ProjectileStandard` 里"停不停"原本分三处判（`IsHitValid` 滤地形 / `TryHit` 判单位且额外要求 `Source.IsValid()` / `HitFX` 再按标旗判一遍），口径一分叉标旗就"没反应"。现收敛到 `TryHit` 一处按标旗判；`HitFX` 保留同口径（穿透命中也要走它播特效+结算，不能被误停），并**去掉重复伤害**：同一 Actor 的第二个部位碰撞体不再走 `foundHit→Hit` 再打一次（旧代码在子弹停于体内时逐帧重复结算）。
- 数据侧事实：全工程**没有任何预制体配 `PenetrateTerrain(2)`**；`IntelligentRifle.prefab` 的 `BulletFlag = 0`；`穿透单位/穿透地形` 在数据里也没有对应升级行（只有 `WeaponUniqueAttributeApplier` 的字典键），所以标旗只能靠预制体手配。
- 验证：`offline_compile.py 06_Gameplay` 0 error；未进 Play 实测。
- 需求追加（用户）：**穿透命中单位后脱离锁定、沿当时朝向直线飞**。实现 = `ProjectileLockStandard.Update` 开头 `if (_target && m_hasHits.Count > 0) _target = null;`（`m_hasHits` 只在"打中单位"时写：穿透分支/弹射；打地形不清锁定）。判定是"命中任一单位"，不是只认锁定目标。
- 口径补充：锁定弹**没有"到达目标点就停"**——`_target` 只喂转向，收尾只有四条路（联机表现弹的 `VisualEndPoint` 收尾 / 超 `MaxRange` / 生命引信 / TryHit 挡下命中）。开了穿透单位后它穿过去仍会被转向拉回来绕圈，第二圈起 `m_hasHits` 已记该 Actor ⇒ 只穿不打，直到射程或引信到点。

  Inspector 里改 `_fakeAttrs` 不会让它失效 ⇒ `AttrFinal()` 一直返回旧 `GameAttribute`，评分与对比都读旧值，只有域重载才恢复。

  + 对列表里每把枪 `cfg.Init()` 强制重建属性表；`OnFocus` 也做同样的属性表重建（但**不重置选中**，避免点一下窗口就丢武器）。
  ⚠ `cfg.Init()` 只在 `!Application.isPlaying` 时调用 —— 运行中重建会把已应用的改装/`GameAttribute` 全换掉。
- 验证（临时 `Instantiate` 副本，不动资产）：改 `cfg._fakeAttrs[ShootInterval]` 后评分 Interval 仍是 0.1396（旧值）⇒ `cfg.Init()` 后变 0.5。
- 结论：编辑器里"读 cfg 派生出来的数值"都要考虑这层缓存；`Damages`（普通序列化列表）不受影响。

- 输出分 `ScoreHeavyOutput = (匣分 + DPS分) × 50%`；**投掷物只取匣分**（0.1s 打空算出的假 DPS 会顶满分）。
- `反重 = 输出分 60% + 破甲 20% + 弱点 20%`（`ScoreHeavyPerTrigger` 改名 `ScoreHeavyOutput`）。

### 综合能力改成「打靶算账」（清杂 = 10s 击杀数，反重 = 重甲 TTK）

- **清杂**：`击杀数 = clamp01(有效单发/50) × 目标数 × min(ClearRate×10, 总备弹/消耗)`，
  `ScoreClear = ScoreCurve(击杀数, ClearKillAnchors)`（`{0.5→0,1→12,2→28,4→48,8→66,15→82,30→93,60→100}`，log）。
  常量 `ClearMobHp=50` / `ClearWindowSeconds=10`。伤害溢出（>50/只）、真空期、多目标全部自动包含。
- **反重**：`需要枪数 = ceil(1000 / 重甲单发)`，`TTK = 需要枪数 / ClearRate`；`需要枪数 > 总备弹` 或 `重甲单发=0` ⇒ **打不死 = 0 分**。
  `ScoreHeavyOutput = ScoreCurve(TTK, TtkAnchors)`（`{0.2→100,1→90,2→80,4→68,8→55,15→40,30→22,60→5,120→0}`，log）。
  常量 `HeavyTargetHp=1000`；`反重 = TTK 分 60% + 破甲 20% + 弱点 20%`。
- 删掉死代码：`ClearScoreScale` / `ClearKillThreshold` / `FireRateAnchors` / `ScoreClearRate` / `ScoreFireRate` /
  `HeavyMagazineDamage` / `HeavyDps` / `ScoreHeavyMagazine` / `ScoreHeavyDps`。
- 面板：清杂行 `10s 击杀 N 只（50血0甲）`；反重行 `AP x · 击杀 N.Ns（1000血4甲）` 或 `打不死`；
  对比表加「10s 清杂击杀」「重甲击杀耗时(s)」，**TTK 行改为越低越好**（`DrawCompareRow(..., lowerIsBetter:true)`）。
- 实测分布：清杂 平均 44.5 / 中位 40.6 / 最高 100（步枪类 88~90、投掷物 53.8 受弹药封顶、慢枪 28~38）；
  反重 平均 9.5 / 中位 2.7 / 最高 80（31 把里只有 7 把打得穿 4 甲，其余靠破甲+弱点拿 0~19）。

### 弱点加成从「反重独立 20%」改成「伤害乘区」

- `weaknessScale = 1 + max(0, WeaknessBonus) × 0.5`（÷2 模拟"不是每枪都打中弱点"），
  只乘到**反重用的重甲单发**上（`HeavyDamagePerTrigger = heavyArmorDamage × weaknessScale`）；`HeavyDamageFactor` 仍只反映护甲折算（不含弱点，避免被顶过 1）。
- 反重公式随之变成 `ScoreAntiHeavy = TTK分 80% + 破甲分 20%`（弱点不再单列；TTK 因为伤害变大而自然受益）。
- 弱点加成这个**单项 3% 仍保留**（`ScoreWeakness`），所以弱点是"单项计分 + 反重伤害乘区"两处体现，不是重复计分。
- 实测：皇室薔薇 弱点 20% ⇒ ×1.1、重甲单发 82.5→90.8、TTK 47.1→43.5s、反重 29.3→33.1；
  逻辑/理性 弱点 20% 但 AP1 对 4 甲伤害为 0 ⇒ 乘区无效，反重从 18.9 掉到 **2.9**（原来那 18.9 几乎全来自弱点 20% 分）。
- 若要"弱点对所有伤害生效"（单发/DPS/清杂一起乘），说一声我把 `weaknessScale` 提到 `RealDamagePerTrigger` 那一层。
