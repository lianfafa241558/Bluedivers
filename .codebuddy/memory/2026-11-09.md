## 空投舱"落在天上"排查（VFXAirdropEffect / AirdropPod）
- 结构事实：舱与内容物的**最终 y 完全由信标 transform 决定** —— `VFXAirdropEffect.cs:537`（`m_creatObject.position = transform.position`）与 `:574`（内容物在 `transform.position+0.2up`）。舱自己算的 `m_LandingHeight` 只是过程量，落地时被这两句覆盖 ⇒ "落在天上" = 信标本身没贴到真地面。
- 信标贴地只有两条射线：`:227`（SetOrigin，`point+10` 向下 200m）与 `:301`（TmpAirdrop，`point+100` 向下 150m）。**失败时静默保留原 point**（空中/墙面/单位身上），无日志无兜底 ⇒ 整发悬空。
- 贴地射线只认 GroundLayers 的**第一个命中面**；而 `Pod.prefab` 的 column_*/Boxc*/bone_root 碰撞体 **layer=3=Ground**（为让子弹能打中）⇒ 永久舱（`ResetLift(9999)`）/上一个舱/悬空载具/货箱/树冠都会被当成"地面"。
- `AirdropPod.Move()` 贴地公式错：`:164-165` 写成 `y = m_LandingHeight + extraHeight`，正确应为 `transform.position.y += extraHeight` ⇒ 多顶"一物理帧下落距离"（200m 自由落体末速 89 m/s × 0.02 = 1.8m；"空投降落速度"×2 ⇒ 3.6m）。
- `AirdropPod.ResolveHit` 的 `:281` `+0.5f` 容差会提前 `Stop()` 且不重定位；若这次 PodHit 因非 Ground 层已早退，则既不出内容物、舱也停在离地 ≤0.5m。
- `Launch()` 的 `:138` 落地射线不排除自身碰撞体（m_IgnoredColliders 收集了但 Raycast 用不上）⇒ Root 在碰撞体上方的 prefab（Artillery Player / OilPlane / Turret_Mission_Machine）会"出生即落地"，全靠信标传送兜底。
- 待拍板：是否加统一 `ResolveAirdropGround()`（排除 AirdropPod 子树 / AirWall，失败记 Warn 并取消该发）+ 修 Move 公式 + 去掉 ResolveHit 的 0.5 容差。

## 地形硬度场（低分辨率，2026-11-09）
- `TerrainUtils`（`Assets/Scripts/00Tools/TerrainMainUtils.cs`）新增硬度场：`float[] hardness`，分辨率 = `heightmapRes/2`（高度图 512 ⇒ 256²），`Main` 赋值时重建、置空时作废。
- 只在"挖"这条路上生效：`ModifyHeightMap(..., isSet:false)`（炸弹坑 `FpsHelper_Hit`、`Furniture_Pipe`）实际挖深 × (1-硬度)；`isSet:true`（任务点整平 / 附加地形）不受硬度约束，否则任务平台永远压不平。硬度 = 1 的格子整格跳过（不能只把挖深归零 —— 那步 Lerp 到 centerOldHeight 会把低洼处抬起来）。

## 换弹"反向加弹" / 三连发来回换弹（WeaponReloadController.ReloadEnd）
- 现象：SecretaryDecision 装 `WUD_OverpressureLoad`（二轮爆发/三连发：BulletsPerShot 1→3、ShootCost 1→3、BurstInterval 0→0.06）后，弹匣2/后备1 会一直换弹，2/1 → 1/2 → 2/1 死循环。
- 根因（`WeaponReloadController.ReloadEnd` 旧式）：`newAmmo = Min(Ammo.CurrValue, Magazine.FinalValue)` 把**后备弹量**当成了换弹后的**弹匣总弹量**；弹匣没打空时 newAmmo < oldAmmo ⇒ `Ammo.CurrValue -= (newAmmo-oldAmmo)` 变成**反向加弹**（总弹数不变、两格互换）。循环的触发前提是 `WeaponController.LogicTick` 那条"残弹 < ShootCost 就自动换弹"兜底（ShootCost=3 ⇒ 弹匣 1~2 时每帧重试）。
- 已修：只补空位 —— `space = FinalValue - CurrValue; take = Min(Ammo.CurrValue, space); Magazine.CurrValue += take; Ammo.CurrValue -= take;`（`WeaponReloadController.cs:233-242`）。修后 2/1 → 3/0 一次到位，ammo=0 自然停止换弹。
- 口径：`ReloadEnd` 三个调用点（换弹计时到点 / AutomaticReload 的 speed>99 / `ReloadComplete`）都是"补满弹匣"语义，统一受益。同类**增量式**自动装弹 `WeaponController.UpdateAmmo`（Magazine += speed*dt，Ammo -= speed*dt）未改 —— 接近满匣时会短暂多抽后备，留待实际表现再定。

## 终端交互时开窗（ESC 设置）关窗后"又能走又能控终端"（修复，2026-11-09）
- 现象：操作 KeyScreen 终端时按 ESC 打开设置窗、关掉之后玩家既被 WASD 移动、终端也在吃同一批键。
- 根因（三处叠在一起）：① `PlayerOperationController.OnWindowStateChange` 在窗口离开 Game 态时把 `PlayerInputHandler.InOperation` 清成 false（本意是别让关窗后还被交互锁住），但**家具自己的 `inOperate`/`owner` 没人收**；② KeyScreen 的 `owner` 仍在 ⇒ `Update` 照旧跑阶段、读输入；③ 方向键 Left/Up/Right/Down 在 `Assets/Resources/Prefabs/Manager/InputManager.prefab` 里 `window: 0`（= `WindowStateEnum.All`）⇒ 与窗口状态无关，UI 里照样有效。终端的 `flags: 2`（SwitchState）⇒ 正常操作时正是靠 InOperation 挡住移动，所以一被清掉就"双吃"。
