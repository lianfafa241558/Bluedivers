## `KeiShield` 是否该继承 `BoosterEffectBehaviour`（结论：暂不改）

- 它是**反条件**（没 `SampleSaver` ⇒ 关罩子 + `enabled=false`），基类是**正条件**（命中 ⇒ `OnApply`）。直接继承会反向失效：没强化时 `_applied` 初值 false、条件 false ⇒ `Evaluate` 一次回调都不调 ⇒ 罩子停在 prefab 默认（开着、100 盾），正是它注释里要避免的"挡队友子弹"。
- 另外基类的 `OnEnable/OnDisable` 是私有的，子类若再声明会顶掉基类；而 `enabled = false` 又会触发基类 `OnDisable → OnRevert`，语义打架。
- 想统一有三条路：① 不动（推荐，gate 只有 4 行）；② 给基类加 `protected virtual bool ConditionMet()` 供取反；③ 把 prefab 默认改成"罩子关 + MaxShield=0"，让「默认关、命中才开」变成自然的 Apply/Revert（最干净但要动 prefab 数据）。
- ⚠ 顺带确认：`KeiShield` 在 `Start` 里判强化是**对的** —— `Start` 跑在 `AsyncLoadScene` 回调（`BattleManager.Creat` → Init 协程第一段同步执行 `ApplyTeamEnhance`）**之后**。真正会被时机坑到的是写在 `OnEnable` 里的判定。

### 最终选择：KeiShield 改为继承基类 + 默认关（2026-11-10 已落地）

- ⚠ **关键结构约束**：`Kei.prefab` 里 `_shieldVisual` 与 KeiShield 的 `m_GameObject` 是**同一个** GameObject（`9000000001` "Shield"，10 个组件：Actor/HealthShield/ShieldRebuild/KeiShield…）⇒ **不能 `SetActive(false)`**，那会把组件自己禁用、基类 `OnDisable → Unbind` 后永远收不到 `OnApply`。所以"关掉"= **关 Collider + Renderer**（Awake 缓存两个数组，`SetShieldOn(bool)` 切换），效果等价且组件存活。
- 代码：`Awake` 缓存 + `SetShieldOn(false)`（默认关）；`Start` 只保留 NetId 补号 + `_samples` 初值 + `GlobalEventBus.OnKeiSubmit` 订阅；`OnApply` = 开 + `Apply()`（设 MaxShield/scale）；`OnRevert` = 关；删掉原来的 `enabled = false`；`OnSubmitted` 里 `if (IsApplied) Apply()`（基类新增 `protected bool IsApplied`）。
