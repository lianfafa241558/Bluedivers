### 动画器重构：蹲/趴收进子状态机（同日）

- 结构（三个控制器一致，Base Layer）：
  - 顶层状态只剩 `Idle / Move / Ready / Death`；新增两个**子状态机** `Crouch{CrouchIdle,CrouchMove}`、`Prone{ProneIdle,ProneMove}`（含 Entry 过渡各 2 条，内部 Idle↔Move 互切）。
  - 站立/移动的 `Idle↔Move` 直连线**全删**，改成 **AnyState 中枢** 6 条：`Ready / Death / SM:Crouch / SM:Prone / Idle / Move`（后两条条件 `!IsCrouch && !IsProne && ±IsMove`，`CanTransitionToSelf=0`）。
  - 图上只剩 AnyState 一个源点 + 2 个状态机盒子，没有交叉线。
- 脚本：`plans/sm_stance_submachines.py`（幂等：已有 `m_Name: Crouch` 就跳过）。改前先备份到 `_bak_controllers/`。
- ⚠ **踩过的坑**：重写 Base Layer 的 `m_ChildStates` 时只写了 Idle/Move，把 Ready/Death 漏掉 ⇒ 它们虽仍有 doc，但不再是该状态机的子状态 ⇒ 运行时报
  `Transition 'AnyState -> Ready' ... transitions to state 'Ready' which does not exist in controller`，死亡/瞄准动画**整个失效**（而且编辑器看着一切正常）。重排任何 `m_ChildStates` 都必须把原有全部状态列回去。
- ⚠ `AnimatorStateTransition.destinationState / destinationStateMachine` 在 Unity 2022 是**只读**（`AddStateMachine` 也直接返回 `AnimatorStateMachine`，没有 `.stateMachine`）⇒ **AnyState→子状态机只能用 YAML 手写** `m_DstStateMachine: {fileID: <1107>}` + `m_DstState: {fileID: 0}`。若要权威格式，先用编辑器 API 造一个样本子状态机、`SaveAssets` 后读 YAML 抄（Entry 过渡是 `!u!1109`，只有 `serializedVersion: 1` + 条件，没有 duration/exitTime）。
- 实测（`Animator.Update` 推进 + `execute_code`）：Idle→Move→CrouchMove→CrouchIdle→ProneIdle→ProneMove→Move→Death→复活 全通，Aris/Nagisa 同；Console 干净（清空后重新实例化三个模型 0 条）。
- 注意：AnyState 过渡里有 `m_TransitionDuration: 1.0` 的（Death），测状态切换要至少推 1 秒以上帧，否则 `GetCurrentAnimatorStateInfo` 还停在源状态（我因此误判过一次）。

### 更正（同日）：**AnyState → 子状态机 会每帧重入，`CanTransitionToSelf=0` 对它无效**

- 现象：Animator 窗口里 `Any State → Entry → CrouchIdle` 一直高亮（蓝线），像在反复进入同一个状态。
- 量化（`execute_code` 逐帧采样）：`CrouchMove` 60 帧里 **50 帧处于 `IsInTransition`**，`normalizedTime` 0.13→0.22 又跳回 0.11（周期约 5 帧）；对照组 `Move`（AnyState 指向**普通状态**）0 帧过渡、时间正常累加。
  ⇒ 结论：`canTransitionToSelf` 只对"目标是 AnimatorState"生效；目标是 AnimatorStateMachine 时 Unity 每帧都判定为可进入，**蹲/趴动画等于一直在重启**。
  （上一节"实测 OK"是误判：当时我用 `t2 > t1` 判断，重启周期恰好让末值略大于初值。）
- 修法（已落地，脚本 `plans/sm_stance_fix_entry.py`，幂等）：
  - 删掉 `AnyState → Crouch/Prone`；
  - 改由**具体状态**进入：`Idle/Move --IsCrouch--> CrouchSM`、`Idle/Move --IsProne--> ProneSM`（源状态是实状态 ⇒ 进去后源不再激活，不可能自循环）；
  - 蹲↔趴直接互切：`CrouchIdle/CrouchMove --IsProne--> ProneSM`、`ProneIdle/ProneMove --IsCrouch--> CrouchSM`；
  - 回站立仍由 `AnyState → Idle/Move`（普通状态目标，安全）兜住。
- 校验方法（可复用）：逐帧 `anim.IsInTransition(0)` 计数 + `normalizedTime` 是否单调；**只看最终停在哪个状态是查不出重入的**。
- 另：`AnimatorStateTransitionInspector.DoErrorAndWarning` 的 NRE 是 **Unity 自身检视面板**在"选中一条目标为子状态机/目标状态被删掉的过渡"时抛的，只影响 Inspector 绘制，不影响运行；重选一次过渡即消失。
- ⚠ 用 `execute_code` 验证状态机必须在**非 Play** 下做（Play 里 `InstantiatePrefab` 会往运行场景塞物体）；进 Play 时 `refresh_unity` 会超时，属正常。

### 趴姿修正 + 武器挂点随姿态下沉（同日，用户实机反馈）

- 实机问题：趴下时「头朝下 + 腿浮空」，且枪仍停在站立胸口高度。
- 趴姿根因：`RootQ` 前倾 84° 后，**膝盖仍是弯的**（当时 LLS 用 +0.10 且 flatten 0.5）⇒ 小腿在旋转后的身体坐标系里朝上翘。
  - 修法（`plans/gen_stance_clips2.py`，新增 `consts` 参数直接写常量而非加法）：`RootQ` 88°、`RootT.y -0.62`、
    `Upper Leg Front-Back = 0.02`（大腿与身体同线）、`Lower Leg Stretch = 0.95`（**伸直**，膝盖不弯）、`Foot Up-Down = -0.35`。
  - 蹲姿**不用改**：edit 模式实测脚在地面（foot 0.06~0.22），是采样方法不同导致我一度误判它下沉。
- 武器挂点：`Player.prefab` 里 `FirstPersonSocket`(0,1.15,0.1) 挂在 **Player 根节点**，`WeaponParentSocket`/`DefaultWeaponPosition`/`AimingWeaponPosition`/`DownWeaponPosition` 全是它子节点 ⇒ **不吃相机高度**。
  - 修法：`PlayerController_Stance` 记录站立挂点坐标，切姿态时按 `_crouchSocketDrop=0.60` / `_proneSocketDrop=1.00` 改 `FirstPersonSocket.localPosition.y`
    （`PlayerController.Awake` 里把 `WeaponsManager` 赋值挪到 `InitStance()` 之前，否则拿不到挂点）。
  - 盟友侧同口径：`FriendWeaponView.SetStanceSocketDrop()`（把 `aimSocketOffset.y` 减掉下沉量），由 `FriendController.ApplyStance` 按同步姿态调用；`ResetAnimState` 归零。
- ⚠ **采样方法教训**（重要）：Play 模式下用 `PlayableGraph + AnimationClipPlayable + anim.runtimeAnimatorController=null` 采样，**只应用了 RootT/RootQ，肌肉曲线没生效**（腿永远保持绑定姿势），据此判定"蹲姿陷地"是错的。
  可靠路径是 **edit 模式 + `AnimationMode.SampleAnimationClip`**；Play 模式下 `Animator.Update` / PlayableGraph 都不可靠（还会受控制器自身播放覆盖）。
  另外 `EditorSceneManager.NewPreviewScene()` 里创建的 Animator **完全不求值**（两种方式都是绑定姿势）。
- 想要"看"姿势：edit 模式下 `AnimationMode` 采样后，用临时 Camera + RenderTexture 渲 PNG 写进 `Temp/`，再 `read_file` 读图（Play 模式同样不可靠）。
