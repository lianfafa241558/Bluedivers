## 诊断：拦截火车位置不同步（只读调研，未改代码）
- ⚠ 更正旧记忆：`mission-intercept-train.md` §2 说"车头 + 车厢都没有 Actor"**只对车厢成立**。实际 `trainEnginePrefab`（Robbery.prefab）指向 `Resources/Prefabs/GameEvent/TrainEngineSam.prefab`，上面有 **Actor(type=4 Enemy / flag=4 Boss) + HealthEnemy + Damageable + PartController**；`trainCarPrefab` = `TrainEngineCar.prefab`（无 Actor，只有 BaseObject+Armor）。
- 位置不同步根因：① `TrainUnit.Update` 每帧 `_distance += _speed * Time.deltaTime`（TrainUnit.cs:71-84）② 发车由各端自己的 `Tick()` 驱动（_Train.cs:98-103），Tick 时钟是各端本地 `Time.time`（TickBehaviour.cs:22-31,52-65）⇒ 发车绝对时刻差 = RTT/2 + 帧量化 + 加载卡顿；③ 全工程**没有任何火车位姿/存在性同步**（`Train` 在 07NetGame 与 09Manager 里 grep 0 命中）。累积量 = trainSpeed(3m/s)×ΔT，卡顿时 Unity 把 deltaTime 截到 maximumDeltaTime ⇒ 永久丢时间，越跑越偏。
- 建议口径（未落地）：**同步弧长而不是 Transform** —— 两端轨道由 BattleRandom 确定性生成（MissionInterceptTrain.cs:114-129），`_distance` 一个 float 就决定车头 + 全部车厢位姿（TrainUnit.cs:86-94）。房主 2Hz 发 `{Tour(班次), Distance}`，成员端变速追赶（大偏差吸附、小偏差插值），包是幂等全量 ⇒ 丢包下一包自愈。需要新号 `CmdId 4067`（4050-4089 段尾，4066 已用）+ `SyncMsg.cs` DTO + `NetRoomFlow` 注册 + 09 侧桥（06 看不见 07，桥查 `MissionInterceptTrain.Active`）。
- 顺带发现（待实测核验）：车头是 Enemy 型真单位、两端各自 `Instantiate`（_Train.cs:164）⇒ `Actor.Awake` 走 `NextEnemyNetId()` 自增段（Actor.cs:288-295），而成员端 4063 复刻单位**不发号**（Actor.cs:278-282）⇒ 两端自增段推进不同步时车头 NetId 会错位，4053/4054 按号寻址就会打错单位/打不掉血。修法可照 `MissionBase.cs:338-350` 用 `ActorsManager.ForceDerivedNetId` 包住车头 Instantiate（spawnPos 由确定性轨道算出 ⇒ 两端同号、零消息）。

## 为什么火车不能复用现成的 5001/5002 位姿通道（拍板口径）
- 现有的"位置同步消息" = `PlayerTransformUp(5001)` / `TransformBatchSync(5002)`，DTO `PoseSnapshot`/`PoseBatchMsg`（BattleMsg.cs:17-46），**键 = `PoseSnapshot.Sid`（玩家会话号，房主=0）**，消费端 `NetFriendBridge.HandlePoses`（NetFriendBridge.cs:1219-1241）只做两件事：`NetVehicleBridge.TryDriveVehiclePose(sid)` 或 `_friends[sid].ApplyPose(...)`。
- 四条不能复用的理由：① **键空间**是 sid（人的身份）⇒ 火车得伪造 sid，会被名单/断线/`ClearFriends`/`ReconcileFriends` 当成真人处理；② **方向**是"本机权威上行 5001、房主聚合下行 5002"，火车只有房主权威、成员永不上行 ⇒ 要么加假上行，要么在 handler 里按角色分叉；③ **粒度**：位姿是 (XYZ+Yaw+Pitch+Stance+Teleport)，火车两端轨道一致只需 1 个 float 弧长，且真用位姿要给车头挂 `NetTransformView`（它在 Update 里插值写 transform，NetTransformView.cs:74-90），与 `TrainUnit` 每帧 `Apply()` 写车头+全部车厢 transform（TrainUnit.cs:86-103）**两套写手打架**；④ 多趟车同时在线，sid 是单值、缺"班次"这一维。
- 另一个更像的候选 `SceneUnitMoveSync(4055)` 也不行：`SceneUnitMoveMsg` 只有目标点 + `Stop`（RoomMsg.cs:176-185），消费端按 NavMesh 走；火车是沿轨道的解析曲线。且键是 `Actor.Id` = `TrainEngineSam` ⇒ 所有趟次同一个键，必撞。
- 可复用的是**套路**（房主权威 + 低频 + 幂等全量 + 客户端平滑追赶），不是那条消息本身 ⇒ 仍按新开 4067（`{Tour, Distance}`）落地。
