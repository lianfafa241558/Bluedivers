## NormalizeMeshNormals 对 FBX 内嵌 mesh 不持久化（Yuuka.prefab 实证）

- `Assets/Editor/Tool/NormalizeMeshNormals.cs` 不改 `mesh.normals`，只把平均法线 xy 写进 **UV3**（`mesh.SetUVs(3, uv)`），消费端唯一一处：`Assets/Shader/ToonLit/Main/ToonLit_Shared.hlsl:257-267` —— 条件为 `#ifdef ToonShaderIsOutline` **且** 材质 `_UseAverNormal != 0`（默认 0），即只影响描边外扩方向，不影响表面光照。
- 根因：prefab 上的 `SkinnedMeshRenderer.sharedMesh` 是 **ModelImporter 生成的 FBX 子资产**，`EditorUtility.SetDirty` + `AssetDatabase.SaveAssets()` 对它**静默无效**（不报错、不写盘），任何一次 reimport / 重启 / 打包都会按 FBX 重建 → UV3 回滚。
- MCP 实测 `Assets/Resources/Prefabs/StudentModle/Yuuka.prefab`（2026-11-17）：4 个 SMR（Yuuka_Ghost_Body1 / _Hand / _Head / _Head(1)）全部 `path=Assets/Art/Modle/Student/Yuuka/Yuuka.fbx`、`isSubAsset=True`、`uv3=EMPTY`；Body 材质 `Yuuka_Ghost_Body._UseAverNormal=1`，EyeMouth 材质无该属性。
- UV3 为空时 shader 里 `UnpackNormalRG(0,0)` 得到 (-1,-1,0) 归一化的固定切向 ⇒ 描边方向错乱，现象表现为"像没处理/更糟"。
- 修复方向（未执行，等用户拍板）：① 首选 `AssetPostprocessor.OnPostprocessModel` 在 FBX 导入时自动写 UV3（不改 prefab 引用，永不回滚；项目目前没有任何 AssetPostprocessor）；② 备选 `Object.Instantiate(mesh)` 复制成独立 `.asset` 并回填 `sharedMesh`（会产生新资产 + 需改 prefab，注意 MCP 存 prefab 回写旧值的坑）。

- 同日复核（代码层证据）：`Yuuka.prefab:84` 的 `m_Mesh` 就是 `{fileID: 5742973125931296453, guid: 5397a348f97e66345b5327c9ed4db8b1, type: 3}` —— guid 即 `Yuuka.fbx.meta`，`type: 3` 表明是 ModelImporter 产物；`NormalizeMeshNormals.cs:79-83` 的 `SetUVs(3)`+`SetDirty`+`SaveAssets` 没有可写落盘所有者 ⇒ 静默无效但日志照打（`Debug.Log("Normalized…")` 让人误判成功）。全工程 `AssetPostprocessor` 命中 0 处。

## ⭐ 修正 + 落地：AverNormal UV3 改走导入回调（同日 11:2x）

- ⚠ **通道索引陷阱（之前证据作废）**：`Mesh.SetUVs(3, …)` 写的是 **channel 3 = TEXCOORD3 = `mesh.uv4`**；`mesh.uv3` 是 **channel 2（TEXCOORD2）**。所以昨天记的"MCP 实测 uv3=EMPTY"是**读错通道**，不能当"UV3 没写进去"的证据 ⇒ 判 UV 有无必须用 `GetUVs(3, list)` 或 `mesh.uv4`。通道序：uv(0)=TEXCOORD0 … uv4(3)=TEXCOORD3。
- 已实现 `Assets/Editor/Tool/AverNormalUV3Postprocessor.cs`：`AssetPostprocessor.OnPostprocessModel` 里遍历 `MeshFilter`/`SkinnedMeshRenderer`（`true` 含未激活）写 channel 3；范围 `ModelRoots = {"Assets/Art/"}`，`SkipPaths` 留空可填路径片段排除；另有菜单 `Assets/美术/重导模型（重建 AverNormal UV3）`（支持选文件夹，内部 `ImportAsset(ForceUpdate)` + 进度条）——新加/改回调不会自动重导旧模型，必须手动跑一次。
- 计算逻辑抽成 `NormalizeMeshNormals.BakeAverNormalToUV3(Mesh)`（公共静态、只算+`SetUVs(3)`+`RecalculateBounds`，不 SetDirty），旧右键菜单与导入回调共用一份；旧菜单遇到 `AssetDatabase.IsSubAsset(mesh)` 会额外打警告指向新菜单。
- **实测（MCP）**：`Assets/Art/Modle/Student/Yuuka/Yuuka.fbx` 重导后 4 个 Mesh `TEXCOORD3` 全等于顶点数（678 / 4953 / 3275 / 178），`normals` 长度不变、数据未被改写；Yuuka_Ghost_Body1 的 UV 有 2185 个不同值（不是全 0.5 的无效填值）⇒ 导入回调写进 artifact 是持久的，重导不丢。
- 反向验证：`Plugins/RootMotion/.../MechSpider.FBX`（不在 ModelRoots）手动 `SetUVs(3)` 后重导即回 `ch3=0`，实验后已还原。
- ⚠ 代价：`Assets/Art/` 下约 440 个模型（Modle 252 + Nature 167 + 其它）会各加一条 8 字节/顶点的通道，下次全量重导/打包体积与显存都会涨；不要的目录塞 `SkipPaths`。
- 遗留：编辑器里手动对导入产物 `SetUVs` 会不会写进 artifact **未证**（`Resources.UnloadUnusedAssets` 拿到的还是同一实例，`Library/Artifacts/<guid前2>/<guid>` 路径也没找到），所以"手动改不持久"这句目前只有 Unity 导入模型层面的推断支撑，不是实测结论。
