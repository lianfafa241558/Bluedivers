## 刷怪器"权重不生效 / 永远出该 tier 第一个单位"（已修）

- 现象：`CreatEnemy` 刷怪器刷出来的单位，同一 tier 永远是权重表里的第一把 prefab。
- 根因：`WaveManager.NewSpawnRandom()` 只按 `(TaskState.Seed, waveSeq)` 播种，**每次调用都 new 一条同种子的流** ⇒
  同一波内首个抽样值恒定；`TakeTierUnit` 里"权重 → 抖动 → 朝向"三次抽样全部相同 ⇒ 同 tier 同一把 prefab，
  且同点刷怪器抖动/朝向雷同（会叠在一点）。权重表数据本身没问题（CD_Kaiser / Desert 各 tier 权重和都是 100）。
- 修法（`09Manager/Battle/WaveManager.cs`）：
  - `NewSpawnRandom(int salt)`：二次派生 `Derive(Derive(seed, UnitPlacement*1000+waveSeq), salt)`。
  - `CreatUnit(tier,…)` → salt = `PosSalt(pos)`（位置量化，两端同点同流）；新增私有重载 `CreatUnit(tier,pos,range,Random,isFixed)`。
  - `CreatPatrol` 整队**共用 `patrolRandom` 一条流**逐只往下抽（两端同序消费 ⇒ 构成一致且队内不重复）。
  - `CreatSpawnerUnit` 改用 `random`（BattleRandom）：刷怪器房主唯一生成，不需要两端同流。
  - `TakeTierUnit` 的 `WeightTake(100, …)` 改成**现算总权重**：和 < 100 会整段落空退化成 `list[0]`（同一症状），> 100 则尾部抽不到。
- `InitWaveUnits` 同步收掉：tier 总权重外提现算、单位总权重每轮按当前 tier 现算，不再写死 100（用户拍板：total ≤ 0 不处理）。
- 验证：`offline_compile.py 09_Managers` 0 error；文件仍 LF+BOM（未被 `replace_in_file` 改成 CRLF）。

## 手雷爆炸"重复播好多特效"（已修）

- 根因 1（主因）：`ProjectileGrenade` 自己声明了**私有 `OnDisable`**，把 `ProjectileBase` 的私有 `OnDisable`
  （`OnShoot=null; OnHit=null`）**整条遮掉** —— Unity 消息按"最先找到的那一个"调用，派生类私有同名消息会顶掉基类的
  ⇒ 池化复用时订阅从不清空，每投一颗就叠一份 `HitFX` + `FpsHelper.Hit`，第 k 次爆炸播 k 份 `DamageData.ImpactVfx`。
  修法：基类改 `protected virtual void OnDisable()`，手雷 `protected override` + `base.OnDisable()`。
  ⚠ 通用教训：任何基类的**私有** Unity 消息都可能被子类同名私有消息遮掉，要么 virtual+override，要么取消订阅写在 OnEnable 里配对。
- 根因 2（会放大）：`ProjectileBase.Release()` 不幂等 —— 引信到点 `OnHit` 里 `HitFX` 先回收一次、`DelayedRelese` 又 `Release()`
  一次 ⇒ `ObjectPool<T>.Release` 无条件 push，同一实例在空闲栈里存两份，之后一次 Get 当"两颗子弹"发出去
  （OnHit 订阅翻倍 / 伤害翻倍）。修法：`m_Released` 标记，`Shoot()` 复位。
- 验证：`offline_compile.py 06_Gameplay` 0 error；未在 Unity 里实测（用户待验）。
- 相关：`ProjectileDelayBomb` 也是同样"HitFX 先回收 + DelayedRelese 再 Release"的写法，靠幂等 Release 兜住。
