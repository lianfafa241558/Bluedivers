## 描边恒黑诊断（OutlineRendererFeature，2026-11-22）
- 现象：运行时怎么改 `_OutlineColor` 描边都是纯黑。根因链：
  1) 工程材质几乎全 `_FixOutlineColor: 0` ⇒ `ConvertSurfaceColorToOutlineColor()`（ToonLit_Shared.hlsl:667）
     返回 `表面受光色 * _OutlineColor` ⇒ 表面色为 0 时改乘数完全无效；
  2) 表面色为 0 因为主光 `distanceAttenuation = unity_LightData.z`（URP RealtimeLights.hlsl:108），
     而 `unity_LightData` 在 `CBUFFER_START(UnityPerDraw)`（URP UnityInput.hlsl:104/117）= per-object，不是全局；
  3) feature 里 `cmd.SetGlobalVector("unity_LightData",(0,0,1,0))`（OutlineRendererFeature.cs:409）
     本来就算在 `DrawRenderers`（:175）**之后**才 `ExecuteCommandBuffer`（:182），只靠全局残留到下一帧侥幸生效；
  4) 11/16 把 ToonLit 家族 Stencil 改常量 `Ref 0` 后，实测 6 个变体 `ShaderUtil.GetSRPBatcherCompatibilityCode=0`
     （SRP Batcher 兼容）⇒ UnityPerDraw 改为按物体绑定，残留全局彻底不再被读 ⇒ 主光衰减 0，
     只剩 `_IndirectLightMinColor`(0.1) × occlusion × `_OutlineColor` ≈ 0 ⇒ 恒黑。
- 临时救急：材质勾 `_FixOutlineColor=1`（描边取固定色，与光照解耦）。
- 正解：Outline pass 里 `GetMainLight()` 后强制 `distanceAttentenuation = 1`（`#ifdef ToonShaderIsOutline`）。
- 顺带：`SnowRendererFeature.cs:590/593` 同款「主光常量写在 DrawRenderers 之后」bug；
  运行时改描边色只能改材质/材质实例/MPB，`Shader.SetGlobalColor` 对 UnityPerMaterial cbuffer 无效。

### 上条修正：不是"恒黑"，是"运行时（夜）黑"
- 用户补充：**非运行（编辑模式）调 `_OutlineColor`=红确实会变成"光照*红"**，一进 Play 就黑。实测当时运行时状态：
  `ambientMode=Trilight`、`ambientSky=(0.096,0.121,0.215)`、主光=`Moon`（int 1，色 0.278/0.306/0.400）、`Sun` int≈0.39、`_IndirectLightMinColor=0.1`、材质 `_FixOutlineColor=0`。
- 结论：描边 = **受光色 × `_OutlineColor`**（ToonLit_Shared.hlsl:680），昼夜系统（EnvironmentLightingModule 每帧改 RenderSettings.ambient*、
  CelestialVisualsModule 改日月光强）把运行时受光色压到 0.0x（Outline 分支走 `unity_AmbientSky` + min 0.1，不走 `SampleSH`，
  所以物体本体亮、描边黑），乘任何颜色都 ≈ 黑；编辑模式用的是场景里 authored 的白天光照 ⇒ 看得见。
- 叠加因素（上一轮查的）：ToonLit 现在是 SRP Batcher 兼容（实测 `GetSRPBatcherCompatibilityCode=0`），
  `unity_LightData`（UnityPerDraw，per-object）的全局写入=死代码，Outline pass 的主光项恒为 0，只剩 0.1 环境光。
- 修法取向：描边不该吃昼夜光照 ⇒ `_FixOutlineColor=1`（纯 `_OutlineColor`），或 Outline 分支用 albedo 当色调而非受光色。

### 真正根因（已修，2026-11-22）：Outline pass 没声明 _FORWARD_PLUS
- 工程 URP Renderer `m_RenderingMode: 2` = **Forward+**（`Assets/Setting/New Universal Render Pipeline Asset_Renderer.asset`）。
- 但 ToonLit 家族的 **Outline pass 的 pragma 里没有 `_FORWARD_PLUS`**（只有 ForwardLit 有）⇒ 该 pass 编译时 `USE_FORWARD_PLUS` 未定义，
  `GetMainLight()` 走 `light.distanceAttenuation = unity_LightData.z` 这条老分支；Forward+ 下 `GetPerObjectLightFlags()`
  只在 `!isForwardPlus` 时附 `PerObjectData.LightData`（UniversalRenderPipeline.cs:1604-1606），这个值根本不会被填，
  再叠加我们自己的 `DrawRenderers` 也没设 perObjectData（默认 None）⇒ 主光项恒 0。
- 结果：描边受光色只剩间接光 `unity_AmbientSky`（被昼夜系统写成 ~0.096）+ `_IndirectLightMinColor`(0.1) 兜底 ≈ 0.1，
  乘 `_OutlineColor` 后恒黑 ⇒ "白天也黑、改颜色没用"（本体亮是因为它走 Forward+ 分支：distanceAttenuation=1 + 全局 `_MainLightColor` + SampleSH）。
- 已改 3 处：
  1. `Assets/Shader/ToonLit/Main/ToonLit_Shared.hlsl`（`ShadeAllLights` 里 `GetMainLight()` 后）：`#ifdef ToonShaderIsOutline` → `mainLight.distanceAttenuation = 1.0;`
  2. `OutlineRendererFeature.Execute`：`drawingSettings.perObjectData = renderingData.perObjectData;`
  3. 同文件：`context.ExecuteCommandBuffer(cmd)` 移到 `DrawRenderers` **之前**（原来 SetRenderTarget/全局 uniform 当帧全不生效）。
- 未改：`SnowRendererFeature.cs` 同样的顺序 bug（雪现在靠残留全局侥幸生效），要改问用户。
- 若要描边间接光与本体完全一致，可把 outline 分支的 `unity_AmbientSky` 换成 `SampleSH(0)`（现在 perObjectData 已给，能拿到探针）。

### 描边宽度与距离（查证，未改）
- 公式：`ToonLit_Shared.hlsl:231-238` `width = _OutlineWidth * clamp(dist/10, 1, 3)`，再乘
  `GetOutlineCameraFovAndDistanceFixMultiplier()`（`NiloOutlineUtil.hlsl:22-51`）。透视下该 multiplier =
  `saturate(|z_view|) * FOV * 0.00005`，而 `saturate(|z|)` 在 1m 外恒为 1 ⇒ **"屏幕等宽"的补偿实际失效**。
- 实际效果：d<10m 世界宽度恒定（屏幕近粗远细，∝1/d）；10~30m 宽度∝d（屏幕宽度基本恒定）；>30m 固定 3 倍（又变细）。
- `_OutlineWidth`：shader 默认 4、单位材质多为 2（Range 0~20）。Feature 的 `maxDistance/minScreenPixels` 只决定
  整条描边画不画（当前都是 0=关），不改变宽度。本轮修黑描边没碰宽度。

### 回归修正：描边"穿透物体"（2026-11-22，是我上一步引入的）
- 诱因：把 `context.ExecuteCommandBuffer(cmd)` 从 `DrawRenderers` 之后挪到之前时，cmd 里的
  `cmd.SetRenderTarget(_renderer.cameraColorTargetHandle)` 也跟着生效了 —— 只绑 color 会把已绑好的**深度**摘掉，
  Outline pass 的 ZTest 失效 ⇒ 膨胀壳（Cull Front）盖在所有物体上 = "描边穿透"。
  （挪之前它排在 draw 之后，只影响后续 pass，URP 每个 pass 自己重绑，所以没暴露。）
- 修法：删掉该 `SetRenderTarget`，AfterRenderingOpaques 时相机颜色+深度本来就绑好，直接继承；
  cmd 只保留主光/额外光全局 uniform，仍在 DrawRenderers 之前执行。
- 经验：**自定义 RenderPass 里别只绑 color target**；要绑就连 depth（`cameraDepthTargetHandle`）或干脆继承。

### ToonLit_MouthEye 发暗 = Properties 里没声明 `_ShadowMapColor`（2026-11-22，已修）
- 实测（Unity MCP，改前）：MouthEye 材质 `HasProperty("_ShadowMapColor")=false`、`GetColor` 返回 (0,0,0,0)，
  尽管 .mat 的 m_Colors 里明明存着 0.8 ⇒ **Properties 块没声明的属性，材质里的值不会被上传，cbuffer 拿到 0**。
- 后果：`ToonLit_LightingEquation.hlsl:71` `litOrShadowColor = lerp(_ShadowMapColor, 1, litOrShadowArea)`，
  `_ShadowMapColor=0` ⇒ 被判成暗面的像素完全不受该光源照射，只剩 ~0.1 环境光 ⇒ 眼嘴比脸暗一大截。
- 已改：`Assets/Shader/ToonLit/Main/ToonLit_MouthEye.shader` Properties 补
  `_ShadowMapColor("阴影颜色", Color) = (0.85,0.85,0.85)` 和 `_IndirectLightMinColor("环境光下限", Color) = (0.1,0.1,0.1)`；
  refresh 后实测 HasProperty=true、值读到 0.8 / 0.1（材质里的旧值立刻生效，不用重设）。
- 同一批"材质有值但 shader 没声明 → 实为 0"的还有（Face 与 MouthEye 都缺，材质里分别存 0.05 / 0.65 / 1）：
  `_CelShadeSoftness`（=0 ⇒ smoothstep 上下界相同，明暗交界硬切）、`_ReceiveShadowMappingAmount`（=0 ⇒ 完全不接收实时阴影）、
  `_FogMaxValue`（=0 ⇒ ApplyFog 的乘子为 0，等于不吃雾）。要补需逐个确认副作用。
