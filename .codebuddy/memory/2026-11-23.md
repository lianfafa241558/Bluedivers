## 附加因素派发改成「轮转发牌」（用户口径变更）
- 起因：用户给 MD_Federal 配了 **12 条**附加因素、只剩 4 个任务点，却问「为什么一个区域没放满 3 个」。
  MCP 实测（`execute_code` 读 Unity 内存）：`count=12 distinct=3 [Cyborg,IncinerationCorps,JetBrigade]`、
  `points=4`、`GetDirtyCount=23` ⇒ **枚举只有 3 个值，12 条是 4+4+4 的重复**；旧算法 `used.Contains(type)` 全局去重 ⇒ 全图只派 3 个，
  且每个枚举独立随机掷点（不做均衡）⇒ 一个点拿到全部 3 个的概率仅 ~6.25%。
- ⚠ 该资产当时**没落盘**（YAML 里根本没有 `additionalFactors` 字段，另三张图 Abydos=1/Gehanna=2 重复/RedWinter=1 已落盘）。
  编辑器 Play 用的是内存脏值，所以看得到效果。
- 新算法（`TaskManager.AssignFactors`，`MaxFactorsPerPoint = 3`）：
  - **按条目**逐个派（不再按枚举全局去重）；游标 a→b→c→d→a… 轮转 ⇒ 每点数量最多差 1（12 条 ÷ 4 点 = 每点 3 条）；
  - 跳过"已满 3 个"或"该点已有同枚举"的点；同点不重复阵营，上限 = `MapTaskButton.prefab` 的 `Layout` 槽位（槽 0 是任务图标，槽 1~3 是因素）；
  - 仍有空位但枚举撞车 ⇒ 跳过该条继续；所有点都满 ⇒ 打一条 warning 并停止（后面的更放不下）；
  - 发牌起点 `TaskRandom.Range(0, points.Count)` 只掷一次（换窗口时起点会变，两端同流复现）。
- 同步改了注释/工具提示：`CoreEnums.AdditionalFactorType`、`MapData_SO.additionalFactors`、`SelectMapWnd` 那段注释。
- 验证：`offline_compile.py 00_Core 04_Data 09_Managers 10_UI` 0 error。

## 两个 bug 诊断（用户报：敌人朝向≠移动方向 / 锁定标记消失）
- **① 敌人面朝与移动方向不一致**：`EnemyController.InitAttribute()` 第 173 行把 `Speed.OnFinalValueChange` 订阅成写 `NavMeshAgent.angularSpeed`
  （`if (AngularSpeed.PrimeValue > 0) Speed.OnFinalValueChange += v => NavMeshAgent.angularSpeed = v.RawFloat;`）。
  Runtime 实测：`AngularSpeed` 属性 prime/final=**120**，而 `agent.angularSpeed=**5**`（== `agent.speed`）。
  触发点 = `Start` 的 `Speed.AddModifier(Factor,-1)` 与 `BirthEnd` 的 `+1` ⇒ 角速度被写成 5°/s，转身 180° 要 36 秒。
  ⇒ 修：改订阅 `AngularSpeed.OnFinalValueChange`。附带：`UpdatePathDestination()` 手动 `transform.rotation` 与 `updateRotation=true` 打架（仅 Patrol）。
- **② 锁定图标/连线消失（锁定效果仍在）**：`SightLockToTarget.Start` 用 `transform.TryGetComponentInParent(out manager)` 取管理器，
  但准星实例在 `CrosshairManager.SetAnimGo` 里 Instantiate 到 `Crosshair` 后，**同一帧** `RefreshCrosshairVisibility` 会把它 `SetParent` 到
  `ExchangeArea`（active、位于 y=-1000 的隐藏区）⇒ Start 在 ExchangeArea 下执行 ⇒ 父链没有管理器 ⇒ `manager` CLR null、`OnLockUpdate` 0 订阅者。
  Runtime 实测确认：HUD 上那个 Lock 的 `manager=CLR-null`、`OnLockUpdate=NO-SUBSCRIBER`、`dic` 已初始化。
  ⇒ 修：由管理器显式绑定（`SetAnimGo` 后对新准星 `GetComponentsInChildren<SightLockToTarget>(true)` 逐个 `Bind(this)`）。
  次生缺陷：`m_Weapons` 只在 Start 赋值（换枪后连线起点仍用旧枪 muzzle）；`--group.Item2` 改的是元组副本、从不写回字典（层数只增不减）。

## 已落地修复（同日）
- `EnemyController.InitAttribute()`：订阅改回 `AngularSpeed.OnFinalValueChange`；`SpecUnitController.InitAttribute()` 有**同款复制粘贴 bug**，一并改掉。
- `SightLockToTarget`：新增 `Bind(CrosshairManager)` / `Unbind()`，`Start` 只初始化 `dic/pool`；`Clear()` 顺带刷新 `m_Weapons`；
  移除分支改成写回字典（`dic[actor] = (tr, left)`）；`UpdateLine` 加 `line`/`m_Weapons` 判空。
- `CrosshairManager.SetAnimGo()` 末尾调 `BindLockMarkers()`（`GetComponentsInChildren<SightLockToTarget>(true)` 逐个 Bind）。
- 验证：`offline_compile.py 06_Gameplay 10_UI` 0 error；Unity 重编 0 error；旧 Play 会话里反射调用 `BindLockMarkers()` 后实测
  `manager=Crosshair / m_Weapons=IntelligentRifle(Clone) / OnLockUpdate 订阅=1`（绑定逻辑成立）。
- ⚠ 直接 `manage_editor play` 只会进 **GameRoot 主菜单**（`BattleScene` 要过流程），所以角速度修复需要用户进战斗才能实测。
- **追加修复（用户实测报 NRE）**：`SightLockToTarget.Clear()` 在 `dic==null` 时被调用 —— 因为 `Bind` 发生在 `Instantiate` 之后、
  本组件 `Start` 之前（Start 要等本帧末），而 `SwitchWeapon` 紧接着就 `OnSwitchWeapon?.Invoke() → Clear`。
  ⇒ 加 `EnsureInit()`（`dic`/`pool` 一次建好），`Bind` 开头与 `Start` 都调它；订阅一律在 EnsureInit 之后。
- ⚠ **在暂停的 Play 里改脚本会留下"半旧实例"**：GameObject 还在、`manager` 是旧的、`dic` 是 null，据此判断会误判 ⇒ 必须 stop→play 全新会话再验。
- 另有三个与本改动无关的 NRE：`DrawLabelUtils.cs:69`、`WndManager.cs:25`、`PlayerSpeechManager.cs:43`（后两个是退出 Play 的拆卸期）。
