**热键（自由相机态，裸 KeyCode，不动 InputManager.prefab）**
Tab 指针/取景、1-9 跳机位、Ctrl+1-9 存机位、`[`/`]` 倍率、J 暂停、`,` 单逻辑帧、Enter 生成、T 释放战备、Backspace 清落点、H 显隐面板。

**踩坑**
1. ⚠ `new GameObject(..., typeof(RectTransform))` 的 **sizeDelta 默认 (100,100)**；在 `HorizontalLayoutGroup` 里没有 `LayoutElement` 时会被当成行高，整行被撑到 100+。且 `HLG.childForceExpandHeight=true` + 父级 preferred 会**正反馈放大**（实测 158px）。正解：按钮加 `LayoutElement`（min/pref 28、flexible 0）+ 行内 `HLG.childControlHeight=false`。
2. `LayoutRebuilder` 是异步的：`SetWndState` 当帧读子项尺寸会拿到**未排布**的默认值（y=0）。核对布局要 `LayoutRebuilder.ForceRebuildLayoutImmediate(root)`。
3. `CycleRate(-1)` 语义：档位数组是从快到慢，`_rateIndex - direction` 才对。
4. 10_Effect 看不见 `07_NetGame` ⇒ 成员判定直接复用 `BattleManager.Instance.IsNetMember`（09 已为此暴露）。
5. 单帧步进 = 设 `timeScale = 0.02 / unscaledDeltaTime` 一帧，让 `LogicFrameHost`（scaled delta 累加 50Hz）恰好推进 1 tick，不是渲染帧。
6. 离线编译新文件必须 `--add:<asm>:`，否则 csproj 里没它 → 会误报「`_panel` 不存在」这类假错误。

**验证**：离线编译 4 个程序集 0 error；Unity 重编 Console 0 error；反射确认 `DirectorMode`/`DirectorPanel` 进 dll；Play 实测机位保存、暂停/倍率/单帧、指针锁定、落点标记（2 个子节点）、无落点拒绝生成均通过。前端阶段无主相机，Play 验证靠临时造 `TempMainCam`。

**边界**：生成与战备仅单机/房主；不持久化；不做运镜曲线与录制。

## PV 导演 · 追加两项（同日）

### 1. H 隐藏时连落点标记一起藏
`DirectorMarker` 把「有没有落点」和「现在显不显示」拆开：`HasPoint`（数据）+ `_visualVisible`（显隐），`Show/Hide` 管数据、`SetVisualVisible` 只管显示。`DirectorMode.HasMarker` 改判 `HasPoint`（原来看 `activeSelf`，一藏就误判"没落点"）；`DirectorMode._markerVisible` 记住 H 的状态，新选的落点不会因为被藏而丢，也不会突然冒出来。`FreeCameraWnd` 的 H 分支调 `_director.SetMarkerVisible(state)`。

### 2. 固定机位（Shot）把角色交还玩家
链路：`DirectorMode.EnterShotFrozen()` → `UIState.PlayerControl = true`；`EnterFly/TogglePointer/Exit` → `false`。
- `04Data/UIState.cs` 加 `PlayerControl { get; internal set; }`，`InternalsVisibleTo` **补 `10_Effect`**（写在 09_Managers 之后，同一 assembly 级特性可多条）。
- `06Gameplay/Player/PlayerInputHandler.CanProcessInput()` 开头：`if (UIState.WindowState == FreeCamera && !UIState.PlayerControl) return false;`（放在 `debugging` 之前，调试开关不该放出这个）。`GetMouseAxis` 原来单判 WindowState 的那行删掉，统一由 `CanProcessInput()` 兜。
- ⚠ 光放行不够：`GetMoveInput` 读 `Horizontal/Vertical`，这两个键只在 Game 段绑 → 自由相机段读不到。给 `InputManager.prefab` 的 `window: 4` 补了 `key:1`(A/D) / `key:2`(W/S) 两条（与 Game 段同键位）。Fly/Pointer 态由 `PlayerControl=false` 挡住，不会让角色乱走。
- 数字键切武器仍用 `CanProcessInput(GameState, WindowState.Game)`，Shot 态不可用 ⇒ 正好留给导演的 1-9 机位。
- 跳跃/蹲/趴用 `CanProcessInput(WindowStateEnum.Game)`，Shot 态也仍不可用（未扩）。

### ⚠⚠ 新坑：prefab 的 YAML 里**不能写 `#` 注释**
在 `InputManager.prefab` 的 `inputList` 序列中间插了两行 `#` 注释，Unity 导入后**把注释之后的整段列表项全丢了**（文件 45 条 → Unity 只读到 32 条，`window:4` 6/8），`AssetDatabase.ImportAsset(ForceUpdate)` 也救不回来，但它**不报错**（静默）。删掉注释后立刻 45/8 全部正常。
⇒ 原则：**prefab / .asset 的 YAML 一律不写注释**，说明写进 C# 侧注释或 memory。这条和"`replace_in_file` 可能把 LF 写成 CRLF"一样属于"Git 看不出、Unity 也不报"的静默坑。

**验证**：运行时 `inputList` FreeCamera 段 = 8 且含 Horizontal/Vertical；`PlayerInputHandler.CanProcessInput()` 在 Fly/Pointer=False、Shot=True；标记 set/hide/show 三步都对且 hide 后 `HasMarker` 仍为 true。Console 无真实错误（两条是普通 `Debug.Log` 被 plain 格式混进 error 列表）。

### 3. 固定机位"出不去" + 列表拖拽放置（同日追加）
- **出不去的原因**：`Tab` 只在 Shot⇄Pointer 循环，代码里**没有任何路径回 Fly**（初版计划的 `F` 键漏实现了）。补：`F` 随时 → `EnterFly()`（与 Unity Scene 视图的 F 同义，全仓无其他 `KeyCode.F` 占用）；状态栏改成「固定机位（F 回飞行）」「选点（Tab 回飞行）」。
- **拖拽放置**：新增 `10UI/Director/DirectorDragItem.cs`（`IBeginDrag/IDrag/IEndDrag`），面板每行挂一个，`DirectorPanel` 暴露 `RowDragBegan/Dragging/DragEnded` 三条委托；窗口接到 `DirectorMode.BeginPlacement/SetMarker/SpawnUnit|ReleaseAirdrop`，拖拽中实时更新落点圆环，松手才生成，松手还在 UI 上 = 取消。
- ⚠ 坑：行的 `IBeginDragHandler` 会**吃掉**拖拽事件，父级 `ScrollRect` 再也收不到 ⇒ 必须在 `OnBeginDrag` 里 `scroll.enabled=false`、`OnEndDrag` 恢复；滚轮滚动不走拖拽链路，禁用期间仍可用。
- ⚠ 拖拽只能在 **Pointer 态**（鼠标已解锁）进行；Fly/Shot 态鼠标锁定，连面板都点不到，这是 `Tab` 的存在意义（图例已写明）。

**验证**：Shot→F→Fly 后 `InputEnabled=true / PlayerControl=false / 倍率保持 0.2`；模拟拖拽 51 行中的战备行：BeginDrag→`IsPlacing=true`、Drag→落点命中 `(0,0,3.5)`、EndDrag→`IsPlacing=false` 且 `ScrollRect.enabled` 已恢复，日志出现 `[导演] 释放战备 呼叫增援(9)`。

### 4. Shift 存档位 + 相机不再死锁（同日追加）
- 存机位按键三轮变迁：`Ctrl+数字` → `Shift+数字`（**与自由视角的「下降」= LeftShift 冲突**）→ 最终 **`Alt+数字`**。Alt 同时是"按住微调"键，用 `_altUsedForShot` 标记「本次按住已用于存档位 ⇒ 不再接管相机」，避免 Alt+1 顺手把玩家输入收走。
- 机位过渡：`ShotBlendTime = 0.35f`（`DirectorMode` 顶部 const，秒），`BlendTo` 用 `unscaledDeltaTime / ShotBlendTime` 推进 + `Mathf.SmoothStep` 缓动 ⇒ 暂停/0 倍速下也按真实时间过渡。要调速改这一行。
- `FreeCameraController` 拆出 `AllowLook`（是否响应鼠标转视角），与 `InputEnabled` 分离。⚠ 选点态**最终选了"相机完全锁死"**（`InputEnabled=false`）：先试过"能 WASD 挪、不转视角"，实测按方向键会让镜头漂移、落点判断跟着错 ⇒ 需要调整取景就按住中键/Alt 临时接管。
- `DirectorMode` 新增 `ApplyStateControl()` **统一收口**三种状态的相机/玩家/光标组合，`EnterFly`/`EnterShotFrozen`/`TogglePointer`/`Exit`/`SetCameraOverride(false)` 全部走它（之前各处手写，漏一条路径就会出现"回不去"这类问题）：

| 状态 | InputEnabled | AllowLook | PlayerControl | 鼠标 |
|---|---|---|---|---|
| Fly | true | true | false | Locked |
| Shot | **false** | true | **true** | Locked |
| Pointer | **false** | false | false | None |

- `SetCameraOverride(bool)`：按住**鼠标中键或 Alt** 临时接管 —— Shot 态用于微调机位（`InputEnabled=true` + 收回玩家，否则 WASD 同时驱动相机和角色），Pointer 态用于转视角（顺带锁鼠标，松开解锁）。松开 = `ApplyStateControl()` 回常态，相机停在新位姿、不回原机位。

**验证**：`Fly / Shot / Pointer / Pointer+中键 / Pointer 松开 / F 回 Fly` 各组合的 `camInput/allowLook/player/lock` 全部符合上表；选点态摆个位姿后按中键再松开，相机位姿与 FOV 均未被改动。

### 5. 机位过渡受移动速度影响 + 面板滑动条（同日追加）
- `FreeCameraController` 暴露只读 `Speed`（私有 `speed` 字段 1..35，`=`/`-` 调）。
- `DirectorMode`：`ShotBlendTime` 常量拆成 `_blendBase`（面板可调，0.05~1.5s，默认 0.35）+
  `BlendDuration = clamp(_blendBase × ReferenceSpeed(4) / 当前Speed, 0.05, 2)`。
  ⇒ 相机飞得快时跳机位更干脆（speed=20 → 0.07s；speed=1 → 1.4s）。`BlendTo` 在过渡开始时取一次 `duration`，避免中途改速度让进度跳变。
- `DirectorPanel`：`ShotLabel` 行改成 `机位 | 滑动条 | 0.12s`（`HorizontalLayoutGroup` + 手搓 uGUI `Slider`：Background + HandleSlideArea/Handle，不画 Fill；左端最慢 1.5s、右端最快 0.05s），右侧文本显示**实际** `BlendDuration`（已含速度缩放），5Hz 随 `Refresh` 刷新。委托 `BlendChanged` 接到 `SetBlendBase`。
- ⚠⚠ **uGUI `Slider` 被点中后会 Select，并吃掉 `Horizontal` 轴** —— 项目里 A/D 就是 `Horizontal` ⇒ 拖完滑条再按 A/D 走动会顺手改过渡时长（实测确认）。修法双保险：`slider.navigation = new Navigation { mode = Navigation.Mode.None }` + 挂 `EventTrigger.PointerUp` 里 `EventSystem.SetSelectedGameObject(null)`。任何自绘滑动条都该这么做。

### 6. 落点圆环定位为"拖动预览"（同日追加）
改成拖拽入场后，圆环不再当"预置目标点"，只做**拖动中**的落点预览：`RowDragEnded` 里无论成功/取消/没打中地面，最后统一 `ClearMarker()`，画面不留残影。`Tab` 点选设的落点不走这条路径，仍显示到 `Backspace`/生成。保留圆环的理由（三条）：斜视角下光标位置≠落点、生成时 `GetNavMeshPoint` 会二次吸附、战备有影响范围需要可视化。
