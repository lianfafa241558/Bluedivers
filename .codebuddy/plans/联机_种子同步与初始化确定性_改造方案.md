### Ⅰ-2 接口（方案，非实现）

```csharp
namespace FPSGame.Utils
{
    /// <summary>派生随机流的用途标识。⚠ 值一旦发布不可修改（会改变所有人的随机结果）。</summary>
    public enum SeedStream
    {
        RandomUtils = 0,   // 保留：静态流本体（不改）
        Battle              = 1,
        Terrain             = 2,
        TerrainDecor        = 3,
        Puzzle              = 4,   // 实际用 PuzzleBase + puzzleId
    }

    public static class SeedUtil
    {
        /// <summary>从权威种子派生一条独立流的种子。同 seed + 同 purpose ⇒ 恒等。</summary>
        public static int Derive(int seed, int purpose) => unchecked(seed * 31 + purpose);
        public static int Derive(int seed, SeedStream stream) => Derive(seed, (int)stream);
    }
}
```

**要点**
1. **`Derive` 必须是纯函数**：不读时间、不读静态可变状态 ⇒ 任何端、任何时刻同参同值。
2. **各用途互不干扰**：地形流被"音效/弹孔/谜题"偷游标的问题**从根上消失**（这是派生流相对"共用 `RandomUtils`"的最大收益）。
3. ⚠ **不要**为了让 `BattleRandom` 与 `RandomUtils` "同源"而把它们变成同一个实例——**两个 `System.Random` 实例各自持有游标**才是安全的；`Derive` 只用来**区分用途**，不要用来"串联"。

```csharp
// ① 字段
[InspectorName("单机调试：用短窗口刷新任务表")]
[SerializeField] private bool useShortWindowForTest = false;

private const long BucketNormal = 1800;   // 30 分钟
private const long BucketShort  = 120;    //  2 分钟（仅调试）

private long _lastBucket = long.MinValue;
private bool _pendingRefresh;

private long CurrentBucket()
    => System.DateTimeOffset.UtcNow.ToUnixTimeSeconds() / (useShortWindowForTest ? BucketShort : BucketNormal);

// ② 生成：把桶作为参数传进来（不再自己取时间）
private void CreatAllTask(long bucket)
{
    TaskRandom = new System.Random(unchecked((int)bucket));   // ⚠ 只吃 int32
    // …其余不变（residualCodeA/B、双重循环、TaskCfgs[i,u] = new TaskCfg{…}）
}

// ③ Init：先定桶再生成，避免首帧多刷
//    ResetTask();
//    _lastBucket = CurrentBucket();
//    CreatAllTask(_lastBucket);

// ④ Update：桶变化检测 + 仅舰桥执行
void Update()
{
    long b = CurrentBucket();
    if (b != _lastBucket) { _lastBucket = b; _pendingRefresh = true; }

    if (_pendingRefresh && GameRoot.GameState == FPSGame.Core.GameStateEnum.Bridge)
    {
        _pendingRefresh = false;
        CreatAllTask(b);
    }
}
```

### Ⅱ-3 为什么这样改（三条结论来自前几轮查证）

1. **改回 30 分钟是"自愈"成立的前提**：`hasTriggeredThisMinute` 复位机制保证每个 :00/:30 必刷一次，而 30 分钟窗口让"启动时算的桶"与"刷新时算的桶"**必然相等** ⇒ 两端只要都在运行就会收敛。（2 分钟版则不相等，会一直错到下一个半点。）
2. **UTC 桶**：消除时区依赖；且桶 id 是连续整数，天然无碰撞。
3. **桶变化检测**：一口气解决"休眠漏拍"+"战斗中不换表"（你要的）+"回舰桥补刷"。

### Ⅱ-4 🔎 已澄清的风险：**战斗中重建 `TaskCfgs` 对本局无害**

我上一轮把它列为"待确认"，现已确认：

```csharp

{

⇒ "仅舰桥刷新"是**体验优化**（大厅列表不跳变），不是正确性必需。**保留残余检查项**：确认没有别处**直接**读 `TaskManager.TaskCfgs[..]`（而不是读 `nowTask`）。

    float timeout = Time.realtimeSinceStartup + 10f;
    while (!asyncOp.isDone && Time.realtimeSinceStartup < timeout) yield return null;   // ⚠ 超时后继续
    if (!asyncOp.isDone) Debug.LogWarning("NavMesh 异步构建超时，可能仍在后台进行");
}
```

**问题**：超时后**照样往下走** ⇒ `IsStartBattle = true` 时 NavMesh 可能还没烘完 ⇒ 两端在不同时刻完成 ⇒ `NavMesh.SamplePosition`（`WaveManager.cs:240/246`、`PatrolContriller.cs:512-516`）结果不同。

**改法（方案）**
```csharp
// 1) 超时只告警、不放弃：一直等到 isDone（并周期性报进度）
while (!asyncOp.isDone)
{
    if (Time.realtimeSinceStartup - lastWarn > 5f) { Debug.LogWarning("…仍在烘焙…"); lastWarn = …; }
    yield return null;
}
// 2) 增加显式标志（供窗口结束判定）
public bool NavMeshReady { get; private set; }     // 成功构建完成为 true；失败保持 false + LogError
```
- 由于 `InitTerrain()` 是在 `BattleManager.cs:168` 被 `yield return` 的，**它整体完成后**才会走到 `:205 GameState = Game` / `:208 DrainInitQueue()` / `:209 IsStartBattle` ⇒ **只要不再"超时即继续"，"完成"就自动成为窗口结束的前置条件** ✓
- 建议再加一条断言：`if (!surface.navMeshData) Debug.LogError(...)`（现在只是 `LogWarning`，容易被忽略）

**⑴ `NetTmp/Services/Msg/RoomMsg.cs`** —— `StartGameNtf` **末尾追加**字段（MessagePack 约定：追加在末尾、取下一个 Key）

**⑵ `09Manager/Global/TeamNetBridge.cs`（房主侧计算 + 成员侧比对）**
```csharp
// 指纹：只取"决定玩法"的字段，且**只用整数混合**（不用 string.GetHashCode —— .NET 随机化）
static int Fingerprint(TaskCfg c)
{
    int h = 17;
    h = Mix(h, (int)c.main);   
    h = Mix(h, c.enable ? 1 : 0);
    h = Mix(h, c.seed);
    h = Mix(h, (int)(c.scale * 1000f));
    foreach (var e in c.extra)      h = Mix(h, (int)e);
    foreach (var n in c.nestCount)  h = Mix(h, n);
    return h;
}
static int Mix(int h, int v) => unchecked((h ^ v) * 16777619);   // FNV-1a 风格
```
