## 1. 先定口径（4 条，施工前必须确认）

1. **权威归属**
   - **位姿** = 驾驶者所在那台（与玩家位姿同口径：各端本地模拟 + 上报；不做 lockstep）。
   - **身份号** = 房主分配（随空投 4028 下发）。
   - **血量/生死** = 走既有统一伤害通道 `DamageMsg`（4025 上报 / 4040 房主下发含 `IsDeath`），但**载具血量必须收敛到单一权威**（见 §3 P3）。
   - **上下机** = 驾驶者本机上报（他按的 F），房主转发。
2. **键 = 载具 `Actor.NetId`**（房主分配，两端同一值）。
   - ⚠ 不用"派生键 `FNV1a(呼叫者sid + 战备id + 落点量化)`"的原因：**落点是各端各自打地面射线取的**（`VFXAirdropEffect.TmpAirdrop` 里 `Physics.Raycast(point + up*100, down, ...)`，`:208-211`）⇒ 地形被炸过后两端会差几厘米到几十厘米（`topics/net-battle.md §7.2f` 已记录同类残留）⇒ 键会分叉。
   - ⚠ 不用"现有 SpecUnit 自增号"的原因见 §0。
3. **车算不算"现有的号空间"**：算 —— `Exosuit` 根就是 `Actor`，本计划把它改成"**号随 4028 带来并在生成后覆盖**"（与 `INetSpawner.ReplaySpawn` 覆盖 NetId 同一手法：`ActorsManager.Replicating = true` 包住 `Instantiate`，生成后显式赋值）。
4. **明确不做**（沿用既有拍板，别再提议）
   - 不做 lockstep / 子弹权威；不做重连与中途入房的全量补发（除已存在的 `_destroyed` 账本这类）；不让成员端本地生成载具实体。

## 3. 分阶段执行

### P0 · 载具身份（NetId 两端一致）—— 前置，其余全依赖它

**目标**：同一辆载具在两端的 `Actor.NetId` 相同，且不消耗自增号段。

1. `07NetGame/Msg/RoomMsg.cs`：`AirdropCallMsg` 追加 `[Key(6)] public int VehicleNetId;`。
2. `07NetGame/CmdId.cs`：4027/4028 的注释补一句"带载具号"（常量值不动）。
3. `07NetGame/NetRoomFlow.cs`：
   - `SendAirdropCall(int airdropId, Vector3 point, float yaw = 0f)` → 追加 `int vehicleNetId = 0`；
   - 房主那条（`:754-759`）**由房主给号**后放进消息；成员那条先发 0，由房主在转发时补号。
4. `07NetGame/NetHostSvc.cs`：`OnAirdropCallNtf`（转发处）补号 —— **号段建议新开 `ActorsManager.VehicleNetIdBase = 0x3000_0000`**（与 `HostSpawnNetIdBase = 0x2000_0000` / `SpecNetIdBase` 并列，理由同 §7.1：不同来源的计数器共用必然互相错位）。
5. `ActorsManager`：新增 `NextVehicleNetId()`；`Actor.cs:273-280` 的 SpecUnit 分支**不动**（载具会走 `Replicating` 覆盖，见下）。
6. `10_Effect/VFX/VFXAirdropEffect.cs`：
   - 新增 `SetVehicleNetId(int)`（与 `SetCallerSid` 并列，字段 `_vehicleNetId = -1`）；
   - 生成 `m_creatObject` 时（`:376`、`:515` 那两处 `Instantiate(data.cfg.creatObect, ...)`）用
     `ActorsManager.Replicating = true; try { Instantiate } finally { Replicating = false; }` 包住（**让 `Actor.Awake` 不发号**），生成后把 `m_creatObject` 子树里 `type == SpecUnit` 的根 `Actor.NetId` 显式赋成 `_vehicleNetId`。
7. `09Manager/Global/NetFriendBridge.cs`：
   - `HandleLocalAirdrop`：本机自己叫的那发，同样带上"本机本地分配的号"（房主 = 自己给号；成员 = 先用本地临时号，**收到 4028 后以 4028 为准覆盖**，做法见下）；

8. `09Manager/Battle/BattleManager.cs`：`ReleaseAirdrop(...)` 重载加 `int vehicleNetId = 0`（默认值避免改调用点）。

**验收**：两端 `NetSyncLog` 打 `载具/号·发|收`（含 netId、呼叫者 sid、战备 id）；同一辆载具两端打印的 `Actor.NetId` 相同；连续放两发不同玩家叫的载具，号互不相同。

### P1 · 上下机（驾驶者状态）

**目标**：A 上机 ⇒ B 端"甲在开那台"；A 下机/死亡/离场 ⇒ B 端恢复。

1. 新 DTO `VehicleMountMsg { [Key(0)] int NetId; [Key(1)] uint Sid; [Key(2)] bool Mounted; }`（`07NetGame/Msg/SyncMsg.cs`）。
2. `NetRoomFlow` 三件套：`OnVehicleMount` 事件 + `SendVehicleMount(...)`（分流规则照 `SendAirdropCall`：房主直达 + 成员上行）+ `HandleVehicleMount`；`Awake/Destroy` 注册/反注册 **4053**（⚠ 同一 CmdId 只能一个注册者）。
3. 新桥 `09Manager/Battle/NetVehicleBridge.cs`（常驻自举，照 `NetPlayerStateBridge` 的 `[RuntimeInitializeOnLoadMethod]`；`references` 含 07 ⇒ 它同时能看游戏层与网络层）：
   - **上报点**：`VehicleController.SetOwener`（唯一收口：进入/退出/`OnDie` 都走它）——
     `Mounted = owner != null`，`Sid = (owner == 本机玩家) ? SelfSid : 该实体对应 sid`；
     ⚠ 只在"驾驶者本机"上报（`IsDriver` 门：`owner == ActorsManager.Player.gameObject`），远端应用时**绝不能**再上报。
   - **应用端**：按 `NetId` 找载具（`ActorsManager.SpecUnits` / `FindActor`），再按 `Sid` 找"本端那个实体"：
     - `Sid == SelfSid` ⇒ 本机自己那份（本机已经在跑真流程）⇒ 只更新本地缓存，不重复 `SetOwener`；
     - 别人的 `Sid` ⇒ 本端那份**盟友实例**（`FriendController`）：
       - 挂到载具挂点（`Furniture_Vehicle.relatedTrans2` 的局部 `(0,0,1)`，与本地 `Operate()` 一致）；
       - 置"被载具接管"门（见 P2）⇒ 该盟友实例**停止应用位姿**、`ActorState` 不参与地面逻辑。
   - **回环门**：应用远端若调用本地 `SetOwener`，会触发 `OnSetOwner` 与 `HandEquip` 等本地事件 ⇒ 必须 `NetApplyGuard.Begin()/End()` 包住，且**与既有桥共享同一个门**（`NetApplyGuard` 是计数式）。
4. `OnPlayerLeft`(4029) / `OnHostLost`：驾驶者离开 ⇒ 对应载具 `SetOwener(null)`（本地安全路径）；房主丢失 ⇒ 清全部驾驶绑定（照 `NetFriendBridge.HandleHostLost`）。
5. ⚠ `VehicleController.SetOwener` 里那些"本机玩家专属开关"（`PlayerController.enabled = false`、`comp.Controller.enabled = false`、`ActorState = Hide`、`WeaponCamera.enabled = false`、`LookAtController.enabled = false`，`:57-98`）—— **只在驾驶者本机执行**；远端走桥另辟的一条"远程应用"路径（不要复用 `SetOwener` 的完整语义）。

**验收**：双端对照 —— A 上机 B 端看到 A 的盟友实例进舱（不再站在地上走动）；A 下机 B 端恢复；A 上机后离场，B 端载具回到无人状态且不卡住 AI/位姿。

### P2 · 位姿 / 移动（推荐：**零新消息**）

**口径**：驾驶者那台对载具位姿权威，而载具位姿**可由驾驶者位姿推导**：
`Furniture_Vehicle.Operate()` 里 `owner.transform.parent = relatedTrans2`（载具根）且 `owner.transform.position = transform.TransformPoint(0,0,1)`（`:31`、`:40`）
⇒ **载具世界位姿 = 驾驶者世界位姿 ⊗ (0,0,1)⁻¹**，而驾驶者位姿已经在 5001/5002 里传了（含 Key(6) Pitch）。

1. `09Manager/Global/NetFriendBridge.cs` `HandlePoses`：若该 `Sid` 处于"驾驶中"（P1 的绑定表）⇒ 把**载具根**摆到 `friendPose * offset⁻¹`，盟友实例作为其子（与本地父子结构一致）。
2. 载具自身在远端**不需要跑运动**：`_owner == null` ⇒ `GetInputMove/TryJump/HandleRotation` 已早退（`VehicleController.cs:130-145`）⇒ 只需把 `transform` 钉在推导位上。
3. ⚠ 上车瞬间：本地有 `Furniture_Vehicle.InOperateUpdate` 的 1 秒 `Slerp/Lerp` 贴合，远端没有 ⇒ 会产生一次瞬移；建议"进入驾驶后的 0.3~0.5s 内把推导位与当前位置插值"（在 P1 的绑定表里记 `mountTime`）。
4. ⚠ 若将来允许**无人载具**自己动（自动驾驶/被推/被队友拖走），推导法不成立 ⇒ 才启用 `5003 VehiclePoseUp/Sync`（届时也把载具当"独立权威实体"接进 `NetTransformFlow` 的批次，别再另起一套）。
5. ⚠ 车上武器的瞄准朝向：若 `VehicleWeaponsManager` 的挂点吃 pitch，而 pitch 不在载具根上（而在驾驶者相机）⇒ 复用 5002 的 `Pitch` 喂远端挂点（别新加字段）。

**验收**：A 开机甲走位/转炮塔 ⇒ B 端机甲位置与朝向跟随（用两端 `execute_code` 打印 `transform` 对照，误差应落在位姿缓冲的插值区间内）。

### P3 · 血量 / 死亡（接既有统一伤害通道）

1. **键**：载具 `Actor.NetId`；**源**：`DamageMsg{NetId, AttackerNetId, CausedNetId, Groups, Part, IsDeath}`（`07NetGame/Msg/RoomMsg.cs`）—— 载具是 `Actor` + `Damageable[]`，`EnemyNetBridge.ResolveDamageable(actor, part)` 可直接复用（部位下标发送端已有 `Actor.IndexOfDamageable`）。
2. **权威必须收敛**（当前各端本地各扣一次 ⇒ 两端血量必然分叉）：
   - 新增数据位 `BattleState.IsVehicleDamageAuthority`（照 `IsTickDamageAuthority` 的做法与置位时机：09 在 `WaveManager.Awake` 按 `flow == null || flow.IsHost || flow.SelfSid == 0u` 置位）；
   - `HealthOther`/`Damageable` 侧加门：非权威端**不扣血/不触发死亡**，只播受击表现，等 4040 落地再应用；
   - ⚠ 玩家/盟友例外口径沿用既有：他们血量本机权威。
3. **伤害上行/下发**：
   - 玩家打载具（含友伤，如果允许）⇒ 4025 上报 ⇒ 房主结算/转发 4040；
   - **敌人 AI 打载具** ⇒ 只有房主那台结算并广播 4040（成员端 AI 的伤害不落地）—— 这一条会与 AI LOD 口径相交，需在 `AiLod` 的"不降"清单里补一句"对载具造成伤害的落点由房主权威"。
4. **死亡**：`DamageMsg.IsDeath` ⇒ 各端 `Actor.Kill()` ⇒ `VehicleController.OnDie → SetOwener(null)`（`:113`）+ `SympatheticDetonation` 殉爆 + `OtherController` 5 秒销毁 —— 各端同一时刻触发即一致。
   ⚠ 回环门：`EnemyNetBridge` 已有 `ApplyingRemoteDamage`；载具这条要复用同一个门（别再开一个）。

**验收**：房主打爆载具 ⇒ 成员端同时殉爆；成员端 AI 把载具打到 0 ⇒ 房主认可（不会"一端已爆一端还在开"）；两端血量曲线一致。

### P4 · 武器开火表现（可选，最后做）

1. 现状：载具武器由驾驶者那台开火（`VehicleWeaponsManager` → `WeaponController.HandleShootInputs`），**命中/伤害已经走既有通道**（本机 `Damageable` + 4025/4040），缺的只是**别人看不到**。
2. 新增 **4054 `VehicleShootNtf/Sync`**（`{ NetId, MuzzleIndex, DirX/Y/Z, HitX/Y/Z, DamageIndex }`，形态照 `PlayerShoot`），落点：`NetVehicleBridge` 上报 + 应用；应用端在载具的 `muzzle` 上 `SpawnVisualBullet(muzzle, dir, endPoint)`（照 `FriendWeaponView.PlayVisual` 的既有做法，含 `SetVisualEndPoint`、`IsVisualBullet` 标记）。
   ⚠ 不要复用 4015/4016 的玩家槽位号（那套是 `PlayerWeaponsManager` 槽位语义，载具武器不是槽位；背包已经借用虚拟槽位 7，别再加一个虚拟值把语义搅浑）。
3. ⚠ 需要"实时瞄准"的车辆弹（制导类）一律**收端本地重算**（沿用 2026-10-13 的口径：`FpsHelper.TryGetAimPoint`），不要新增同步字段。

**验收**：A 开机甲开火 ⇒ B 端有枪口焰 + 弹道 + 命中特效；B 端不因表现弹产生结算（`IsVisualBullet` 门）。

### P5 · 边缘 / 回归

1. `OnPlayerLeft` / `OnHostLost` / `GlobalEventBus.OnSceneChange`：清载具绑定表与号表（照 `NetFriendBridge.HandleHostLost`、`HandleSceneChanged`）。
2. 载具被摧毁时，驾驶者本机 `SetOwener(null)` 已恢复 `PlayerController`；远端要把盟友实例"放回地面"（清被载具接管门 + 让它重新吃位姿）。

## 6. 已知坑（施工时逐条对照）

- **`CmdId` 一个号只能有一个 `Register` 者**；`Awake` 注册、`OnDestroy` 反注册（漏了就报 `未注册消息:N`）。
- **`SendToAll` 不含房主自己** ⇒ 房主广播的状态必须本地再 `MessageCenter.Dispatch(msg)` 自派发一次。
- **07 层看不见游戏层** ⇒ 新 DTO 只能用基础类型（枚举传 int，`GameObject` 一律不传）。
- **应用远端会触发本地事件** ⇒ `NetApplyGuard` 跨桥共享（计数式），别各持一个私有 bool。
- **`Actor.Awake` 的号不可绕过**：`Replicating` 必须在 `Instantiate` **之前**置位、`finally` 复位；生成后显式覆盖 `NetId`（⚠ `NetId` 是 `{get;set;}`，可后赋）。
- **空投落点两端可能不同**（各端各自打地面射线）⇒ 这就是本计划"显式带号"而不是"派生键"的原因。
- **`VehicleController.SetOwener` 里全是本机玩家专属开关**（`PlayerController.enabled` / CC / `ActorState.Hide` / `WeaponCamera` / `LookAtController`）⇒ 远端应用必须走桥的独立路径。
- **AI LOD**：`AiLod` 只降敌人且"交战不降"；载具相关的新增落点若涉及伤害权威，记得在它的"不降"清单里补说明（`topics/net-battle.md §7.2b`）。
- **新增 `.cs` 后离线编译会报假错**（新文件不在 Unity 生成的 `.csproj` 里）⇒ 先让 Unity 编一次，再用 `offline_compile.py`。
- **破坏性协议变更**：4027/4028 追加字段属"追加在末尾"（旧端拿默认值），可兼容；若把 `VehicleNetId` 插到中间就会串字段 —— **只许追加**。
