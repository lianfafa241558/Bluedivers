# 记忆治理（Bluedivers）

> 分层：`memory/MEMORY.md`（热区 + 路由表，≤3500 字符，每轮注入）→ `memory/topics/*.md`（按需读，≤8000/篇）→ `memory/YYYY-MM-DD.md`（过程流水，**不注入**）。
> 整理/拆分/归档的**操作流程**见 skill `memory-hygiene`；本文只放每轮都要遵守的红线。

## 【必须】

1. **写对层**：稳定事实/红线进 `MEMORY.md`（只允许"热区 1/2/3 + 路由表 + 待办"这几个题材）；主题细节进 `memory/topics/<主题>.md`；过程流水进当天 daily。多段式长文档一律进 topic，不在 `MEMORY.md` 里铺。
2. **写完必体检**：`python -X utf8 .codebuddy/plans/memory_gate.py` —— L0 ≤ 3500、每篇 topic ≤ 8000。超了就**整段搬到对应 topic / 拆成多篇**，只留一行指针；**不许靠删知识来达标**。
3. **改 `MEMORY.md` 前先重读**（多窗口会并发写）：同一事实只留一处，发现重复就合并；冲突以内容更全者为准。
4. **一个事实只有一个真相源**：记忆里写过的不在 skill/README 里再抄一遍；skill 只留"判据 + 指针"（skill 命中即整篇注入、且没人天天改 ⇒ 复述实现必然过期）。
5. **注释与记忆同一个口径**：写"为什么 + 陷阱 + 别怎么写"，**1~3 行**；长文档/权衡放 topic。
6. daily 超过 30 天用 `plans/memory_archive_legacy.py --cut <日期> --delete` 归档：先出 `archive/INDEX-legacy-*.md` 索引，正文 `git checkout HEAD -- .codebuddy/memory/<日期>.md` 可回。

## 【禁止】

- **禁止**用记忆替代交付物：该改代码/该写文档的就去做，memory 只是补充笔记。
- **禁止** `open(p, 'w').write(open(p).read())` 这类"先截断后读"的写法碰记忆或源码文件（会清空）。
- **禁止**把 `.md` 存成 UTF-8 with BOM（BOM 口径只管 `.cs`）。
